# LeetCode 左侧右侧求和差值 题解

## 1. 题目概述

- **标题 / 题号**：左侧右侧求和差值（#2574，easy）
- **链接**：https://leetcode.cn/problems/left-and-right-sum-differences/
- **难度**：简单
- **标签**：数组、前缀和

**题意**：给定一个下标从 $0$ 开始的整数数组 `nums`。定义：

- $\text{leftSum}[i]$：下标 $i$ **左侧**所有元素之和，即 $\sum_{k=0}^{i-1}\text{nums}[k]$；约定 $\text{leftSum}[0]=0$。
- $\text{rightSum}[i]$：下标 $i$ **右侧**所有元素之和，即 $\sum_{k=i+1}^{n-1}\text{nums}[k]$；约定 $\text{rightSum}[n-1]=0$。

返回长度为 $n$ 的数组 `answer`，其中 $\text{answer}[i] = |\,\text{leftSum}[i] - \text{rightSum}[i]\,|$。

**示例 1**：

```text
输入：nums = [10,4,8,3]
输出：[15,1,11,22]
解释：
  i=0: leftSum=0,    rightSum=4+8+3=15,  |0-15|   = 15
  i=1: leftSum=10,   rightSum=8+3=11,    |10-11|  = 1
  i=2: leftSum=14,   rightSum=3,         |14-3|   = 11
  i=3: leftSum=22,   rightSum=0,         |22-0|   = 22
```

**示例 2**：

```text
输入：nums = [1]
输出：[0]
解释：唯一元素左侧、右侧均空，leftSum=rightSum=0，|0-0|=0。
```

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $1 \le \text{nums[i]} \le 10^5$

> 💡 关键观察：「左侧和」与「右侧和」并非两个独立量——它们共同瓜分了**总和** $T=\sum\text{nums}$。对任意 $i$，恒有 $\text{leftSum}[i] + \text{nums}[i] + \text{rightSum}[i] = T$。于是只要手握总和 $T$ 与一个滚动的前缀和，右侧和即可由这两者「扣」出来，无需为每个 $i$ 重新累加右侧。

## 2. 解题思路

### 2.1 暴力思路：每个位置双趟求和

最直观的写法：对每个下标 $i$，分别用一个内层循环把 $\text{nums}[0..i-1]$ 累加成 `leftSum`、把 $\text{nums}[i+1..n-1]$ 累加成 `rightSum`，再取绝对差。

```python
ans = []
for i in range(len(nums)):
    left  = sum(nums[:i])          # 累加 i 左侧
    right = sum(nums[i+1:])        # 累加 i 右侧
    ans.append(abs(left - right))
return ans
```

时间 $O(n^2)$（每个 $i$ 都扫两段，合计 $\sum_i i + (n-1-i) = O(n^2)$）、空间 $O(1)$（不计结果）。对 $n \le 1000$ 规模（$\sim 10^6$ 次加法）仍可 AC，但**完全无视了「左侧和、右侧和、总和三者守恒」**这一结构，把本可一遍做完的事做了 $n$ 遍。

### 2.2 核心观察：总和恒等式扣出右侧和

![核心观察：leftSum + nums[i] + rightSum = 总和 T，故 rightSum = T − leftSum − nums[i]](../images/lrsum_concept.svg)

**关键直觉**：对所有元素求和得到 $T=\sum_k \text{nums}[k]$。对任意下标 $i$，把数组切成三段——左侧、自身、右侧——三段之和必为 $T$：

$$
\text{leftSum}[i] \;+\; \text{nums}[i] \;+\; \text{rightSum}[i] \;=\; T.
$$

由此解出右侧和：

$$
\text{rightSum}[i] \;=\; T - \text{leftSum}[i] - \text{nums}[i].
$$

于是**只需一遍从左到右的扫描**，维护一个滚动的 $\text{leftSum}$（初始 $0$，每处理完一个 $i$ 就 $\mathrel{+}=\text{nums}[i]$）即可：

- 处理 $i$ 时，`leftSum` 此时正是 $\sum_{k=0}^{i-1}\text{nums}[k]$；
- 由恒等式算出 $\text{rightSum} = T - \text{leftSum} - \text{nums}[i]$；
- $\text{answer}[i] = |\text{leftSum} - \text{rightSum}|$；
- 然后 `leftSum += nums[i]`，进入下一轮。

> 💡 **为何右侧和能这样「白嫖」？** 右侧和的本质是「总和刨掉左边、再刨掉自己」。只要 $T$ 已知且左边和随扫描滚动更新，右侧和就是两个减法的事——无需再扫一遍右侧。这把 $O(n^2)$ 的「每个 $i$ 各扫一遍」压成了 $O(n)$ 的「总共扫一遍」。

> ⚠️ 注意**更新 `leftSum` 的时机**：必须**先用后加**——处理 $i$ 时 `leftSum` 是 $i$ 左侧之和（不含 `nums[i]`），算完 `answer[i]` 之后再 `leftSum += nums[i]` 把自己并入，为下一个下标备好「左侧和」。若先加后用，会把 `nums[i]` 错算进左侧和，得到 `leftSum[i+1]` 而非 `leftSum[i]`。

### 2.3 算法流程图

![算法流程：求总和 T → 初始化 leftSum=0 → 循环：算 rightSum=T−leftSum−nums[i]，写 answer[i]=|leftSum−rightSum|，leftSum+=nums[i] → 返回](../images/lrsum_flow.svg)

流程分三阶段：

1. **求总和**：一趟遍历算出 $T=\sum\text{nums}$（也可一行 `sum(nums)`）；
2. **滚动扫描**：令 `leftSum = 0`，对 $i$ 从 $0$ 到 $n-1$：
   - $\text{rightSum} = T - \text{leftSum} - \text{nums}[i]$；
   - $\text{answer}[i] = |\text{leftSum} - \text{rightSum}|$；
   - $\text{leftSum} \mathrel{+}= \text{nums}[i]$（**先算后加**）；
3. **返回** `answer`。

> 💡 也可把绝对值式子展开：$\text{answer}[i] = |\,\text{leftSum} - (T - \text{leftSum} - \text{nums}[i])\,| = |\,2\cdot\text{leftSum} + \text{nums}[i] - T\,|$，少算一次减法，但可读性略降，面试以「先算 rightSum 再作差」更贴近题意。

### 2.4 示例演算

![示例演算：nums=[10,4,8,3]，T=25，滚动 leftSum 逐步得到 [15,1,11,22]](../images/lrsum_walkthrough.svg)

以示例 1 `nums=[10,4,8,3]` 为例，$T=10+4+8+3=25$：

| 步 | $i$ | leftSum（处理前） | nums[i] | rightSum $=T-\text{leftSum}-\text{nums}[i]$ | answer[i] $=|\text{left}-\text{right}|$ | 更新后 leftSum |
|----|-----|-------------------|---------|---------------------------------------------|------------------------------------------|----------------|
| 0 | 0 | $0$  | 10 | $25-0-10=15$  | $\|0-15\|=15$  | $0+10=10$ |
| 1 | 1 | $10$ | 4 | $25-10-4=11$  | $\|10-11\|=1$  | $10+4=14$ |
| 2 | 2 | $14$ | 8 | $25-14-8=3$   | $\|14-3\|=11$  | $14+8=22$ |
| 3 | 3 | $22$ | 3 | $25-22-3=0$   | $\|22-0\|=22$  | $22+3=25$ |

输出 `[15,1,11,22]`。注意末步更新后 `leftSum=25=T`，正是「扫完整段，前缀和追平总和」的体现。

示例 2 `nums=[1]`：$T=1$；$i=0$ 时 `leftSum=0`、`rightSum=1-0-1=0`、`answer[0]=|0-0|=0`，输出 `[0]`。

## 3. 参考代码

### C++（一遍扫描，$O(n)$ / $O(1)$ 额外空间）

```cpp
class Solution {
public:
    vector<int> leftRightDifference(vector<int>& nums) {
        int total = 0;
        for (int x : nums) total += x;
        int leftSum = 0;
        vector<int> ans;
        ans.reserve(nums.size());
        for (int x : nums) {
            int rightSum = total - leftSum - x;
            ans.push_back(abs(leftSum - rightSum));
            leftSum += x;
        }
        return ans;
    }
};
```

> 💡 两次 $O(n)$ 遍历：第一次求 $T$，第二次滚动 `leftSum`。`ans.reserve(n)` 预分配避免 `push_back` 反复扩容。「先用后加」体现在 `rightSum` 用 `leftSum`、`ans` 写完之后才 `leftSum += x`。

### Python（一遍扫描，$O(n)$ / $O(1)$ 额外空间）

```python
class Solution:
    def leftRightDifference(self, nums: List[int]) -> List[int]:
        total = sum(nums)
        left_sum = 0
        ans = []
        for x in nums:
            right_sum = total - left_sum - x
            ans.append(abs(left_sum - right_sum))
            left_sum += x
        return ans
```

> 💡 `total = sum(nums)` 用内置求和，C 实现、常数极小。循环体只做两个减法、一个 `abs`、一个加法，纯整数、$O(1)$ 额外空间。若追求更短可写 `abs(2 * left_sum + x - total)`，但保留 `right_sum` 显式更贴题意。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n)$ | 一趟求和 + 一趟滚动扫描，共 $2n$ 次加法与若干减法 |
| **空间复杂度** | $O(1)$ 额外 | 仅 `total` / `leftSum` / `rightSum` 三个变量；结果数组不计入 |
| 对照：暴力版 | $O(n^2)$ 时间 / $O(1)$ 空间 | 每个 $i$ 各扫一遍左右两段 |
| 对照：前缀和+后缀和数组 | $O(n)$ 时间 / $O(n)$ 空间 | 预存 `prefix[]`、`suffix[]` 再逐位作差，见第 5 节 |

> 💡 $O(n)$ 已是最优：至少要把每个 `nums[i]` 读一遍，$\Omega(n)$ 不可破。恒等式把「算右侧和」从一次内层扫描降为 $O(1)$ 减法，是本题从 $O(n^2)$ 降到 $O(n)$ 的关键一步。

## 5. 扩展：前缀和 + 后缀和数组（$O(n)$ 时间 / $O(n)$ 空间）

若不利用恒等式，也可先**预处理两套数组**再逐位作差，思路直白、易于并行：

```cpp
int n = nums.size();
vector<int> L(n + 2, 0), R(n + 2, 0);   // 哨兵位
for (int i = 1; i <= n; ++i) L[i] = L[i - 1] + nums[i - 1];   // L[i] = nums[0..i-1] 之和
for (int i = n; i >= 1; --i) R[i] = R[i + 1] + nums[i - 1];   // R[i] = nums[i-1..n-1] 之于 i 右侧
vector<int> ans(n);
for (int i = 0; i < n; ++i)
    ans[i] = abs(L[i] - R[i + 2]);      // leftSum[i]=L[i], rightSum[i]=R[i+2]
return ans;
```

时间 $O(n)$、空间 $O(n)$（两个辅助数组）。它**不依赖总和**、把「左、右和」显式存下，便于后续多次查询（如要回答每个 $i$ 的 `leftSum`/`rightSum` 而非只取差值），但单次取差场景下空间被恒等式版碾平为 $O(1)$。

> 💡 选型口诀：**只要差值 → 总和恒等式（$O(1)$ 空间）；要反复查 `leftSum`/`rightSum` 各值 → 前缀和+后缀和数组**。前者是后者的空间优化，本质都是「前缀和思想」——一个把右侧和也存成数组、一个用总和把它算出来。

## 6. 面试要点

1. **为什么「右侧和」可以用 $T-\text{leftSum}-\text{nums}[i]$ 算出，而不必重新扫描右侧？**

   > 数组三段——左侧、自身、右侧——之和必为总和 $T$，即 $\text{leftSum}[i]+\text{nums}[i]+\text{rightSum}[i]=T$，是加法结合律的直接结果。已知任意两段即可解出第三段。既然 `leftSum` 随扫描滚动维护、$T$ 预先求好，`rightSum` 自然是两个减法的事，省掉一遍右侧扫描。

2. **`leftSum` 为什么要「先用后加」？搞反了会怎样？**

   > 处理 $i$ 时 `leftSum` 应表示 $i$ 左侧之和（不含 `nums[i]`）。若先 `leftSum += nums[i]` 再算，`leftSum` 就变成了 $\sum_{k=0}^{i}\text{nums}[k]=\text{leftSum}[i+1]$，相当于把 `nums[i]` 错算进左侧和，使 `rightSum` 与 `answer` 全部错位一个元素。正确顺序：算完 `answer[i]` 再并入自身，为下一轮备好左侧和。

3. **末步 `leftSum` 更新到 $T$ 是否多余？能否提前结束循环？**

   > 末步 `leftSum += nums[n-1]` 后 `leftSum = T`，但此后无下一轮，确属冗余写入，可省。但保留它让循环体统一（每轮「算差→并自身」），无需为最后一行特判，可读性更好、且仅多一次加法，面试保留即可。优化可写 `for i in range(n-1):` 末位单独处理，得不偿失。

4. **本题与「除自身以外数组的乘积（238）」是什么关系？**

   > 238 求 $\text{answer}[i]=\prod_{k\ne i}\text{nums}[k]$，是本题把「求和」换成「求积」、「绝对差」换成「左积×右积」的对应物。238 因禁用除法，必须显式建「左前缀积」「右前缀积」两数组再相乘（或两趟滚动）；本题有加法的**可逆性**——减法能「扣」出右侧和——故连第二个数组都省了，只需总和与一个滚动量。对比可见：加法有逆运算支撑恒等式优化、乘法在禁除法下只能存两侧乘积。

5. **如果元素允许为负或为 $0$，恒等式还成立吗？**

   > 成立。恒等式 $\text{leftSum}+\text{nums}[i]+\text{rightSum}=T$ 是纯加法结构，与元素正负无关，负数、零同样适用。变的是 `answer` 的语义（绝对差仍非负），但推导与代码不变——这正是恒等式法的稳健之处。若题改为「不带绝对值的差 $\text{leftSum}-\text{rightSum}$」，则符号需保留，但算式 `leftSum - (T - leftSum - x)` 仍正确。

> 💡 **一句话总结**：抓住 $\text{leftSum}[i]+\text{nums}[i]+\text{rightSum}[i]=T$ 的守恒式，用预先求好的总和 $T$ 与滚动前缀和 `leftSum` 把右侧和「扣」出来，一遍扫描 $O(n)$ 时间、$O(1)$ 额外空间完成绝对差；是「前缀和 + 总和恒等式」把 $O(n^2)$ 压到 $O(n)$ 的招牌模板。
