# LeetCode 字符串的总引力 题解

## 1. 题目概述

- **标题 / 题号**：字符串的总引力（#2262，hard）
- **链接**：https://leetcode.cn/problems/total-appeal-of-a-string/
- **难度**：困难
- **标签**：字符串、哈希表、贡献法（计数）

**题意**：字符串的 **引力** 定义为：字符串中 **不同** 字符的数量。

- 例如，`"abbca"` 的引力为 `3`，因为其中有 `3` 个不同字符 `'a'`、`'b'` 和 `'c'`。

给你一个字符串 `s` ，返回 **其所有子字符串的总引力**。

**子字符串** 定义为：字符串中的一个连续字符序列。

**示例 1**：

```text
输入：s = "abbca"
输出：28
解释："abbca" 的子字符串有：
- 长度为 1 的子字符串："a"、"b"、"b"、"c"、"a" 的引力分别为 1、1、1、1、1，总和为 5 。
- 长度为 2 的子字符串："ab"、"bb"、"bc"、"ca" 的引力分别为 2、1、2、2 ，总和为 7 。
- 长度为 3 的子字符串："abb"、"bbc"、"bca" 的引力分别为 2、2、3 ，总和为 7 。
- 长度为 4 的子字符串："abbc"、"bbca" 的引力分别为 3、3 ，总和为 6 。
- 长度为 5 的子字符串："abbca" 的引力为 3 ，总和为 3 。
引力总和为 5 + 7 + 7 + 6 + 3 = 28 。
```

**示例 2**：

```text
输入：s = "code"
输出：20
解释："code" 的子字符串有：
- 长度为 1 的子字符串："c"、"o"、"d"、"e" 的引力分别为 1、1、1、1 ，总和为 4 。
- 长度为 2 的子字符串："co"、"od"、"de" 的引力分别为 2、2、2 ，总和为 6 。
- 长度为 3 的子字符串："cod"、"ode" 的引力分别为 3、3 ，总和为 6 。
- 长度为 4 的子字符串："code" 的引力为 4 ，总和为 4 。
引力总和为 4 + 6 + 6 + 4 = 20 。
```

**约束**：

- $1 \le \text{s.length} \le 10^5$
- `s` 由小写英文字母组成

> 💡 本题表面要“枚举所有子串再数不同字符”，子串数达 $O(n^2) \approx 5 \times 10^9$（$n=10^5$）。直接枚举必然超时。关键是**换求和顺序**：总引力 $=\sum_{\text{子串}} \text{appeal} = \sum_{c} (\text{含 } c \text{ 的子串数})$，再用“右端扩展”把每个右端 $i$ 的贡献 $O(1)$ 滚动出来，整体降到 $O(n)$。

## 2. 解题思路

### 2.1 暴力思路：枚举所有子串逐个数引力

最直白的做法是照搬题意：枚举所有 $\frac{n(n+1)}{2}$ 个子串 $s[j..i]$，对每个子串用哈希集合数不同字符，累加引力。

```text
for i in 0 .. n-1:
    seen = {}
    for j = i downto 0:        # 以 i 为右端，向左扩展
        seen[s[j]] = true
        ans += len(seen)        # s[j..i] 的引力
```

内层虽然能 $O(1)$ 增量维护 `seen`，但仍有 $\frac{n(n+1)}{2} \approx 5 \times 10^9$ 个子串要逐一累加。当 $n = 10^5$ 时**超时**。

> ⚠️ 浪费在于：我们对每个子串单独问“引力是多少”，而引力 $=$ 子串中不同字符数 $=$ $\sum_c [\text{子串含 } c]$。把“逐子串求和”改成“逐字符求和”，就能避开 $O(n^2)$ 枚举。这是**贡献法**（换求和顺序）登场的信号。

### 2.2 核心观察：右端扩展法，$f(i) = f(i-1) + (i - \text{last}[s[i]])$

![核心：把 s[i] 追加到所有以 i−1 结尾的子串，引力增量 = “未含 s[i] 的子串数 + 1” = i − last[s[i]]](../images/2262_concept.svg)

记 $f(i)$ 为**所有以 $i$ 结尾的子串的引力之和**，则答案 $=\sum_{i=0}^{n-1} f(i)$。下面把 $f(i)$ 递推出来。

**观察一：换求和顺序**。以 $i$ 结尾的子串有 $i+1$ 个（左端 $j \in [0, i]$）。每个子串 $s[j..i]$ 的引力 $= \sum_c [c \text{ 在 } s[j..i] \text{ 中出现}]$。交换求和次序：

$$f(i) = \sum_c \big(\text{以 } i \text{ 结尾且含 } c \text{ 的子串数}\big)$$

**观察二：含 $c$ 的子串数 $= \text{last}_i[c] + 1$**。设 $\text{last}_i[c]$ 为 $c$ 在 $s[0..i]$ 中**最右**位置（$-1$ 表未出现）。子串 $s[j..i]$ 含 $c$ 当且仅当 $j \le \text{last}_i[c]$，共 $\text{last}_i[c] + 1$ 个（$-1$ 时为 $0$）。于是

$$f(i) = \sum_c \big(\text{last}_i[c] + 1\big) \quad (\text{仅 } c \text{ 已出现项})$$

**观察三：相邻 $i$ 只有一个字符的 `last` 变化**。从 $i-1$ 到 $i$，唯有 $c = s[i]$ 的最右位置从 $\text{last}_{i-1}[c]$ 跳到 $i$，其余字符不变。因此

$$f(i) - f(i-1) = \big(i + 1\big) - \big(\text{last}_{i-1}[c] + 1\big) = i - \text{last}_{i-1}[c]$$

（若 $c$ 此前未出现，$\text{last}_{i-1}[c] = -1$，增量 $= i - (-1) = i+1$，与“$c$ 贡献从 $0$ 变 $i+1$”一致。）

**直观理解**：把 $s[i]$ 追加到所有以 $i-1$ 结尾的子串末尾，再补一个单字符新子串 $s[i..i]$。引力增量 $=$ “原本不含 $s[i]$ 的子串数” $+\ 1$。“原本不含 $s[i]$”的子串左端必须 $>$ 上次出现位置 $\text{last}[s[i]]$，即左端落在 $(\text{last},\ i-1]$，共 $(i-1) - \text{last}$ 个；加单字符新子串 $+1$，合计

$$\Delta = (i-1) - \text{last}[s[i]] + 1 = i - \text{last}[s[i]]$$

> 💡 一句话：**每步增量 = 当前下标 − 该字符上次出现下标**。用 `last[26]` 记每个小写字母的最右位置（初值 $-1$），变量 `cur` 滚动 $f(i)$，`ans` 累加即可。

**观察四：答案规模与溢出**。子串数 $\le \frac{n(n+1)}{2} \approx 5 \times 10^9$，每串引力 $\le 26$，总引力上界 $\approx 1.3 \times 10^{11}$，超出 32 位 `int`（$\approx 2.1 \times 10^9$）。C++ 中 `ans`、`cur` 必须用 `long long`；Python 整数任意精度，无此虑。

### 2.3 算法流程图

![流程：初始化 last/cur/ans → 遍历 i → delta=i−last[c] → cur+=delta, last[c]=i → ans+=cur → 返回](../images/2262_algorithm_flow.svg)

1. **初始化**：`last[c] = -1`（$c \in [0,25]$），`cur = 0`，`ans = 0`。
2. **遍历** `i` 从 `0` 到 `n-1`：
   - `c = s[i] - 'a'`。
   - `delta = i - last[c]`。
   - `cur += delta`，得到 $f(i)$。
   - `last[c] = i`，更新最右位置。
   - `ans += cur`，累加到总引力。
3. **返回** `ans`。

> 💡 **不变式**：处理完位置 $i$ 后，`cur` 恒等于 $f(i) = \sum_c (\text{last}_i[c] + 1)$。由于仅 $s[i]$ 对应字符的 `last` 变化，`delta` 一步把 $f(i-1)$ 修正为 $f(i)$，转移 $O(1)$。

### 2.4 示例演算

![示例演算：s="abbca" 逐位置滚动 cur=f(i)，delta=i−last[s[i]]，累加得 28](../images/2262_example_walkthrough.svg)

以 `s = "abbca"`（$n=5$）为例，初始 `cur=0`、`ans=0`，`last[*]=-1`：

| $i$ | $s[i]$ | $\text{last}[s[i]]$（前） | $\Delta=i-\text{last}$ | $\text{cur}=f(i)$ | $\text{ans}$（累计） |
|-----|--------|---------------------------|------------------------|-------------------|----------------------|
| 0   | a      | $-1$                      | $0-(-1)=1$             | 1                 | 1                    |
| 1   | b      | $-1$                      | $1-(-1)=2$             | 3                 | 4                    |
| 2   | b      | $1$                       | $2-1=1$                | 4                 | 8                    |
| 3   | c      | $-1$                      | $3-(-1)=4$             | 8                 | 16                   |
| 4   | a      | $0$                       | $4-0=4$                | 12                | **28**               |

- $i=0$：首个 `a`，`last[a]` 从 $-1$ 变 $0$，$\Delta=1$，`cur=1`（子串 `"a"` 引力 1）。
- $i=4$：`a` 上次在 $0$，$\Delta=4-0=4$。即把 `'a'` 追加到 `"abbc"/"bbc"/"bc"/"c"` 后，后三个不含 `'a'` 各 $+1$，加上新增 `"a"` 共 $+4$；`cur` 由 $8$ 跳到 $12$。

累加 `cur` 序列 $1+3+4+8+12 = 28$ ✓

**答案 = 28** ✓

再以 `s = "code"`（全字符互异）验证：$\Delta$ 序列为 $1,2,3,4$，`cur` 序列 $1,3,6,10$，累加 $=20$ ✓（$f(i)=\frac{(i+1)(i+2)}{2}$，对应等差求和）。

## 3. 参考代码

### C++（右端扩展 + last 表，推荐）

```cpp
class Solution {
  public:
    long long appealSum(string s) {
        long long ans = 0, cur = 0;
        int last[26];
        for (int i = 0; i < 26; ++i) last[i] = -1;

        for (int i = 0; i < (int)s.size(); ++i) {
            int c = s[i] - 'a';
            cur += i - last[c]; // delta = i − last[s[i]]，滚动 f(i)
            last[c] = i;        // 更新该字符最右位置
            ans += cur;         // 累加 f(i) 到总引力
        }
        return ans;
    }
};
```

> ⚠️ `ans`、`cur` 必须用 `long long`：总引力上界 $\approx 26 \cdot \frac{n(n+1)}{2} \approx 1.3 \times 10^{11}$，超出 `int`。`last` 用定长数组比 `unordered_map` 更快且更省内存（字符集仅 26）。

### Python（右端扩展 + last 字典）

```python
class Solution:
    def appealSum(self, s: str) -> int:
        ans = cur = 0
        last = {}
        for i, ch in enumerate(s):
            cur += i - last.get(ch, -1)  # delta = i − last[ch]
            last[ch] = i                 # 更新最右位置
            ans += cur                   # 累加 f(i)
        return ans
```

> 💡 Python 用 `dict.get(ch, -1)` 天然处理“未出现”情形，无需预先填 26 个键。整数无溢出，逻辑与 C++ 完全对应。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(n)$ | 一次遍历，每步 $O(1)$（查 `last`、加 `delta`、更新 `last`、累加 `ans`） |
| 空间复杂度 | $O(|\Sigma|)$ | `last` 表大小等于字符集大小；本题小写字母 $|\Sigma|=26$，可视为 $O(1)$ 额外空间 |

> 💡 相比暴力 $O(n^2)$，贡献法把“逐子串求引力”重构为“逐字符 $/$ 逐右端滚动 $f(i)$”，用 $O(|\Sigma|)$ 的 `last` 表换 $O(n)$ 的线性时间，是典型的**计数换序 + 增量递推**范式。

## 5. 扩展：左端贡献视角与对偶公式

上面是“右端扩展”视角，按**右端**累加 $f(i)$。对偶地有“左端贡献”视角：把每个 $(\text{子串}, c)$ 对 attributed 到 $c$ 在该子串中的**最左**出现位置。设 $\text{last}'[c]$ 为 $c$ 上次出现位置（同前），则位置 $i$ 的 $s[i]$ 作为“子串中最左 $c$”的子串数为：左端 $j \in (\text{last}'[c],\ i]$（$i - \text{last}'[c]$ 个）$\times$ 右端 $k \in [i,\ n-1]$（$n - i$ 个），即

$$\text{total} = \sum_{i=0}^{n-1} (i - \text{last}[s[i]]) \cdot (n - i)$$

以 `"abbca"` 验证：$(0+1)\cdot5 + (1+1)\cdot4 + (2-1)\cdot3 + (3+1)\cdot2 + (4-0)\cdot1 = 5 + 8 + 3 + 8 + 4 = 28$ ✓

> 💡 两种视角等价、都是 $O(n)$：右端法滚动 `cur` 累加；左端法每项独立相乘再求和。右端法的优点是 `cur` 复用上一步结果、常数更小，且与“扩展子串”的直观一致，故本文以其为主。

> ⚠️ 注意左端法每项 $(i-\text{last})(n-i)$ 单独看**不是**“以 $i$ 为最右 $c$ 的子串数”（那需用到下一次出现 $\text{next}[c]$），而是“以 $i$ 为最**左** $c$ 的子串数”。两者对每个 $(\text{子串},c)$ 对各计一次，总和相同，但逐项含义不同，切勿混用。

## 6. 面试要点

1. **为什么不能直接枚举所有子串？**

   - 子串数 $\frac{n(n+1)}{2} \approx 5 \times 10^9$（$n=10^5$），即便每个子串 $O(1)$ 增量数引力，累加次数仍达 $5 \times 10^9$，常数过大、必然超时。必须换求和顺序，把 $O(n^2)$ 降为 $O(n)$。

2. **“换求和顺序”具体怎么换？**

   - 总引力 $= \sum_{\text{子串}} \text{appeal} = \sum_{\text{子串}} \sum_c [c \in \text{子串}] = \sum_c \sum_{\text{子串}} [c \in \text{子串}] = \sum_c (\text{含 } c \text{ 的子串数})$。把“逐子串求和”翻转为“逐字符求和”，每个字符的贡献由其出现位置决定，可 $O(1)$ 增量维护。

3. **`delta = i - last[s[i]]` 的直观含义？**

   - 把 $s[i]$ 追加到所有以 $i-1$ 结尾的子串，引力增加 $1$ 的恰是“原本不含 $s[i]$”的那些（左端 $>$ 上次出现位置，共 $(i-1)-\text{last}$ 个），再加单字符新子串 $s[i..i]$ 的 $+1$，合计 $\Delta = (i-1)-\text{last}+1 = i-\text{last}$。

4. **为什么 `ans`/`cur` 要用 `long long`？**

   - 总引力上界 $\approx 26 \cdot \frac{n(n+1)}{2} \approx 1.3 \times 10^{11}$（$n=10^5$），远超 32 位 `int`（$\approx 2.1 \times 10^9$）。用 `int` 会溢出返回错误结果。Python 整数任意精度无此问题。

5. **`last` 用数组还是哈希表？字符集变大怎么办？**

   - 本题字符集为 26 个小写字母，定长数组 `int last[26]` 最快最省。若字符集扩大（如任意 ASCII / Unicode），改用 `unordered_map`/`dict`，空间 $O(|\Sigma|)$ 但均摊 $O(1)$ 查询；若 $|\Sigma|$ 与 $n$ 同阶，整体仍 $O(n)$。

6. **与 828“统计子串中的唯一字符”有何异同？**

   - 828 统计 $\sum_{\text{子串}} (\text{只出现一次的字符数})$，贡献按“该字符在子串中**唯一**出现”计，需同时看上一次与下一次出现（左右边界相乘）；本题按“该字符在子串中**至少出现一次**”计，只需看上一次出现。二者同为贡献法骨架，但贡献条件不同，是面试常成对出现的姊妹题。
