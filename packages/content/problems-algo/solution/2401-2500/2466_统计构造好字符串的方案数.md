# LeetCode 统计构造好字符串的方案数 题解

## 1. 题目概述

- **标题 / 题号**：统计构造好字符串的方案数（#2466，medium）
- **链接**：https://leetcode.cn/problems/count-ways-to-build-good-strings/
- **难度**：中等
- **标签**：动态规划、字符串、完全背包计数

**题意**：给定整数 `zero`、`one`、`low`、`high`。从空字符串开始构造一个字符串，每一步执行以下操作中的一种：

- 在末尾添加 `'0'` 共 `zero` 次（长度增加 `zero`）；
- 在末尾添加 `'1'` 共 `one` 次（长度增加 `one`）。

操作可执行任意次。若最终字符串的**长度**落在 $[\text{low},\text{high}]$（含边界）内，则称其为**好字符串**。返回不同好字符串的数目，结果对 $10^9+7$ 取余。

**示例 1**：

```text
输入：low = 3, high = 3, zero = 1, one = 1
输出：8
解释：长度恰为 3 的二进制串共 2^3 = 8 个，从 "000" 到 "111" 都是好字符串。
```

**示例 2**：

```text
输入：low = 2, high = 3, zero = 1, one = 2
输出：5
解释：好字符串为 "00"、"11"、"000"、"110"、"011"。
```

**约束**：

- $1 \le \text{low} \le \text{high} \le 10^5$
- $1 \le \text{zero}, \text{one} \le \text{low}$

> 💡 关键在于把「构造一个字符串」翻译成「达到某个长度」：每次操作只让长度 $+\text{zero}$ 或 $+\text{one}$，而两种操作因产生字符不同（全 `'0'` 块 vs 全 `'1'` 块）而天然区分。于是「不同字符串的数目」恰好等于「从长度 $0$ 出发、用步长 $\{\text{zero},\text{one}\}$ 爬到长度 $i$ 的路径数」——这正是 [70. 爬楼梯](../0001-0100/70_爬楼梯.md) 把步长从 $\{1,2\}$ 换成 $\{\text{zero},\text{one}\}$ 的形态。

## 2. 解题思路

### 2.1 暴力思路：DFS 枚举所有操作序列

最直观的做法是从空串出发 DFS：每步选择「加 `zero` 个 `'0'`」或「加 `one` 个 `'1'`」，一旦长度落在 $[\text{low},\text{high}]$ 就计入答案，超过 `high` 就剪枝回溯。

```text
ans = 0
def dfs(len):
    if len > high:        return          # 剪枝：长度越界
    if len >= low:       ans += 1        # 命中好字符串
    dfs(len + zero)                      # 选择 1：加 '0'×zero
    dfs(len + one)                       # 选择 2：加 '1'×one
```

当 `zero = one = 1` 时，长度每步恰好 $+1$，长度 $\in[\text{low},\text{high}]$ 的每条路径都对应一个二进制串，路径数 $\sim 2^{\text{high}}$，$\text{high}=10^5$ 时完全不可行。

> ⚠️ 瓶颈在于「逐路径独立计数」：同一个长度被无数条路径反复抵达，却没有任何**长度层面**的复用。突破口是把「数路径」改成「数长度」——只关心**长度 $i$ 有多少种方案到达**，方案数可由更短长度的方案数滚动推出，无需记录路径细节。

### 2.2 核心观察：长度轴上的爬楼梯一维 DP

![核心观察：dp[i] 由 dp[i−zero] 与 dp[i−one] 转移而来，区间求和得答案](../images/goodstring_dp_concept.svg)

令 $\text{dp}[i]$ = 恰好构造出长度为 $i$ 的字符串的方案数。基准 $\text{dp}[0]=1$（空串一种）。转移方程：

$$
\text{dp}[i] \;=\; \bigl(i\ge\text{zero}\ ?\ \text{dp}[i-\text{zero}]\ :\ 0\bigr)\;+\;\bigl(i\ge\text{one}\ ?\ \text{dp}[i-\text{one}]\ :\ 0\bigr)
$$

即「从长度 $i-\text{zero}$ 末尾补 `zero` 个 `'0'`」与「从长度 $i-\text{one}$ 末尾补 `one` 个 `'1'`」两条来源相加。最终答案为

$$
\text{ans} \;=\; \sum_{i=\text{low}}^{\text{high}} \text{dp}[i] \pmod{10^9+7}.
$$

**为什么 DP 计的是「不同字符串数」而非「相同字符串被重复计入」？** 这是本题最易误解之处，三条性质合起来保证一一对应：

1. **无后效性**：长度 $i$ 的方案数只依赖更短的 $i-\text{zero}$、$i-\text{one}$，与「前面具体排成哪条串」无关——把长度作为唯一状态足矣，不必记串本身。
2. **块长固定→切分唯一**：`'0'` 块长度恒为 `zero`、`'1'` 块长度恒为 `one`。给定一个合法串，按字符种类切成连续 run 后，每段 run 的长度必是 `zero`（或 `one`）的整数倍，从而唯一还原出操作序列。故**不同操作序列 ⇄ 不同字符串**。
3. **加法而非或**：当 `zero == one` 时，两项 $\text{dp}[i-\text{zero}]$ 与 $\text{dp}[i-\text{one}]$ 指向**同一个下标值**，但代表「补 `'0'` 块」与「补 `'1'` 块」两种产生**不同字符**的操作，必须**都计入**（示例 1 中 `zero=one=1` 正是靠这一步把方案数翻倍成 $2^i$）。代码里写两个并列 `if`、各加一次，即可正确处理；若误用 `if/elif` 或去重，会直接漏算。

> 💡 与 [70. 爬楼梯](../0001-0100/70_爬楼梯.md) 对照：70 的步长 $\{1,2\}$ 对应 `zero=1, one=2`，$\text{dp}[i]=\text{dp}[i-1]+\text{dp}[i-2]$ 正是斐波那契；本题只是把步长换成 $\{\text{zero},\text{one}\}$ 并把「爬到第 $n$ 阶」改成「爬进 $[\text{low},\text{high}]$ 这一段台阶求和」。

### 2.3 算法流程图

![算法流程：初始化 dp[0]=1，循环填 dp[1..high]，最后对 [low,high] 求和](../images/goodstring_algorithm_flow.svg)

一趟循环即可完成，骨架四步：

1. **初始化**：$\text{dp}[0]=1$，其余 $\text{dp}[1..{high}]=0$；$\text{ans}=0$；
2. **填表**：对 $i$ 从 $1$ 到 $\text{high}$，按转移式累加两项（下标越界则该项为 $0$），每步对 $M=10^9+7$ 取余；
3. **区间求和**：在填表过程中，一旦 $i\ge\text{low}$，就把 $\text{dp}[i]$ 累加进 $\text{ans}$（避免第二趟扫描，也省下完整数组外的额外遍历）；
4. **返回**：$\text{ans}\bmod M$。

$i$ 单调递增，每步 $O(1)$，总 $O(\text{high})$。

> ⚠️ **取余时机**：每步填 $\text{dp}[i]$ 后立即对 $M$ 取余，累加进 $\text{ans}$ 时也取余，防止中间值溢出。C++ 中 $\text{dp}$ 用 `int` 即可（两项之和 $<2M<2^{31}$），但累加器与运算常量须确保整型提升。

### 2.4 示例演算

以示例 2 `zero=1, one=2, low=2, high=3` 为例，逐位填表：

![示例演算：zero=1, one=2, 逐步填 dp[0..3] 并对区间求和得 5](../images/goodstring_example_walkthrough.svg)

| 步 | $i$ | $\text{dp}[i-\text{zero}]=\text{dp}[i-1]$ | $\text{dp}[i-\text{one}]=\text{dp}[i-2]$ | $\text{dp}[i]$ | $\in[2,3]?$ | 对应字符串 |
|----|-----|-------------------------------------------|------------------------------------------|----------------|-------------|-----------|
| 0 | 0 | —（base） | — | **1** | 否 | （空串） |
| 1 | 1 | 1 | —（越界→0） | **1** | 否 | `"0"` |
| 2 | 2 | 1 | 1 | **2** | 是 | `"00"`、`"11"` |
| 3 | 3 | 2 | 1 | **3** | 是 | `"000"`、`"011"`、`"110"` |

- $i=0$：空串，基准 $\text{dp}[0]=1$；
- $i=1$：只能来自 $i-\text{zero}=0$（补 1 个 `'0'`），$\text{dp}[1]=\text{dp}[0]=1$；$i-\text{one}=-1$ 越界取 0；
- $i=2$：$\text{dp}[2]=\text{dp}[1]+\text{dp}[0]=1+1=2$，对应 `"00"`（`"0"`+`"0"`）与 `"11"`（空+`"11"`）；
- $i=3$：$\text{dp}[3]=\text{dp}[2]+\text{dp}[1]=2+1=3$，对应 `"000"`、`"011"`、`"110"`。

区间求和 $\text{ans}=\text{dp}[2]+\text{dp}[3]=2+3=5$ ✓。

> 💡 注意 $i=1$ 时 $\text{dp}[i-\text{one}]=\text{dp}[-1]$ 越界，须当 $0$ 处理；代码里用 `if i >= one` 守卫即可。这正是「步长可能大于 1」相对 [70. 爬楼梯](../0001-0100/70_爬楼梯.md)（步长固定含 1）多出的一处边界意识。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    int countGoodStrings(int low, int high, int zero, int one) {
        const int MOD = 1000000007;
        vector<int> dp(high + 1, 0);
        dp[0] = 1;
        int ans = 0;
        for (int i = 1; i <= high; ++i) {
            if (i >= zero) dp[i] = (dp[i] + dp[i - zero]) % MOD;   // 补 zero 个 '0'
            if (i >= one)  dp[i] = (dp[i] + dp[i - one])  % MOD;   // 补 one  个 '1'
            if (i >= low)  ans = (ans + dp[i]) % MOD;              // 命中好字符串区间
        }
        return ans;
    }
};
```

> ⚠️ **两个 `if` 必须并列**：当 `zero == one` 时它们指向同一下标 `dp[i-zero]`，但分别代表「补 `'0'` 块」与「补 `'1'` 块」两种产生不同字符的操作，须各加一次。若写成 `if/else if` 会漏掉一种，使 `zero==one` 时答案退化成 $2^{i-1}$ 而非正确的 $2^i$。两条件在语义上独立（一个长度可同时满足「足够补 `'0'`」与「足够补 `'1'`」），故并列 `if`。

### Python

```python
class Solution:
    def countGoodStrings(self, low: int, high: int, zero: int, one: int) -> int:
        MOD = 10 ** 9 + 7
        dp = [0] * (high + 1)
        dp[0] = 1
        ans = 0
        for i in range(1, high + 1):
            if i >= zero:
                dp[i] = (dp[i] + dp[i - zero]) % MOD   # 补 zero 个 '0'
            if i >= one:
                dp[i] = (dp[i] + dp[i - one]) % MOD    # 补 one  个 '1'
            if i >= low:
                ans = (ans + dp[i]) % MOD              # 命中好字符串区间
        return ans
```

> 💡 **空间优化**：$\text{dp}[i]$ 仅依赖 $\text{dp}[i-\text{zero}]$ 与 $\text{dp}[i-\text{one}]$，回看距离至多 $\max(\text{zero},\text{one})\le\text{low}\le\text{high}$，可用大小为 $\max(\text{zero},\text{one})+1$ 的环形数组滚动，最坏仍 $O(\text{high})$，故常数优化有限、直写 $O(\text{high})$ 数组最清爽。

## 4. 复杂度分析

| 维度 | 一维 DP + 区间求和 | DFS 枚举路径 |
|------|-------------------|--------------|
| **时间复杂度** | $O(\text{high})$（单趟循环，每步 $O(1)$） | $O(2^{\text{high}/\min(\text{zero},\text{one})})$（路径数指数爆炸） |
| **空间复杂度** | $O(\text{high})$（`dp` 数组；可滚动至 $O(\max(\text{zero},\text{one}))$） | $O(\text{high}/\min(\text{zero},\text{one}))$（递归栈深度） |
| **状态粒度** | 按长度聚合，长度层面的复用 | 按路径独立，无复用 |

> 💡 从指数级降到线性的关键，是把「逐条路径计数」提升为「按长度分桶聚合」——同一长度的所有路径共用一个 $\text{dp}[i]$，后续长度只读这一个数，不再关心路径内部。这正是「爬楼梯 / 完全背包计数」家族的统一骨架：[70](../0001-0100/70_爬楼梯.md)、[377. 组合总和 IV](../0301-0400/377_组合总和IV.md) 都是同一套「外层目标、内层步长」的转移。

## 5. 扩展：与「零钱兑换 II（组合计数）」的对照

`dp[i]=dp[i-step]` 这种结构既可数**排列**也可数**组合**，区别只在外层/内层循环的嵌套顺序：

| 问题 | 循环顺序 | 计的是 | 示意 |
|------|----------|--------|------|
| **2466（本题）** | 外层长度 $i$、内层步长 $\{\text{zero},\text{one}\}$ | **排列数**（顺序不同即不同串） | `先 0 后 1` 与 `先 1 后 0` 视为两种 |
| [518. 零钱兑换 II](https://leetcode.cn/problems/coin-change-ii/) | 外层硬币、内层金额 | **组合数**（顺序无关） | 两种视为同一种，只计一次 |

> ⚠️ 本题「顺序不同即不同字符串」的根本原因是两种操作产生**可区分的字符块**（`'0'` 块与 `'1'` 块），序列顺序直接体现在串中；而 518 的硬币是「面值相同即可」，交换顺序得到同一种凑法。若把本题条件改成「只问能否凑出长度、不区分串内容」，则退化为 [322. 零钱兑换](https://leetcode.cn/problems/coin-change/) 的可行性/最小步数版。三题同源不同貌，循环顺序是分水岭。

## 6. 面试要点

1. **怎样把指数级的 DFS 降成一维 DP？**

   > 观察到每次操作只改变「长度」这一个量，且长度 $i$ 的方案数只依赖 $i-\text{zero}$、$i-\text{one}$，与具体串无关。于是以长度为状态 $\text{dp}[i]$，转移 $\text{dp}[i]=\text{dp}[i-\text{zero}]+\text{dp}[i-\text{one}]$（越界项取 0），把「数路径」变成「数长度」，$O(2^{\text{high}})\to O(\text{high})$。

2. **为什么 DP 计的恰好是「不同字符串数」，不会把同一串重复计入？**

   > 因为 `'0'` 块长恒为 `zero`、`'1'` 块长恒为 `one`，任一合法串按字符 run 切分后能唯一还原操作序列，故**操作序列与字符串一一对应**。DP 每条路径恰对应一个不同串，加法不重不漏。

3. **`zero == one` 时转移式会不会重复加同一个 `dp` 值？**

   > 两项虽指向同一下标，但代表「补 `'0'` 块」与「补 `'1'` 块」两种产生**不同字符**的操作，对应的串不同，必须都计入。代码用两个并列 `if` 实现这一「同值不同义」的相加；写成 `if/else if` 会漏算一半。

4. **答案为何要取余、在哪里取？**

   > 最坏 `zero=one=1` 时 $\text{dp}[\text{high}]=2^{\text{high}}$，$\text{high}=10^5$ 远超 64 位范围。须在**每步填表后**立即 $\bmod\,10^9+7$，区间累加时也取余，保证中间值始终 $<M$。C++ 用 `int` 存 $\text{dp}$（两项和 $<2M<2^{31}$）即可，但累加器务必同步取余。

5. **能否只遍历 $[\text{low},\text{high}]$ 而省掉前面的 `dp`？**

   > 不能。$\text{dp}[\text{low}]$ 依赖 $\text{dp}[\text{low}-\text{zero}]$、$\text{dp}[\text{low}-\text{one}]$，而 `zero,one ≤ low` 意味着这些前驱下标 $\ge 0$ 且 $<\text{low}$，必须从 $\text{dp}[0]$ 一路填到 $\text{dp}[\text{high}]$ 才能得到区间内的值。不过在填表同时把 $i\ge\text{low}$ 的项累加进 `ans`，可省一次额外遍历。

> 💡 **一句话总结**：把「构造字符串」抽象成「长度轴上用步长 $\{\text{zero},\text{one}\}$ 爬楼梯」，$\text{dp}[i]=\text{dp}[i-\text{zero}]+\text{dp}[i-\text{one}]$ 一趟填到 $\text{high}$，对 $[\text{low},\text{high}]$ 求和即答案。$O(\text{high})$ / $O(\text{high})$，关键是两个并列 `if` 与「序列⇄串一一对应」的相加语义。
