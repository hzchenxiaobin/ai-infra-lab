# LeetCode 对字母串可执行的最大删除数 题解

## 1. 题目概述

- **标题 / 题号**：对字母串可执行的最大删除数（#2430，hard）
- **链接**：https://leetcode.cn/problems/maximum-deletions-on-a-string/
- **难度**：困难
- **标签**：字符串、动态规划、最长公共前缀（LCP）

**题意**：给定仅由小写字母组成的字符串 `s`。每一步操作可以二选一：

- **删整个串** `s`（操作后串为空，过程结束）；或
- 选一个 $i$ 满足 $1 \le i \le |s|/2$，且 `s` 的**前 $i$ 个字母**与**接下来的 $i$ 个字母相等**（即 $s[0:i] = s[i:2i]$），则**删去前 $i$ 个字母**，剩余 $s[i:]$。

返回把 `s` 完全删去所需的**最大操作数**。

**示例 1**：

```text
输入：s = "abcabcdabc"
输出：2
解释：删前 3 个 "abc"（因 s[0:3]="abc"==s[3:6]="abc"）→ 剩 "abcdabc"；再删整个串。共 2 步。
```

**示例 2**：

```text
输入：s = "aaabaab"
输出：4
解释：删 "a"→"aabaab"；删 "aab"→"aab"；删 "a"→"ab"；删整个。共 4 步。
```

**示例 3**：

```text
输入：s = "aaaaa"
输出：5
解释：每步只删第一个字母，共 5 步。
```

**约束**：

- $1 \le |s| \le 4000$
- `s` 仅由小写英文字母组成

> 💡 关键观察：每次操作要么删整个串（结束），要么只删**前缀**——删前缀后右端点不动、只把左端点右移。因此**剩余串永远是原串的某个后缀** $s[l:]$，状态只需一个左端点 $l$。再配合 LCP 把"前 $i$ 个 == 接下来 $i$ 个"的判定压到 $O(1)$，即得 $O(n^2)$ DP。

## 2. 解题思路

### 2.1 暴力思路：记忆化搜索 + 逐段比较

定义 $f(l)$ = 删去后缀 $s[l:]$ 所需的最大操作数。则

$$
f(l) = \max\Bigl(\,1,\;\;\max_{\substack{1 \le i \le (n-l)/2 \\ s[l:l+i] = s[l+i:2i]}} \bigl(1 + f(l+i)\bigr)\Bigr)
$$

其中 $1$ 是"选项 A：删整个后缀"；$1+f(l+i)$ 是"选项 B：删前 $i$ 个字母后转交后缀 $s[l+i:]$"。答案为 $f(0)$。

直接记忆化：状态 $O(n)$ 个，每个状态枚举 $i$ 共 $O(n)$ 个，每次判 $s[l:l+i] = s[l+i:2i]$ 若用逐字符比较则花 $O(i)$。总计 $O(n^3)$；$n=4000$ 时约 $6.4 \times 10^{10}$，必然 TLE。

> ⚠️ 瓶颈在于**重复比较子串**：$s[l:l+i]$ 与 $s[l+i:2i]$ 的相等性，本质是后缀 $s[l:]$ 与 $s[l+i:]$ 的最长公共前缀是否 $\ge i$。这是一次"后缀对"的 LCP 查询，可预处理后 $O(1)$ 回答——把"逐 i 重扫子串"压成"一次查表"。

### 2.2 核心观察：后缀 DP + LCP 预处理

![核心观察：删前缀后剩余恒为原串后缀 s[l:]，状态只需左端点 l](../images/mdel_concept.svg)

**第一步——降状态**：因为操作只删前缀，右端点恒为 $n-1$，只有左端点 $l$ 在变。所以 $f(l)$ 仅依赖 $l$，状态数 $O(n)$。

**第二步——压判定**：判 $s[l:l+i] = s[l+i:2i]$ 等价于

$$
\text{lcp}(l,\, l+i) \ge i,
$$

其中 $\text{lcp}(a, b)$ 是后缀 $s[a:]$ 与 $s[b:]$ 的最长公共前缀长度。LCP 满足递推

$$
\text{lcp}(a, b) =
\begin{cases}
1 + \text{lcp}(a+1, b+1), & s[a] = s[b] \\
0, & s[a] \ne s[b]
\end{cases}
$$

> 💡 **滚动数组省空间**：上式依赖"下一行"$\text{lcp}(l+1, \cdot)$。维护一维数组 $\textit{nxt}[j] = \text{lcp}(l+1, j)$，处理 $l$ 时先用它算 $f[l]$（$\text{lcp}(l,l+i) = (s[l]{=}s[l+i])\,?\,1+\textit{nxt}[l{+}i{+}1]:0$），再把 $\textit{nxt}$ 原地滚成 $\text{lcp}(l, \cdot)$：**从左到右**更新 $\textit{nxt}[k] = (s[l]{=}s[k])\,?\,1+\textit{nxt}[k{+}1]:0$。左→右保证读 $\textit{nxt}[k{+}1]$ 时它仍是上一行的旧值（尚未被覆盖）。如此空间 $O(n)$，而非 $O(n^2)$ 的整张 LCP 表。

于是每个 $f[l]$ 的计算只需枚举 $i$、每次 $O(1)$ 查 LCP，总复杂度降到 $O(n^2)$。

### 2.3 算法流程图

![算法流程：预处理 LCP（滚动 nxt）→ 反向 DP l=n−1..0 → 返回 f[0]](../images/mdel_algorithm_flow.svg)

骨架三步：

1. **预处理 LCP**：维护 $\textit{nxt}[j]=\text{lcp}(l+1,j)$，初始全 0（对应 $l=n$ 的空后缀）；
2. **反向 DP**：$l$ 从 $n-1$ 到 $0$。对每个后缀 $s[l:]$：
   - $\textit{best} \leftarrow 1$（选项 A，删整个）；
   - 枚举 $i=1 \dots \lfloor(n-l)/2\rfloor$，若 $\text{lcp}(l,l+i) \ge i$，则 $\textit{best} \leftarrow \max(\textit{best},\, 1+f[l+i])$；
   - $f[l] \leftarrow \textit{best}$；
   - 把 $\textit{nxt}$ 左→右原地滚成 $\text{lcp}(l,\cdot)$，供下一轮 $l-1$ 使用；
3. **返回** $f[0]$。

> ⚠️ **边界**：$f[n]=0$（空串）；当 $n-l < 2$ 时枚举 $i$ 的区间为空，$f[l]=1$（只能删整个）。访问 $\textit{nxt}[l+i+1]$ 的下标上界为 $l+\lfloor(n-l)/2\rfloor+1 \le n$，而 $\textit{nxt}[n]$ 恒为 0（$\text{lcp}(\cdot,n)=0$），故不越界。

### 2.4 示例演算

![示例演算：s=aaabaab 的 f[l] 与最优删法路径](../images/mdel_example_walkthrough.svg)

以示例 2 `s = "aaabaab"`，$n=7$。从 $l=6$ 倒推：

| $l$ | 后缀 $s[l:]$ | 合法 $i$（$\text{lcp}(l,l+i)\ge i$） | 转移取值 | $f[l]$ |
|-----|--------------|----------------------------------------|----------|--------|
| 6 | `b` | — | $1$ | 1 |
| 5 | `ab` | — | $1$ | 1 |
| 4 | `aab` | $i=1$（`a`==`a`） | $\max(1,\,1{+}f[5]{=}2)$ | **2** |
| 3 | `baab` | — | $1$ | 1 |
| 2 | `abaab` | — | $1$ | 1 |
| 1 | `aabaab` | $i=1$（`a`==`a`），$i=3$（`aab`==`aab`） | $\max(1,\,1{+}f[2]{=}2,\,1{+}f[4]{=}3)$ | **3** |
| 0 | `aaabaab` | $i=1$（`a`==`a`） | $\max(1,\,1{+}f[1]{=}4)$ | **4** |

最优路径：$l=0 \xrightarrow{i=1} l=1 \xrightarrow{i=3} l=4 \xrightarrow{i=1} l=5 \xrightarrow{\text{整段}} \varnothing$，共 $4$ 步 ✓。

> 💡 注意 $l=1$ 处贪心取最小 $i=1$ 只得 $1{+}f[2]=2$，而取 $i=3$ 得 $1{+}f[4]=3$ 更优——**必须对所有合法 $i$ 取 max**，这正是要 DP 而非贪心的原因。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    int deleteString(string s) {
        int n = s.size();
        vector<int> f(n + 1, 0);          // f[l] = 删后缀 s[l:] 的最大操作数；f[n]=0
        vector<int> nxt(n + 2, 0);        // nxt[j] = lcp(l+1, j)；nxt[n]/nxt[n+1] 恒 0
        for (int l = n - 1; l >= 0; --l) {
            int m = n - l;
            int best = 1;                 // 选项 A：删整个后缀
            for (int i = 1; 2 * i <= m; ++i) {
                // lcp(l, l+i) = (s[l]==s[l+i]) ? 1 + lcp(l+1, l+i+1) : 0
                int lcp = (s[l] == s[l + i]) ? 1 + nxt[l + i + 1] : 0;
                if (lcp >= i) best = max(best, 1 + f[l + i]);
            }
            f[l] = best;
            // nxt 左→右原地滚动为 lcp(l, ·)：读 nxt[k+1] 时它仍是上一行旧值
            for (int k = l; k < n; ++k)
                nxt[k] = (s[l] == s[k]) ? 1 + nxt[k + 1] : 0;
        }
        return f[0];
    }
};
```

> 💡 两个循环合起来：枚举 $i$ 的总次数 $\sum_l (n{-}l)/2 = O(n^2/4)$，滚动 $\textit{nxt}$ 的总次数 $\sum_l (n{-}l) = O(n^2/2)$，整体约 $1.2 \times 10^7$ 次整数运算，$n=4000$ 下毫秒级。

### Python

```python
class Solution:
    def deleteString(self, s: str) -> int:
        n = len(s)
        f = [0] * (n + 1)                # f[n] = 0
        nxt = [0] * (n + 2)             # nxt[j] = lcp(l+1, j)；尾部两格恒 0
        for l in range(n - 1, -1, -1):
            m = n - l
            best = 1                     # 选项 A：删整个后缀
            for i in range(1, m // 2 + 1):
                lcp = 1 + nxt[l + i + 1] if s[l] == s[l + i] else 0
                if lcp >= i:
                    cand = 1 + f[l + i]
                    if cand > best:
                        best = cand
            f[l] = best
            # nxt 左→右原地滚动为 lcp(l, ·)
            for k in range(l, n):
                nxt[k] = 1 + nxt[k + 1] if s[l] == s[k] else 0
        return f[0]
```

> 💡 Python 下 $O(n^2)$ 约 $1.2 \times 10^7$ 次循环，在力扣时限内可过。若仍想提速，可把内层用预计算的二维 LCP（`array('H')` 扁平表）替代滚动，省掉滚 $\textit{nxt}$ 的那趟 $O(n^2/2)$，仅保留枚举 $i$ 的 $O(n^2/4)$。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n^2)$ | 每个 $l$ 枚举 $i$ 约 $(n{-}l)/2$ 次、滚动 $\textit{nxt}$ 约 $(n{-}l)$ 次，求和 $\Theta(n^2)$ |
| **空间复杂度** | $O(n)$ | `f` 与 `nxt` 两个长度 $n{+}2$ 的一维数组；滚动省去了 $O(n^2)$ 的整张 LCP 表 |
| 对照：暴力记忆化 | $O(n^3)$ | 状态 $O(n)$ × 枚举 $O(n)$ × 逐字符比较 $O(i)$，$n=4000$ 约 $6.4 \times 10^{10}$，TLE |

> 💡 LCP 把"子串相等判定"从 $O(i)$ 压到 $O(1)$，是"重叠子串比较 + 可复用前缀"从 $O(n^3)$ 降到 $O(n^2)$ 的通用范式——与 [718. 最长重复子数组](../0701-0800/718_最长重复子数组.md) 的 lcp 型二维 DP、[1392. 最长快乐前缀](../1301-1400/1392_最长快乐前缀.md) 的 lcp(0,·) 预处理同源。

## 5. 扩展：LCP 的其它求法与贪心的反例

**LCP 的等价求法**：本题用"二维 DP + 滚动到一维"求任意 $\text{lcp}(a,b)$，最直观。其它常见做法都能把"判 $s[l:l+i]=s[l+i:2i]$"压到 $O(1)$ 或 $O(\log n)$，但实现更重：

| 方法 | 预处理 | 单次查询 | 备注 |
|------|--------|----------|------|
| 二维 LCP DP（滚动） | $O(n^2)$ | $O(1)$ | 本题采用，空间可压到 $O(n)$ |
| Z 函数 | $O(n)$ | 仅 $\text{lcp}(0,\cdot)$ | 只覆盖"前缀对"，本题需任意 $l$，需对每个后缀跑一次 → $O(n^2)$ |
| 后缀数组 + LCP 数组 + ST 表 | $O(n \log n)$ | $O(1)$ | 通用但代码量大，$n=4000$ 杀鸡用牛刀 |
| 滚动哈希 + 二分 | $O(n)$ | $O(\log n)$ | 判 $s[l:l+i]=s[l+i:2i]$ 改为二分最长公共前缀再比 $i$；需双哈希防冲突 |

> 💡 $n=4000$ 时 $O(n^2)$ 的二维 LCP 已足够小（$\sim 1.6 \times 10^7$），后缀数组/哈希的优势要到 $n \sim 10^5$ 才显现，本题不必上重武器。

**为何不能贪心**：一个自然的贪心是"每步取最小的合法 $i$"（删得越少、步数越多）。但示例 2 在 $l=1$（`aabaab`）处给出反例——取 $i=1$ 得 $1{+}f[2]=2$，取 $i=3$ 得 $1{+}f[4]=3$，**大 $i$ 反而更优**。原因是删更长前缀可能跳到一个"自身可拆很多步"的后缀（$f[4]=2 > f[2]=1$）。子结构无后效性（剩余只由 $l+i$ 决定），故只能枚举所有 $i$ 取 max，DP 不可避免。

## 6. 面试要点

1. **为什么"剩余串恒为原串后缀"？**

   > 每次操作要么删整个串（结束），要么删前缀——右端点恒为 $n-1$，只有左端点 $l$ 右移。归纳可知剩余串形如 $s[l:]$。这是把状态从"任意子串 $s[l..r]$"降到"仅左端点 $l$"的关键，状态数从 $O(n^2)$ 变 $O(n)$。

2. **朴素 $O(n^3)$ 的瓶颈在哪？如何降到 $O(n^2)$？**

   > 状态 $O(n)$、每个状态枚举 $i$ 共 $O(n)$、每次判 $s[l:l+i]=s[l+i:2i]$ 逐字符比 $O(i)$ → $O(n^3)$。观察到该判定等价于 $\text{lcp}(l,l+i) \ge i$，用二维 LCP DP 预处理后 $O(1)$ 回答，总 $O(n^2)$。

3. **$\textit{nxt}$ 滚动为什么必须从左到右原地更新？**

   > $\textit{nxt}_{\text{new}}[k] = (s[l]{=}s[k])\,?\,1+\textit{nxt}_{\text{old}}[k{+}1]:0$ 依赖上一行第 $k{+}1$ 列。**左→右**更新时，处理 $k$ 时 $k{+}1$ 尚未被覆盖，读到的还是旧值（$\text{lcp}(l{+}1,\cdot)$）；若误用右→左，则会读到本轮已改写的新值（$\text{lcp}(l,\cdot)$），递推出错。

4. **能否贪心取最小 $i$？给反例。**

   > 不能。$s=$`aabaab`（对应示例 2 的 $l=1$）：$i=1$ 得 $1{+}f[2]=2$，$i=3$ 得 $1{+}f[4]=3$。删更长前缀跳到更"可拆"的后缀可能更优，须对所有合法 $i$ 取 max。

5. **若 $n$ 升到 $10^5$ 怎么办？**

   > $O(n^2)$ 不够。改用后缀数组 + LCP 数组 + ST 表（$O(n \log n)$ 预处理、$O(1)$ 查任意 $\text{lcp}$），DP 仍是 $f(l)=\max(1,\max_i 1{+}f(l+i))$，但每个 $l$ 枚举 $i$ 仍 $O(n)$ → 总 $O(n^2)$ 仍超时。此时需进一步利用"合法 $i$ 集合"的结构（如只关心使 $f(l+i)$ 最大的 $i$，配合单调栈/线段树优化转移），属于竞赛级进阶。

> 💡 **一句话总结**：剩余恒为后缀 → 状态 $f(l)$ 只看左端点；用 LCP 把"前 $i$ 个 == 接下来 $i$ 个"压到 $O(1)$，反向 DP 取 max 即得，$O(n^2)$ 时间、$O(n)$ 空间。
