# LeetCode 按身高排序 题解

## 1. 题目概述

- **标题 / 题号**：按身高排序（#2418，easy）
- **链接**：https://leetcode.cn/problems/sort-the-people/
- **难度**：简单
- **标签**：数组、排序、索引数组

**题意**：给你两个长度均为 `n` 的平行数组：字符串数组 `names` 与**互不相同**的正整数数组 `heights`。对于每个下标 `i`，`names[i]` 与 `heights[i]` 表示第 `i` 个人的名字和身高。请按身高**降序**顺序返回对应的名字数组。

**示例 1**：

```text
输入：names = ["Mary","John","Emma"], heights = [180,165,170]
输出：["Mary","Emma","John"]
解释：Mary(180) 最高，接着 Emma(170)、John(165)。
```

**示例 2**：

```text
输入：names = ["Alice","Bob","Bob"], heights = [155,185,150]
输出：["Bob","Alice","Bob"]
解释：第一个 Bob(185) 最高，然后 Alice(155)、第二个 Bob(150)。
```

**约束**：

- $n = \text{names.length} = \text{heights.length}$
- $1 \le n \le 10^3$
- $1 \le \text{names}[i].\text{length} \le 20$
- $1 \le \text{heights}[i] \le 10^5$
- `names[i]` 由大小写英文字母组成
- `heights` 中的所有值**互不相同**

> 💡 **关键不变式**：`names` 与 `heights` 是**平行数组**——同一下标 `i` 的两条信息天然绑定，但**绑定关系不动**，需要重排的是「输出顺序」。再加上 `heights` 互不相同，排序结果**唯一确定**、不存在并列，稳定性不再是问题。核心问题退化为：如何按 `heights` 的顺序，把 `names` 重新取一遍。

## 2. 解题思路

### 2.1 暴力思路：选择式重复扫描

最直白的做法是**逐个选最大**：输出有 $n$ 个位置，第 $k$ 个位置要从「尚未用过的人」中挑身高最高者，把其名字写入答案。

```text
used = [False] * n
for k in 0..n-1:
    best = -1
    for i in 0..n-1:
        if not used[i] and heights[i] > best:
            best = heights[i]; pick = i
    ans[k] = names[pick]
    used[pick] = True
return ans
```

正确性没问题——每轮都精确选出剩余最大者。但代价是 $O(n^2)$：每个输出位置都要把整个 `heights` 重扫一遍，$n \le 10^3$ 时约 $10^6$ 次比较能 AC，却把「同一个人被反复比较」的重复劳动背在身上。

> ⚠️ 暴力把「找剩余最大」当作独立子任务重做 $n$ 遍，但**整个身高数组的相对顺序在一次排序里就能全部确定**——关键观察：不要逐个挑，**一次性排好序**再按序取名字即可。

### 2.2 核心观察：索引数组间接排序

![核心观察：不搬数据，只排下标——idx 按 heights[idx] 降序排好后，按下标取 names](../images/stp_concept.svg)

把「按身高排序，再取名字」翻译成两个动作：

1. **排下标，不排数据**：构造下标数组 $\text{idx} = [0, 1, \dots, n-1]$，以 $\text{heights}[\text{idx}[i]]$ 为键对其降序排序。排序过程中**只有整数下标被换位**，`names` 与 `heights` 两个原始数组**纹丝不动**——它们只读不写。

2. **按下标取名字**：排序后 $\text{idx}$ 即为「身高从高到低的人的原始下标序列」，于是答案就是 $\text{names}[\text{idx}[0]],\ \text{names}[\text{idx}[1]],\ \dots,\ \text{names}[\text{idx}[n-1]]$。

这就是经典的 **索引数组（argsort）** 技巧。它相比「把 `(height, name)` 捆成对再排序」有两点好处：

| 维度 | 捆绑排序 `(height, name)` | 索引数组 `idx` |
|------|---------------------------|----------------|
| 排序中换位对象 | 字符串 + 整数组成的对 | 仅整数下标 |
| 字符串是否被搬动 | 是（每轮比较/换位都触及字符串） | 否（只在最后读一次） |
| 原数组是否被改 | 否（都构造副本） | 否（`names`/`heights` 全程只读） |

排序时真正的开销在「元素比较 + 换位」次数（$O(n \log n)），二者渐近相同；但索引数组让**体积大、拷贝贵的字符串全程不参与换位**，常数更优、语义更干净，且是「用一个数组的顺序去重排另一个数组」这一大类问题的通用范式。

> 💡 **为什么用 $\text{heights}[\text{idx}[a]]$ 而非 $\text{heights}[a]$ 作键？** 因为被排序的是 `idx` 数组本身——`idx[a]` 才指向「第 $a$ 个槽位对应的那个人」。比较两个人的身高，等于比较 `heights[idx[a]]` 与 `heights[idx[b]]`。这是 argsort 的核心「一层间接」：**排序的对象（下标）与提供键的对象（身高）分属两个数组，下标是二者之间的桥梁**。

### 2.3 算法流程图

![算法流程：构造 idx → 按 heights[idx] 降序排序 → 遍历 idx 收集 names → 返回](../images/stp_algorithm_flow.svg)

算法骨架只有四步，无任何分支特判：

1. **构造**：`idx = [0, 1, …, n-1]`（`iota` 生成）；
2. **排序**：以 $\text{heights}[\text{idx}[i]]$ 为键对 `idx` 降序排序；
3. **收集**：`for i in 0..n-1: ans[i] = names[idx[i]]`；
4. **返回** `ans`。

`heights` 互不相同 ⟹ 排序结果唯一、无需处理并列 ⟹ 无需稳定排序、无需副键。整个流程线性无分支。

### 2.4 示例演算

![示例演算：names=[Mary,John,Emma]、heights=[180,165,170] → idx 降序排成 [0,2,1] → 取名字得 [Mary,Emma,John]](../images/stp_example_walkthrough.svg)

以示例 1 `names = ["Mary","John","Emma"]`、`heights = [180,165,170]` 演算：

**第一步——构造下标数组**：

| 槽位 $i$ | 0 | 1 | 2 |
|----------|---|---|---|
| `idx[i]` | 0 | 1 | 2 |
| 指向的人 | Mary | John | Emma |
| `heights[idx[i]]` | 180 | 165 | 170 |

**第二步——按 `heights[idx]` 降序排序**：比较三人的身高 $180 > 170 > 165$，故排序后下标顺序为 $[0,\ 2,\ 1]$（Mary 最高、Emma 次之、John 最低）：

| 排序后槽位 $k$ | 0 | 1 | 2 |
|----------|---|---|---|
| `idx[k]` | 0 | 2 | 1 |
| `heights[idx[k]]` | 180 | 170 | 165 |

**第三步——按下标取名字**：

| $k$ | `idx[k]` | `names[idx[k]]` |
|-----|----------|-----------------|
| 0 | 0 | Mary |
| 1 | 2 | Emma |
| 2 | 1 | John |

最终答案 `["Mary","Emma","John"]` ✓。

> 💡 注意示例 2 中名字可重复（两个 Bob），但**身高互不相同**保证排序唯一——两个 Bob 因身高不同（185 与 150）被区分到不同位置，绝不会被「同名合并」错排。索引数组按身高排，名字只是被动地跟着下标走。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> sortPeople(vector<string>& names, vector<int>& heights) {
        int n = (int)names.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return heights[a] > heights[b];
        });
        vector<string> ans(n);
        for (int i = 0; i < n; ++i) ans[i] = names[idx[i]];
        return ans;
    }
};
```

> 💡 `iota` 用 $0,1,\dots,n-1$ 填充 `idx`；lambda 捕获 `heights`，比较 `heights[a]`（`a` 已是被排序的下标本身，即 `idx[i]`）——注意这里 `a`、`b` 就是 `idx` 数组里的元素值，故直接 `heights[a]` 而无需再 `heights[idx[a]]`。`names` 全程只读，仅 `ans` 接收结果。

### Python

```python
class Solution:
    def sortPeople(self, names: List[str], heights: List[int]) -> List[str]:
        idx = sorted(range(len(names)), key=lambda i: heights[i], reverse=True)
        return [names[i] for i in idx]
```

> 💡 `sorted(range(n), key=...)` 是 Python 里 argsort 的地道写法——`range(n)` 即下标数组，`key=lambda i: heights[i]` 让排序以身高为键、`reverse=True` 取降序。最后一行列表推导按下标取名字。也可一行流：`return [n for n, _ in sorted(zip(names, heights), key=lambda p: -p[1])]`——这是「捆绑排序」版，对比可见索引数组版语义更清晰、不构造临时对。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n \log n)$ | 排序 `idx` 主导；收集结果线性 $O(n)$，每元素 $O(1)$ |
| **空间复杂度** | $O(n)$ | `idx` 数组 $O(n)$ + 答案数组 $O(n)$；不计输出则 $O(\log n)$（排序栈） |
| 对照：选择式重复扫描 | $O(n^2)$ / $O(n)$ | 每个输出位置重扫整个 `heights`，正确但慢 |
| 对照：捆绑 `(height,name)` 排序 | $O(n \log n)$ / $O(n)$ | 渐近相同，但换位时触及字符串、常数略大 |

> 💡 $n \le 10^3$ 时 $O(n^2) \approx 10^6$ 也能 AC，三种做法差异不明显；但索引数组版是**渐近最优**且语义最干净，并在 $n$ 变大（如 $10^5$）时仍 $O(n \log n)$ 立得住——这是选它而非暴力的根本理由。

## 5. 扩展：argsort 范式与稳定性边界

「索引数组间接排序」即 NumPy 的 `argsort`：**返回的是「使原数组有序的下标序列」**，而非排好序的数据本身。它的价值在于解耦「排序键」与「被取值对象」：

| 情形 | 键来自 | 取值对象 | 例 |
|------|--------|----------|-----|
| 平行数组按其一重排另一个 | `heights` | `names` | **本题 2418** |
| 按子串/派生量排序原数组 | 派生键 | 原数组 | 2343 裁剪数字后查询 |
| 按频次排序值 | 频次表 | 原值 | 1636 按频率排序 |
| 名次变换 | 排名 | 原值 | 1331 数组序号转换 |

一次 `idx` 排序，后续任意「按下标取值」都 $O(1)$——这是把 $O(n^2)$ 重复比较压成 $O(n \log n)$ 的通用杠杆。

**关于稳定性**：本题 `heights` 互不相同 ⟹ 无并列 ⟹ 排序结果唯一、稳定性无意义。但若放宽为「身高可相同、并列时需保输入相对序」，则需用**稳定排序**（Python `sorted` 默认稳定；C++ `stable_sort`），或在键里加副键「原始下标升序」：`key = (-heights[i], i)`。这把「并列保序」从隐式稳定性转为显式副键，与排序算法是否稳定解耦。

> 💡 经验：见到「按 A 的顺序重排 B」一类题，先想 argsort——构造 `idx`、以 `A[idx]` 为键排序、再 `B[idx[i]]` 收集。若 A 有并列且要求保序，加副键 `i` 升序即可，无需依赖 `stable_sort`。

## 6. 面试要点

1. **为什么要用索引数组，而不是把 `(height, name)` 捆成对排序？**

   > 两者渐近都是 $O(n \log n)$，但索引数组让排序换位只触及**整数下标**，字符串全程只读、仅在最后取一次值——避免了对大对象的反复拷贝/交换，常数更优。更重要的是语义更干净：明确表达「键（身高）」与「被取值对象（名字）」分属两个数组，下标是桥梁，这是 argsort 范式的标准写法。

2. **排序键里 `heights[a]` 的 `a` 到底是谁？为什么不是 `heights[idx[a]]`？**

   > `a`、`b` 是 `sort` 传进 lambda 的**被排序元素本身**，而这里被排序的就是 `idx` 数组，所以 `a` 已经是 `idx` 中存的某个下标值（即某个人的原始位置）。比较两个槽位的人的身高，直接 `heights[a]` 即可。只有当被排序的是别的数组、需经一层 `idx` 间接时才会出现 `heights[idx[a]]` 的二重间接。

3. **`heights` 互不相同意味着什么？对实现有什么影响？**

   > 意味着排序结果**唯一**、无并列。因此：(1) 不需要稳定排序；(2) 不需要副键打破并列；(3) 不存在「同名同高被错排」的歧义。示例 2 中两个 Bob 名字相同但身高不同（185 与 150），仍被正确分到不同位置——身高是唯一决定因素。

4. **能否不构造 `ans`，原地返回？**

   > 不能原地改 `names` 本身（要按新顺序输出），但可原地排好 `idx` 后，用 `ans[i] = names[idx[i]]` 填一个新数组返回。若追求零额外输出空间，可原地重排 `names` 使其变为目标序（按 `idx` 做置换、带环分解），但实现复杂且会破坏输入，对 $n \le 10^3$ 完全不划算——构造 `ans` 是最直白正确的选择。

5. **索引数组模式还在哪些题里出现？**

   > 「按一个数组的顺序取另一个数组的值」是通用骨架：1331 数组序号转换（按值排名生成下标序列）、2343 裁剪数字后查询第 K 小的数字（按子串排序下标再二分）、1636 按频率升序排序（按频次表对值排序）。一次 argsort，后续查询全 $O(1)$，是把重复比较压成单次排序的杠杆。

> 💡 **一句话总结**：平行数组按其一降序重排另一个 ⟹ argsort：构造 `idx`、以 `heights[idx]` 为键排序、再 `names[idx[i]]` 收集 ⟹ $O(n \log n)$。`heights` 互不相同保证结果唯一、无需稳定性，索引数组让字符串全程不参与换位——是「按键重排另一数组」类的范式解。
