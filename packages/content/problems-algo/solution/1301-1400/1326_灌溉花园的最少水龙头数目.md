# LeetCode 灌溉花园的最少水龙头数目 题解

## 1. 题目概述

- **标题 / 题号**：灌溉花园的最少水龙头数目（#1326，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-taps-to-open-to-water-a-garden/
- **难度**：困难
- **标签**：贪心、区间覆盖、跳跃游戏

**题意**：在 x 轴上有一个长度为 `n` 的一维花园，区间为 `[0, n]`。花园里共有 `n + 1` 个水龙头，分别位于 `0, 1, ..., n` 处。

给你一个整数 `n` 和一个长度为 `n + 1` 的整数数组 `ranges`，其中 `ranges[i]`（下标从 0 开始）表示第 `i` 个水龙头灌溉的范围是 `[i - ranges[i], i + ranges[i]]`。

**返回可以灌溉整个花园 `[0, n]` 的最少水龙头数目**。如果花园无法被全部灌溉，返回 **-1**。

**示例 1**：

```text
输入：n = 5, ranges = [3,4,1,1,1,0]
输出：1
解释：第 0 个水龙头在 [0 - 3, 0 + 3] = [0, 3] 范围浇水。
     第 1 个水龙头在 [1 - 4, 1 + 4] = [0, 5] 范围浇水。
     只要打开第 1 个水龙头即可浇灌整个花园 [0, 5]。
```

**示例 2**：

```text
输入：n = 3, ranges = [0,0,0,0]
输出：-1
解释：所有水龙头的灌溉范围都是 [i, i]，即只浇自己那一个点，无法覆盖区间。
```

**示例 3**：

```text
输入：n = 5, ranges = [1,2,1,0,2,1]
输出：2
解释：打开第 1 个水龙头覆盖 [0, 3]，打开第 4 个水龙头覆盖 [2, 5]，两段叠加可覆盖整个 [0, 5]。
```

**约束**：

- `1 <= n <= 10^4`
- `ranges.length == n + 1`
- `0 <= ranges[i] <= 100`

> 💡 本题本质是**区间覆盖**问题——用最少数量的区间覆盖 `[0, n]`。一旦把每个水龙头的灌溉区间 `[i−r, i+r]` 转换为「从左端点可一步跳到右端点」的跳跃，问题就变成了 [45. 跳跃游戏 II](../0001-0100/45_跳跃游戏%20II.md) 换皮，直接套贪心模板即可。

## 2. 解题思路

### 2.1 暴力思路：动态规划

最直观的做法：设 `dp[j]` 表示覆盖 `[0, j]` 所需的最少水龙头数。对每个位置 `j`，枚举所有能覆盖到 `j` 的水龙头 `i`（即 `i - ranges[i] <= j <= i + ranges[i]`），取 `dp[j] = min(dp[left] + 1)`，其中 `left = max(0, i - ranges[i])`。

问题在于——

- **时间复杂度 $O(n^2)$**：对每个 `j` 都要枚举所有水龙头，`n = 10^4` 时达到 $10^8$ 量级，虽然勉强能过但远非最优；
- **没有利用区间结构**：水龙头的灌溉区间天然有「从左端点出发能到达多远」的跳跃语义，暴力 DP 完全忽略了这个性质。

> ⚠️ DP 解法正确但不够好。本题的区间结构完全可以转化为跳跃游戏，从而用 $O(n)$ 贪心一趟解决。

### 2.2 核心观察：转换为跳跃游戏 II

![核心观察：水龙头灌溉区间 → 跳跃游戏 reach[]](../images/1326_concept.svg)

**关键洞察**：每个水龙头 `i` 灌溉 `[i - ranges[i], i + ranges[i]]`，这等价于——**在位置 `left = max(0, i - ranges[i])` 处，可以一步跳到 `right = min(n, i + ranges[i])`**。

于是预处理一步：把所有水龙头转换为跳跃游戏中的 `reach[]` 数组：

$$\text{reach}[\max(0,\, i - r_i)] = \max\big(\text{reach}[\max(0,\, i - r_i)],\;\min(n,\, i + r_i)\big)$$

> **同一左端点只留跳得最远的那个水龙头**——因为如果两个水龙头都从 `left` 出发，一个能到 `3`、一个能到 `5`，前者完全被后者支配，保留 `reach[left] = 5` 即可。这就是贪心的「支配消除」。

转换后，问题变为：**从位置 `0` 出发，每次可从 `j` 跳到 `reach[j]`，求覆盖到 `n` 的最少跳跃次数**——这正是 [45. 跳跃游戏 II](../0001-0100/45_跳跃游戏%20II.md)。

> ⚠️ **为什么不是区间调度（按右端点排序）？** 经典的「活动选择 / 会议室」区间调度问题按右端点排序、贪心选不重叠区间。但本题要求**覆盖** `[0, n]`（区间可重叠、要无缝拼接），而非选不重叠区间。覆盖型问题用跳跃游戏贪心（维护最远边界）更自然——两者是不同的贪心范式，勿混淆。

### 2.3 算法流程图

![算法流程：预处理 reach[] + 跳跃游戏贪心一趟](../images/1326_algorithm_flow.svg)

**完整步骤**：

1. **预处理**：遍历每个水龙头 `i`，计算 `left = max(0, i - ranges[i])`、`right = min(n, i + ranges[i])`，更新 `reach[left] = max(reach[left], right)`；
2. **初始化**：`steps = 0`（已开水龙头数）、`end = 0`（当前这步覆盖到的右边界）、`maxPos = 0`（在 `[0, end]` 范围内扫描到的最远可达点）；
3. **贪心循环** `i` 从 `0` 到 `n - 1`：
   - **更新最远可达**：`maxPos = max(maxPos, reach[i])`；
   - **到达当前边界**：若 `i == end`，说明当前这步的覆盖范围已全部考察完，必须再开一个水龙头：
     - **卡死检测**：若 `maxPos <= end`，说明 `[0, end]` 内没有任何水龙头能继续向右扩展，返回 `-1`；
     - **开龙头**：`steps++`，`end = maxPos`；
     - **提前结束**：若 `end >= n`，花园已全覆盖，返回 `steps`；
4. **循环结束仍未覆盖**：返回 `-1`（安全兜底，正常逻辑中已在步骤 3 提前返回）。

> 💡 **与 45 题模板的唯一区别**：45 题保证可达、无需检测 `-1`；本题需要「卡死检测」——当 `i == end` 且 `maxPos <= end` 时，说明存在覆盖缺口，返回 `-1`。这是把跳跃游戏从「保证可达」推广到「可能不可达」时必须加的一行。

### 2.4 示例演算

以示例 3（`n=5, ranges=[1,2,1,0,2,1]`）为例，预处理后 `reach = [3, 3, 5, 3, 5, 5]`，贪心执行过程如下：

![示例演算：两步贪心覆盖 [0,5]](../images/1326_example_walkthrough.svg)

| 阶段 | 水龙头 | 灌溉区间 | 贪心动作 |
|------|--------|----------|----------|
| `i=0` | tap 1（r=2） | `[0, 3]` | `end=0`→开第 1 个，`end` 扩到 `3` |
| `i=1,2` | — | — | 在 `[0,3]` 内扫描，`i=2` 时发现 `reach[2]=5`，`maxPos→5` |
| `i=3` | tap 4（r=2） | `[2, 5]` | `i==end=3`→开第 2 个，`end` 扩到 `5≥n`，返回 `2` |

> 💡 **贪心的选择过程**：第 1 步覆盖 `[0, 3]` 后，在 `[0, 3]` 范围内继续扫描所有水龙头能到达的最远点。`i=2` 时发现 tap 4 能覆盖到 `5`（`reach[2]=5`），于是 `maxPos` 更新为 `5`。当 `i` 走到 `end=3` 时，开第 2 个水龙头（选 `maxPos` 对应的 tap 4），`end` 一步到位扩到 `5`。**两步搞定，且每步都选了能跳最远的那个**。

> ⚠️ **`maxPos` 不是马上用的**：`i=2` 发现 `maxPos=5` 后并没有立刻开龙头，而是等到 `i=3==end` 才开。这是跳跃游戏贪心的精髓——**在当前覆盖范围内先全部扫一遍，再选最远的那个跳**。提前跳反而可能不是最优。

## 3. 参考代码

### C++

```cpp
// 灌溉花园的最少水龙头数目.cpp —— 跳跃游戏贪心 O(n)
// 编译: g++ -O2 -std=c++17 灌溉花园的最少水龙头数目.cpp -o min_taps
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minTaps(int n, vector<int>& ranges) {
        // ① 预处理：水龙头 → reach[] 跳跃数组
        vector<int> reach(n + 1, 0);
        for (int i = 0; i <= n; ++i) {
            int left  = max(0, i - ranges[i]);
            int right = min(n, i + ranges[i]);
            reach[left] = max(reach[left], right);
        }

        // ② 贪心：跳跃游戏 II 模板 + 卡死检测
        int steps = 0;    // 已开水龙头数
        int end = 0;      // 当前这步覆盖到的右边界
        int maxPos = 0;   // [0, end] 内能到达的最远点

        for (int i = 0; i < n; ++i) {
            maxPos = max(maxPos, reach[i]);
            if (i == end) {                   // 当前覆盖范围已扫完
                if (maxPos <= end) return -1; // 卡死：无法继续扩展
                steps++;                      // 开一个水龙头
                end = maxPos;                 // 扩展边界
                if (end >= n) return steps;   // 全覆盖，提前返回
            }
        }
        return -1;                            // 循环结束仍未覆盖
    }
};
```

### Python

```python
class Solution:
    def minTaps(self, n: int, ranges: list[int]) -> int:
        # ① 预处理：水龙头 → reach[] 跳跃数组
        reach = [0] * (n + 1)
        for i, r in enumerate(ranges):
            left  = max(0, i - r)
            right = min(n, i + r)
            reach[left] = max(reach[left], right)

        # ② 贪心：跳跃游戏 II 模板 + 卡死检测
        steps = 0
        end = 0
        max_pos = 0

        for i in range(n):
            max_pos = max(max_pos, reach[i])
            if i == end:                       # 当前覆盖范围已扫完
                if max_pos <= end:             # 卡死：无法继续扩展
                    return -1
                steps += 1                     # 开一个水龙头
                end = max_pos                  # 扩展边界
                if end >= n:                   # 全覆盖，提前返回
                    return steps
        return -1                              # 循环结束仍未覆盖
```

> 💡 两版等价，核心只有三行：**预处理 `reach[left] = max(·, right)`** + **`i == end` 时开龙头 `steps++`** + **`maxPos <= end` 时返回 `-1`**。预处理把异构的区间信息压缩为统一的跳跃数组，之后完全是 45 题的模板。

## 4. 复杂度分析

| 维度 | 贪心（推荐） | 动态规划（暴力） |
|------|-------------|-----------------|
| 时间复杂度 | $O(n)$ | $O(n^2)$ |
| 空间复杂度 | $O(n)$（`reach` 数组） | $O(n)$（`dp` 数组） |
| 实现简洁度 | ★★★★★ 预处理 + 一趟贪心 | ★★★ 双重枚举 |

> ⚠️ **时间说明**：预处理遍历 `n + 1` 个水龙头，$O(n)$；贪心循环遍历 `reach[0..n-1]`，$O(n)$。总计 $O(n)$。`ranges[i] <= 100` 的约束对贪心解法无影响（只是保证区间不会太长），但对 DP 的常数因子有帮助。

> 💡 **空间说明**：`reach` 数组长度 `n + 1`，$O(n)$。若极致优化空间，可预处理时原地改写 `ranges` 为 `reach`（因预处理后 `ranges` 不再使用），但会破坏输入、可读性差，面试中不推荐。

## 5. 扩展：动态规划解法

若面试官要求给出 DP 解法作为对比，或贪心正确性难以当场证明时，DP 是稳妥的保底方案。

设 `dp[j]` = 覆盖 `[0, j]` 所需的最少水龙头数。预处理 `reach[]` 后：

$$\text{dp}[j] = \min_{\text{reach}[k] \geq j,\; k < j} \big(\text{dp}[k] + 1\big)$$

即：枚举所有能一步跳到 `j` 的左端点 `k`，取最小值。

```python
class Solution:
    def minTaps(self, n: int, ranges: list[int]) -> int:
        reach = [0] * (n + 1)
        for i, r in enumerate(ranges):
            left  = max(0, i - r)
            right = min(n, i + r)
            reach[left] = max(reach[left], right)

        dp = [float('inf')] * (n + 1)
        dp[0] = 0
        for j in range(1, n + 1):
            for k in range(j):
                if reach[k] >= j and dp[k] != float('inf'):
                    dp[j] = min(dp[j], dp[k] + 1)
        return dp[n] if dp[n] != float('inf') else -1
```

- 时间 $O(n^2)$，空间 $O(n)$；
- 正确性直观（经典区间覆盖 DP），但 `n = 10^4` 时 $10^8$ 次操作，效率远不如贪心。

> 💡 **DP → 贪心的优化路径**：DP 的内层 `min` 实际上在找「能跳到 `j` 的最左 `k` 中 `dp[k]` 最小的那个」。而贪心观察发现：**不需要对每个 `j` 单独求最优前驱**，只需维护一个全局的「当前步数下能到达的最远边界」，到边界就 +1 步。这把 $O(n^2)$ 的逐点决策压缩为 $O(n)$ 的边界推进——与 [45. 跳跃游戏 II](../0001-0100/45_跳跃游戏%20II.md) 中「DP $O(n^2)$ → 贪心 $O(n)$」的优化完全同构。

## 6. 面试要点

1. **如何想到把水龙头转换为跳跃游戏？**

   > 水龙头 `i` 灌溉 `[i−r, i+r]`，把左端点 `max(0, i−r)` 看作「起跳点」、右端点 `min(n, i+r)` 看作「落点」，就是「从 `left` 可一步跳到 `right`」。多个水龙头有相同左端点时，只保留跳得最远的（`reach[left] = max(·, right)`），这步「支配消除」是贪心的关键——被支配的水龙头不可能出现在最优解中。

2. **为什么贪心一定能得到最优解？**

   > 贪心策略是「在当前覆盖范围 `[0, end]` 内，选能跳到最远的水龙头」。用交换论证：设最优解在某步选了跳到 `r'` 的水龙头而非跳到 `maxPos > r'` 的水龙头，那么把前者换成后者后，覆盖范围只会更大或相等，后续步骤不会变多。因此贪心选择不劣于最优解。这与 [45. 跳跃游戏 II](../0001-0100/45_跳跃游戏%20II.md) 的正确性证明完全一致。

3. **什么时候返回 -1？如何检测？**

   > 当 `i == end`（当前覆盖范围已全部扫完）且 `maxPos <= end`（没有任何水龙头能继续向右扩展）时，说明 `[end, ...]` 这段存在覆盖缺口，返回 `-1`。这对应示例 2 中所有 `ranges[i] = 0` 的情况——每个水龙头只浇自己那一个点，`reach[0] = 0`，第一次 `i == end` 就卡死。45 题不需要这个检测因为题目保证可达，本题不保证。

4. **为什么循环到 `n - 1` 而不是 `n`？**

   > 位置 `n` 是花园右端点，到达即意味着全覆盖。一旦 `end >= n` 就提前返回 `steps`，所以循环只需到 `n - 1`。即使 `reach[n - 1]` 只能跳到 `n - 1`（无法扩展），`i == end` 时也会触发卡死检测返回 `-1`。遍历到 `n` 是多余的——`n` 已经是终点，不需要从终点再跳。

5. **本题和经典的「区间覆盖」问题（如 [435. 无重叠区间](../0401-0500/435_无重叠区间.md)）有何区别？**

   > 435 是「**选最多不重叠区间**」（活动选择型），按右端点排序、贪心选不重叠。1326 是「**用最少区间覆盖 `[0, n]`**」（覆盖型），区间可重叠、要无缝拼接。覆盖型用跳跃游戏贪心（维护最远边界、到边界就 +1 步），活动选择型用右端点排序贪心。两者是不同的贪心范式，切勿混淆。同类的覆盖型问题还有 [1024. 视频拼接](https://leetcode.cn/problems/video-stitching/)（几乎与 1326 完全相同）。

> 💡 **一句话总结**：1326 的灵魂是「**区间覆盖 = 跳跃游戏 II 换皮**」——预处理把水龙头灌溉区间转为 `reach[]` 跳跃数组，之后套 45 题贪心模板维护 `end / maxPos / steps`，到边界就 +1 步、卡死就返回 `-1`，$O(n)$ 一趟搞定。识别出「区间覆盖 → 跳跃游戏」的归约，是本题最核心的洞察。
