# LeetCode 检查数组是否存在有效划分 题解

## 1. 题目概述

- **标题 / 题号**：检查数组是否存在有效划分（#2369，medium）
- **链接**：https://leetcode.cn/problems/check-if-there-is-a-valid-partition-for-the-array/
- **难度**：中等
- **标签**：动态规划、数组

**题意**：给你一个下标从 **0** 开始的整数数组 `nums`，必须将数组划分为一个或多个 **连续** 子数组。若每个子数组都满足下述条件 **之一**，则称为一种 **有效** 划分：

1. 子数组 **恰** 由 `2` 个相等元素组成，例如 `[2,2]`；
2. 子数组 **恰** 由 `3` 个相等元素组成，例如 `[4,4,4]`；
3. 子数组 **恰** 由 `3` 个连续递增元素组成，且相邻元素差值为 `1`，例如 `[3,4,5]`（`[1,3,5]` 不符合）。

数组**至少存在一种**有效划分返回 `true`，否则返回 `false`。

**示例 1**：

```text
输入：nums = [4,4,4,5,6]
输出：true
解释：划分为 [4,4] 和 [4,5,6]。
  [4,4]：2 个相等（条件①）
  [4,5,6]：3 连续递增差 1（条件③）
```

**示例 2**：

```text
输入：nums = [1,1,1,2]
输出：false
解释：无论怎么切都不满足——
  [1,1][1,2]：[1,2] 不等也不是 3 元段；
  [1,1,1][2]：剩 [2] 长度 1，无法成段；
  [1,1,1,2]：长度 4，单段也不合法。
```

**约束**：

- $2 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums[i]} \le 10^6$

> 💡 **关键不变式**：合法子段长度**只有 2 或 3** 两种。这把「划分点」从连续任意位置收缩到「每隔 2 或 3」——前缀 `i` 的可行性只依赖前缀 `i−2` 与 `i−3`，是一个**窗口固定为 2/3 的前缀 DP**，与 [139. 单词拆分](https://leetcode.cn/problems/word-break/) 的「字典词长有限」同构。

## 2. 解题思路

### 2.1 暴力递归

最直白的做法是**忠实模拟「切分」**：从左到右枚举每一段的长度（只能是 2 或 3），切下一段合法就递归剩余后缀，任一路径走通即返回 `true`。

```text
dfs(i):  从下标 i 起的后缀能否有效划分
  若 i == n: 返回 true
  若 i+2 <= n 且 nums[i]==nums[i+1]      且 dfs(i+2): 返回 true   // 条件①
  若 i+3 <= n 且 nums[i]==nums[i+1]==nums[i+2] 且 dfs(i+3): 返回 true   // 条件②
  若 i+3 <= n 且 nums[i]+1==nums[i+1] 且 nums[i+1]+1==nums[i+2] 且 dfs(i+3): 返回 true  // 条件③
  返回 false
```

正确性没问题，但同一后缀 `dfs(i)` 会被不同切分路径反复调用，最坏 $O(2^n)$ 指数级，$n=10^5$ 必然超时。

> ⚠️ 真正该问的不是「这一刀切在哪」，而是「前 `i` 个元素整体能否有效划分」。后者只取决于更短前缀的答案——这正是**前缀可行性 DP** 的契机。

### 2.2 核心观察：前缀可行性 DP（只回看 2 或 3 格）

![核心观察：三类合法子段 + 前缀可行性 DP，只回看 dp[i−2]/dp[i−3]](../images/valid_partition_concept.svg)

把「划分」重新表述为**前缀可行性**：令 `dp[i]` 表示**前 `i` 个元素（`nums[0..i)`）能否被有效划分**。由于末段长度只能是 2 或 3，`dp[i]` 只可能由下面三类转移之一推得：

$$
\text{dp}[i] =
\big(\text{dp}[i-2] \wedge \text{①}\big)
\;\lor\;
\big(\text{dp}[i-3] \wedge \text{②}\big)
\;\lor\;
\big(\text{dp}[i-3] \wedge \text{③}\big)
$$

其中 ①②③ 即对应末段（`nums[i-2..i)` 或 `nums[i-3..i)`）是否满足三类条件。基准 $\text{dp}[0] = \text{true}$（空前缀视为已划分），答案为 $\text{dp}[n]$。

> 💡 **为什么不回看 `dp[i-1]`？** 合法子段最短为 2，故长度 1 的末段永远非法——`dp[i-1]` 与 `dp[i]` 之间无合法转移。图中把 `dp[i-1]` 标灰，正是「窗口固定 2/3」的直观体现，与 [91. 解码方法](https://leetcode.cn/problems/decode-ways/)「末 1/2 位决定 `dp[i]`」同构（本题末 2/3 位）。

> ⚠️ 三类条件要在**同一段**内满足，不是跨段。如末 3 元素 `[4,4,5]`：②要三相等（不满足）、③要连续递增（`4,4,5` 不单调递增，不满足）——两类都落空，`dp[i]` 只能由 `dp[i-2]` 那条路（末 2 元素 `[4,5]`，但也不等）救场，救不了就为 `false`。

### 2.3 算法流程图

![算法流程：逐位推导 dp[i]，命中三类合法子段之一且前缀可行则 true](../images/valid_partition_algorithm_flow.svg)

主循环 `i` 从 `1` 到 `n`，每步检查末 2/3 元素是否构成三类合法子段之一、且对应前缀可行；命中置 `dp[i]=true`，否则 `false`。每步转移 $O(1)$，跑完返回 `dp[n]`。

### 2.4 示例演算

![示例演算：nums=[4,4,4,5,6] 逐位填 dp 并回溯划分](../images/valid_partition_example_walkthrough.svg)

以示例 1 `nums = [4,4,4,5,6]` 逐步填表（下标 `i` 为前缀长度）：

| i | 末段子段 | 三类检查 | dp[i] |
|---|----------|----------|-------|
| 0 | —（空前缀） | 基准 | T |
| 1 | — | i<2，无法成段 | F |
| 2 | `[4,4]` | ①4=4 ✓ ∧ dp[0]=T ✓ | **T** |
| 3 | `[4,4,4]` | ②4=4=4 ✓ ∧ dp[0]=T ✓（①虽 4=4 但 dp[1]=F） | **T** |
| 4 | `[4,5]` / `[4,4,5]` | ①4≠5 ✗；②4≠5 ✗；③4,4,5 不连续 ✗ | F |
| 5 | `[4,5,6]` | ③4→5→6 连续 ✓ ∧ dp[2]=T ✓ | **T** |

回溯路径：`dp[5]` 经 ③ 来自 `dp[2]`，`dp[2]` 经 ① 来自 `dp[0]` → 划分 `[4,4] + [4,5,6]` ✓。

> 💡 注意 `i=4` 一度「断档」（dp 为 F），但整体仍返回 `true`——因为 `i=5` 经 ③ 接力到 `dp[2]` 这条「存活的更早前缀」。这正是 DP 相比贪心的优势：**不要求每个前缀都可行，只要存在一条可行链**。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    bool validPartition(vector<int>& nums) {
        int n = nums.size();
        vector<char> dp(n + 1, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; ++i) {
            if (i >= 2 && nums[i - 2] == nums[i - 1] && dp[i - 2])
                dp[i] = 1;
            else if (i >= 3 && nums[i - 3] == nums[i - 2] && nums[i - 2] == nums[i - 1] && dp[i - 3])
                dp[i] = 1;
            else if (i >= 3 && nums[i - 3] + 1 == nums[i - 2] && nums[i - 2] + 1 == nums[i - 1] && dp[i - 3])
                dp[i] = 1;
        }
        return dp[n];
    }
};
```

> 💡 `dp` 用 `vector<char>` 而非 `vector<bool>`，避免 `vector<bool>` 的位压缩代理带来的潜在开销与语义陷阱。三个 `else if` 用短路顺序：一旦命中即跳过后续检查，每步最多 3 次比较。

> 💡 三类检查可抽成内联小函数或预计算的「`ok2[i]` / `ok3[i]`」布尔表，让主循环只剩 `dp[i] = (dp[i-2]&&ok2[i]) || (dp[i-3]&&ok3[i])`。但本题直接展开更直观、常数更小，无需过度抽象。

### Python

```python
class Solution:
    def validPartition(self, nums: List[int]) -> bool:
        n = len(nums)
        dp = [False] * (n + 1)
        dp[0] = True
        for i in range(1, n + 1):
            if i >= 2 and nums[i - 2] == nums[i - 1] and dp[i - 2]:
                dp[i] = True
            elif i >= 3 and nums[i - 3] == nums[i - 2] == nums[i - 1] and dp[i - 3]:
                dp[i] = True
            elif i >= 3 and nums[i - 3] + 1 == nums[i - 2] and nums[i - 2] + 1 == nums[i - 1] and dp[i - 3]:
                dp[i] = True
        return dp[n]
```

> 💡 Python 的链式比较 `a == b == c` 等价于 `a == b and b == c`，写法简洁。若追求极致常数，可用 `nums[i-3:i]` 切片配合 `len(set)==1`（条件②）与 `list(range(...))` 比对（条件③），但切片会引入 $O(k)$ 拷贝，本题 $k\le3$ 影响可忽略，仍推荐展开写法。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n)$ | 主循环 $n$ 步，每步至多 3 次比较 + 2 次布尔查表，转移 $O(1)$ |
| **空间复杂度** | $O(n)$ | `dp` 数组长 $n+1$ |
| 对照：暴力递归 | $O(2^n)$ / $O(n)$ | 同一后缀反复求解，$n=10^5$ 必超时 |
| 对照：记忆化 DFS | $O(n)$ / $O(n)$ | 递归 + `memo`，与递推等价但栈深 $n$ 有溢出风险 |
| 对照：滚动数组 | $O(n)$ / $O(1)$ | 只保留最近 3 个 dp 值，见第 5 节 |

> 💡 $n$ 达 $10^5$，$O(n)$ 时间充足；空间 $O(n)$ 已可接受，但可进一步压到 $O(1)$（见下节），适合对内存敏感的嵌入式/竞赛场景。

## 5. 扩展：滚动数组 O(1) 空间 + 记忆化 DFS

### 5.1 滚动数组（O(1) 空间）

`dp[i]` 只依赖 `dp[i-2]` 与 `dp[i-3]`（**不依赖 `dp[i-1]`**），故只需滚动保留最近 3 个值。设处理 `i` 时 `(r, q, p) = (dp[i-3], dp[i-2], dp[i-1])`，算出 `cur = dp[i]` 后整体左移 `(r,q,p) ← (q,p,cur)`：

```cpp
class Solution {
public:
    bool validPartition(vector<int>& nums) {
        int n = nums.size();
        bool r = false, q = false, p = true;  // dp[-2], dp[-1], dp[0]
        for (int i = 1; i <= n; ++i) {
            bool cur = false;
            if (i >= 2 && nums[i - 2] == nums[i - 1] && q) cur = true;
            else if (i >= 3 && nums[i - 3] == nums[i - 2] && nums[i - 2] == nums[i - 1] && r) cur = true;
            else if (i >= 3 && nums[i - 3] + 1 == nums[i - 2] && nums[i - 2] + 1 == nums[i - 1] && r) cur = true;
            r = q; q = p; p = cur;
        }
        return p;  // 处理完 i=n 后 p 即 dp[n]
    }
};
```

> ⚠️ 初始 `p=true`（`dp[0]`），`r=q=false` 是 `dp[-2]/dp[-1]` 的占位——它们只在 `i>=3` 分支被读取，而那时已通过两轮左移把 `dp[0]` 搬进 `r`，占位值不会被用到。这是「窗口 DP」滚动时的常见陷阱：**初始垃圾值必须被后续左移覆盖到正确位置后才进入读取**。

### 5.2 记忆化 DFS（自顶向下）

把 2.1 的递归加 `memo`，即得自顶向下版，与递推等价：

```python
def validPartition(self, nums: List[int]) -> bool:
    n = len(nums)
    @lru_cache(None)
    def dfs(i):               # 下标 i 起的后缀能否划分
        if i == n:
            return True
        if i + 2 <= n and nums[i] == nums[i + 1] and dfs(i + 2):
            return True
        if i + 3 <= n and nums[i] == nums[i + 1] == nums[i + 2] and dfs(i + 3):
            return True
        if i + 3 <= n and nums[i] + 1 == nums[i + 1] and nums[i + 1] + 1 == nums[i + 2] and dfs(i + 3):
            return True
        return False
    return dfs(0)
```

> 💡 自顶向下语义更贴近「切分」直觉，但 Python 默认递归上限 1000，$n=10^5$ 会触发 `RecursionError`，需 `sys.setrecursionlimit`。C++ 无显式上限但有栈溢出风险。故 $n$ 大时**递推（自底向上）是更稳妥的首选**。

## 6. 面试要点

1. **`dp[i]` 的含义是什么？为什么是「前缀可行性」而非「切分点」？**

   > `dp[i]` = 前 `i` 个元素能否有效划分。把视角从「在何处下刀」转到「前缀整体是否可行」，天然把重复子问题暴露出来：`dp[i]` 只依赖更短前缀的答案。这正是 [139. 单词拆分](https://leetcode.cn/problems/word-break/) 的同款骨架——「字典词」换成「三类合法子段」，词长有限（2 或 3）让窗口固定。

2. **为什么只回看 `dp[i-2]` 和 `dp[i-3]`，不回看 `dp[i-1]`？**

   > 合法子段最短长度为 2，末段长度 1 永远非法，故 `dp[i-1]` 与 `dp[i]` 间无合法转移。这是「窗口固定 2/3」的根源，也是滚动数组只需 3 个变量的依据。对比 [91. 解码方法](https://leetcode.cn/problems/decode-ways/) 末 1/2 位决定 `dp[i]`——窗口形状由「合法段长集合」决定。

3. **三类条件为什么要用 `else if`（短路）？能否并行？**

   > 同一末段可能同时满足多类（如 `[3,3,3]` 既满足②也... 不，③要递增故②③互斥；`[3,4]` 只能①）。三类对**同一末段**判别，命中任一即可置 `dp[i]=true`，用 `else if` 短路避免无谓比较。逻辑上是「或」关系，顺序无关正确性，只影响常数。

4. **怎么从 `dp` 表回溯出具体划分方案？**

   > `dp` 只记了可行性。要还原方案，命中时记录「由哪类、来自哪个前缀」：若经①则前缀是 `i-2`，经②③则 `i-3`。从 `dp[n]` 反向跳到 `dp[i-k]` 即得各段边界。本题只问真假，无需回溯；若题目改为「输出任一有效划分」，加一个 `from[i]` 指针表即可。

5. **滚动数组的初始垃圾值会不会出错？**

   > 不会，前提是**垃圾值在被读取前已被正确值覆盖**。`dp[-2]/dp[-1]` 仅在 `i>=3` 分支读取 `r/q`，而处理 `i=1,2` 两轮后 `dp[0]=true` 已左移进 `r`（`i=3` 时 `r` 恰为 `dp[0]`）。若窗口更复杂（如依赖 `dp[i-5]`），需保证前若干轮把所有真实基准搬到对应槽位——这是滚动 DP 的通用校验点。

> 💡 **一句话总结**：2369 =「前缀可行性 DP」——`dp[i] = (dp[i−2]∧①) ∨ (dp[i−3]∧②) ∨ (dp[i−3]∧③)`，`dp[0]=true`，答案 `dp[n]`。合法子段长度只有 2/3，故窗口固定、转移 $O(1)$、整体 $O(n)$，滚动可压到 $O(1)$ 空间。与 139 单词拆分、91 解码方法同属「末段有限长度的前缀 DP」家族。
