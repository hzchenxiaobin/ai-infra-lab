# LeetCode 寻找旋转排序数组中的最小值II 题解

## 1. 题目概述

- **标题 / 题号**：寻找旋转排序数组中的最小值 II（#154，hard）
- **链接**：https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array-ii/
- **难度**：困难
- **标签**：数组、二分查找

**题意**：已知一个长度为 `n` 的数组 `nums`，它**预先按升序排列**（**可能包含重复值**），并在**下标 `k`（`0 <= k < n`）处旋转**了一次，变为：

$$[\text{nums}[k],\ \text{nums}[k+1],\ \ldots,\ \text{nums}[n-1],\ \text{nums}[0],\ \text{nums}[1],\ \ldots,\ \text{nums}[k-1]]$$

请找出并返回数组中的**最小元素**。

> ⚠️ **与 [153 题](153_寻找旋转排序数组中的最小值.md) 的唯一区别**：153 题保证元素**互不相同**，本题允许**重复值**。重复值会让二分判定出现一个「无法判断断点在哪半」的歧义情形——这是本题（困难）的核心难点，也是由「两路二分」升级为「三路二分」的根因。

**示例 1**：

```text
输入：nums = [1,3,5]
输出：1
解释：k=0（未旋转），首元素即最小值。
```

**示例 2**：

```text
输入：nums = [2,2,2,0,2]
输出：0
解释：原数组 [0,2,2,2,2] 在 k=3 处旋转，最小值 0 位于下标 3。
```

**示例 3**：

```text
输入：nums = [2,0,2,2,2]
输出：0
解释：原数组 [0,2,2,2,2] 在 k=1 处旋转，最小值 0 位于下标 1。
```

> 💡 对比示例 2 与示例 3：两者都含重复 `2`，且在中点处 `nums[mid] == nums[right] == 2`，但最小值 `0` 一个在右半、一个在左半——这正是「歧义」的典型写照。

**约束**：

- $n == \text{nums.length}$
- $1 \le n \le 5000$
- $-5000 \le \text{nums}[i] \le 5000$
- `nums` 可能含重复值
- `nums` 原为升序并旋转过一次（`k` 可为 `0`，即未旋转）

> ⚠️ 注意题目**不要求** $O(\log n)$——这其实是一个暗示：含重复值时，最坏情况无法做到对数，线性是信息论下界。但平均情况下二分仍远快于线性扫描，故仍以二分为正解。

## 2. 解题思路

### 2.1 暴力思路：线性扫描

扫一遍取最小值，时间 $O(n)$、空间 $O(1)$。简单正确，且本题本就允许 $O(n)$。但这样完全放弃了「旋转后仍大体有序」的结构，面试中期望你能讲出二分思路及其退化原因。问题在于：**能否在 153 题的二分骨架上处理重复值？**

### 2.2 核心观察：重复值导致的歧义

![含重复值时 nums[mid]==nums[right] 无法判断断点在哪半](../images/findmin_ii_ambiguous.svg)

153 题的二分骨架是：每轮取 `mid`，与**右端点** `nums[right]` 比较——`<` 则右半升序、最小值在左含 `mid`；`>` 则右半有下坠、最小值在右不含 `mid`。值互异时这两路必有一个成立，每轮砍半。

但本题允许重复值，会出现第三种情形：**`nums[mid] == nums[right]`**。此时单凭「相等」无法判断断点在哪半：

- `[2,2,2,0,2]`（`k=3`）：`mid=2`、`right=4`，`nums[mid]==nums[right]==2`，但最小值 `0` 在 `(mid, right]` 内（右半）；
- `[2,0,2,2,2]`（`k=1`）：`mid=2`、`right=4`，同样 `nums[mid]==nums[right]==2`，但最小值 `0` 在 `[left, mid)` 内（左半）。

两例的 `mid`、`right` 取值完全相同，断点却左右皆可——**信息不足以二分砍半**。

> 💡 **对策（保守退缩）**：既然 `nums[right]` 与 `nums[mid]` 相等，`nums[right]` 就**不可能是唯一最小值**（`mid` 处有一个等值的候选）。于是安全地丢弃 `nums[right]`：执行 `right -= 1`，缩小区间一个位置后重新二分。每轮只退一步，逐步消解歧义，直到 `<` / `>` 关系重新显现。

> ⚠️ **为什么退缩 `right` 而不是 `left`？** 153 题的整套判定都基于「与右端点比较」，退缩 `right` 能保持比较基准的语义连贯（下一轮仍是比较 `nums[mid]` 与新的 `nums[right]`）。若改为退缩 `left`，则需切换到「与左端点比较」的另一套模板，心智负担更大。当然，理论上退缩任一端都正确——只要不变量「最小值仍在 `[left, right]` 内」不被破坏。下文扩展节会给出双端退缩的变体。

### 2.3 算法流程图

![三路二分流程](../images/findmin_ii_algorithm_flow.svg)

把 153 题的「两路判定」升级为**三路**：

| 条件 | 含义 | 动作 |
|------|------|------|
| `nums[mid] < nums[right]` | 右半 `[mid..right]` 升序，断点不在右半 | `right = mid`（min 在左含 `mid`） |
| `nums[mid] > nums[right]` | 右半存在「断点下坠」，min 在右不含 `mid` | `left = mid + 1` |
| `nums[mid] == nums[right]` | **歧义**，无法判断断点在哪半 | `right -= 1`（保守退缩，丢弃非唯一候选） |

循环不变量：**最小值始终落在闭区间 `[left, right]` 内**。前两路每轮砍半；第三路每轮只退一步。当区间收缩到只剩一个元素（`left == right`），它即为答案。

### 2.4 示例演算

以 `nums = [2,2,2,0,2]` 为例（此例刻意触发歧义分支）：

![示例演算](../images/findmin_ii_walkthrough.svg)

| 轮次 | left | right | mid | nums[mid] | nums[right] | 比较 | 动作 |
|------|------|-------|-----|-----------|-------------|------|------|
| 1 | 0 | 4 | 2 | 2 | 2 | $2 = 2$ | right−− → right=3 |
| 2 | 0 | 3 | 1 | 2 | 0 | $2 > 0$ | left = mid+1 = 2 |
| 3 | 2 | 3 | 2 | 2 | 0 | $2 > 0$ | left = mid+1 = 3 |
| 结束 | 3 | 3 | — | — | — | left==right | 返回 nums[3] = 0 |

`nums[3] = 0` 确为最小值 ✓。注意第 1 轮遇 `==` 歧义，**未砍半**，仅 `right−−` 退一步消歧；第 2、3 轮恢复正常二分砍半。这正是本题与 153 题的典型差异——**歧义轮退化为线性步进，非歧义轮仍享二分对数**。

## 3. 参考代码

### C++

```cpp
class Solution {
  public:
    int findMin(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[right]) {
                right = mid;            // 右半升序：min 在左（含 mid）
            } else if (nums[mid] > nums[right]) {
                left = mid + 1;         // 右半有下坠：min 在右（不含 mid）
            } else {
                --right;                // 歧义：丢弃非唯一候选 nums[right]
            }
        }
        return nums[left];
    }
};
```

### Python

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        while left < right:
            mid = (left + right) // 2
            if nums[mid] < nums[right]:
                right = mid             # 右半升序：min 在左（含 mid）
            elif nums[mid] > nums[right]:
                left = mid + 1          # 右半有下坠：min 在右（不含 mid）
            else:
                right -= 1              # 歧义：丢弃非唯一候选 nums[right]
        return nums[left]
```

> 💡 **与 153 题的关系**：把 153 题模板的 `else`（原等价于 `nums[mid] > nums[right]`）拆成 `else if (nums[mid] > nums[right])` 与 `else`（即 `==`）两路，后者新增 `right -= 1` 退缩分支，即得本题解法。**两题共用同一套骨架，仅多一个 `==` 分支**。元素互异时 `==` 分支永不触发，退化为 153 题。

> 💡 未旋转的情况（如 `[1,3,5]`）无需特判：每轮都有 `nums[mid] < nums[right]`，`right` 一路收到 `0`，最终返回 `nums[0]` 即首元素，正确。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度（平均） | $O(\log n)$ | 无歧义时每轮砍半，与 153 题一致 |
| 时间复杂度（最坏） | $O(n)$ | 全相同值（如 `[2,2,2,2,2]`）时每轮都走 `==` 分支 `right−−`，退化为线性 |
| 空间复杂度 | $O(1)$ | 仅 `left`、`right`、`mid` 三指针 |

> 💡 **最坏 $O(n)$ 不可避免**：当所有元素相同时，任何基于比较的算法都无法利用「旋转」结构来砍半——因为每次比较得到的信息量为零（`nums[mid]` 与 `nums[right]` 永远相等，无法分辨断点）。线性扫描 $O(n)$ 是此情形的信息论下界。但此类输入极罕见，实际评测中二分法远快于线性扫描。

## 5. 扩展：双端退缩与退缩 left 的变体

### 5.1 双端同时退缩

歧义时若 `nums[left] == nums[mid] == nums[right]`，可同时收缩两端——`left++; right--`，跳过两端各一个重复值，在两端都堆满相同值时收敛快一倍：

```cpp
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] < nums[right]) {
        right = mid;
    } else if (nums[mid] > nums[right]) {
        left = mid + 1;
    } else if (nums[left] < nums[mid]) {   // left < mid == right：左半升序，min 在 left
        return nums[left];                  // left 即最小值，提前返回
    } else {                                // left == mid == right：双端退缩
        left++;
        right--;
    }
}
return nums[left];
```

> ⚠️ 双端退缩的逻辑更繁琐、边界更多（需判 `nums[left] < nums[mid]` 提前返回），面试中**推荐单端 `right--` 版**——简洁不易错，最坏复杂度相同（都是 $O(n)$），常数差异在 $n \le 5000$ 下可忽略。

### 5.2 与 81 题（搜索旋转排序数组 II）的对照

[81 题](../0001-0100/81_搜索旋转排序数组II.md)是「含重复值的旋转数组中找 target」，同样有 `nums[left] == nums[mid] == nums[right]` 的歧义，对策是 `left++` 退缩。两题的歧义处理思路完全同源，区别仅在于：

- **81 题**比较 `nums[left]` 与 `nums[mid]`（因为要判「哪半有序」以定位 target），退缩 `left`；
- **154 题**比较 `nums[mid]` 与 `nums[right]`（因为只找最小值，无需判有序半段），退缩 `right`。

掌握其中一题的「三路判定 + 退缩」模板，另一题只需换比较基准与退缩方向。

## 6. 面试要点

1. **与 153 题的核心区别是什么？**
   - 153 题值互异，`nums[mid]` 与 `nums[right]` 比较必能定 `<` 或 `>`，两路砍半；本题允许重复，会出现 `nums[mid] == nums[right]` 的歧义——断点左/右皆可能，需新增第三路 `right--` 保守退缩。最坏退化为 $O(n)$。

2. **为什么 `right--` 是安全的？不会丢弃最小值吗？**
   - 安全。进入 `==` 分支时 `nums[mid] == nums[right]`，即便 `nums[right]` 是最小值，`mid` 处也有一个**等值**候选仍在区间内（`mid < right`，`mid` 未被排除）。丢弃 `nums[right]` 不丢失「最小值」这个**数值**，只丢弃一个冗余位置。不变量「最小值仍在 `[left, right]` 内」成立。

3. **为什么最坏是 $O(n)$？能避免吗？**
   - 全相同值时每轮都走 `==` 分支，`right--` 只退一步不砍半，$n$ 轮才结束。这是信息论下界——所有元素相同意味着每次比较零信息量，任何算法都无法更快。实际中此类输入极罕见。

4. **为什么仍用 `nums[mid]` 与 `nums[right]` 比较，不和 `nums[left]` 比？**
   - 与右端点比较时，`nums[mid] < nums[right]` 直接等价于「右半无下坠」，最小值在左含 `mid`，判定无歧义；与左端点比较时 `nums[mid] > nums[left]` 存在歧义（整体有序 vs 旋转），需额外判断。右端点模板分支最少，且 153 题已用此模板，本题仅在其上加 `==` 分支，迁移成本最低。

5. **`while` 用 `left < right` 还是 `left <= right`？**
   - 用 `left < right`。当 `left == right` 时区间只剩一个元素，由不变量保证它就是最小值，直接返回。用 `left <= right` 反而要在循环内处理 `left == right` 的退出，并担心 `right--` 在 `left == right` 时越界。**「区间型二分」统一用 `left < right`**，退出后 `left` 即答案。
