# LeetCode 提取至多K个元素的最大总和 题解

## 1. 题目概述

- **标题 / 题号**：提取至多K个元素的最大总和（#3462，medium）
- **链接**：https://leetcode.cn/problems/maximum-sum-with-at-most-k-elements/
- **难度**：中等
- **标签**：贪心、数组、矩阵、排序、堆（优先队列）

**题意**：给你一个大小为 `n x m` 的二维矩阵 `grid`，以及一个长度为 `n` 的整数数组 `limits`，和一个整数 `k`。你的目标是从矩阵 `grid` 中提取出**至多 `k` 个元素**，并计算这些元素的**最大总和**，提取时需满足以下限制：

- 从 `grid` 的第 `i` 行提取的元素数量不超过 `limits[i]`。

返回最大总和。

**示例 1**：

```text
输入：grid = [[1,2],[3,4]], limits = [1,2], k = 2
输出：7
解释：
  从第 2 行提取至多 2 个元素，取出 4 和 3。
  至多提取 2 个元素时的最大总和 4 + 3 = 7。
```

**示例 2**：

```text
输入：grid = [[5,3,7],[8,2,6]], limits = [2,2], k = 3
输出：21
解释：
  从第 1 行提取至多 2 个元素，取出 7。
  从第 2 行提取至多 2 个元素，取出 8 和 6。
  至多提取 3 个元素时的最大总和 7 + 8 + 6 = 21。
```

**约束**：

- `n == grid.length == limits.length`
- `m == grid[i].length`
- `1 <= n, m <= 500`
- `0 <= grid[i][j] <= 10^5`
- `0 <= limits[i] <= m`
- `0 <= k <= min(n * m, sum(limits))`

## 2. 解题思路

### 2.1 暴力思路

最直接的想法是**组合枚举**：对每一行列举所有大小不超过 `limits[i]` 的元素子集，再在行间组合出总数不超过 `k` 的全局方案。子集数量是指数级的（单行最多 $2^m$ 种），`n, m` 到 500 时完全不可行。

退一步的"朴素贪心"是**忽略行配额，直接取全局前 `k` 大**。这是错的——反例：`grid = [[10,9],[1,1]]`，`limits = [1,2]`，`k = 2`。全局前 2 大是 `10 + 9 = 19`，但第 0 行只许取 1 个，正确答案是 `10 + 1 = 11`。**行配额会把同一行的"扎堆大数"拦腰截断**，这正是本题要处理的核心矛盾。

还有一种正确但不够精的写法：把全部 `n·m` 个元素塞进一个大顶堆，每次弹出全局最大者，若其所在行配额已满就**丢弃**。它是对的（见 2.2 的交换论证），但要为所有被丢弃的元素付堆操作代价，最坏 $O(nm \log (nm))$，且完全没利用「每行只需关心前 `limits[i]` 大」这一结构。

### 2.2 核心观察：两步贪心——行内裁剪 + 跨行合并

![两步贪心概念：每行截取前 limits[i] 大入候选池，再取池内前 k 大](../images/p3462_two_step_greedy.svg)

整个问题可以拆成两步各自贪心，每步都有干净的证明：

**第一步（行内裁剪）：每行只需考虑前 `limits[i]` 大的元素。**

> 💡 **交换论证**：设某个可行方案从第 `i` 行取了元素 `x`，但同行还有更大的未取元素 `y > x`。把 `x` 换成 `y`：每行取的个数不变（可行性不变），总和变大。因此任意最优解中，第 `i` 行取出的必然是该行**降序排列后的一个前缀**——于是每行贡献给全局的候选只有**前 `limits[i]` 大**这至多 `m` 个数，其余元素可以直接扔掉。

**第二步（跨行合并）：候选池内取前 `k` 大之和。**

把每行留下的候选汇入一个池子（池大小 $S = \sum \text{limits}[i] \le n \cdot m$），问题退化为不带任何约束的「取前 `k` 大」。两个约束条件保证了这就是答案：

1. **元素非负**（`0 <= grid[i][j]`）：多取一个候选不会让总和变小，"至多 `k` 个"等价于"取满 `k` 个"；
2. **`k <= sum(limits)`**（题目显式保证）：池子里的候选永远够取，不存在取不满的情况。

两步合起来：**排序每行取前缀入池 → 池排序取前 `k` 个求和**。时间复杂度 $O(nm\log m + S\log S)$，其中 $S = \sum \text{limits}[i]$；当 `limits` 普遍很小时，池远小于全矩阵，比全量堆的做法省得多。

> ⚠️ **溢出提醒**：`n·m` 最多 $2.5\times10^5$ 个元素，每个最大 $10^5$，总和上界 $2.5\times10^{10}$，超出 `int32` 范围。C++ 必须用 `long long` 累加（Python 天然大数无碍）。

### 2.3 算法流程图

![算法流程：逐行降序排序、截取前 limits[i] 入池、池降序排序、取前 k 个累加](../images/p3462_algorithm_flow.svg)

流程是纯线性的：逐行「排序 → 截取入池」，最后「池排序 → 前 `k` 个求和」。两个排序阶段分别对应 2.2 的两步贪心。

### 2.4 示例演算

以示例 2 走一遍完整流程（`grid = [[5,3,7],[8,2,6]]`，`limits = [2,2]`，`k = 3`）：

```text
第 0 行 [5,3,7] 降序 → [7,5,3]，limits[0]=2 → 取 7、5 入池（3 被裁掉）
第 1 行 [8,2,6] 降序 → [8,6,2]，limits[1]=2 → 取 8、6 入池（2 被裁掉）
候选池 [7,5,8,6] 降序 → [8,7,6,5]，k=3 → 取 8+7+6 = 21 ✓
（被裁掉的 3、2 永远不可能出现在任何最优解里——行内已有足够大的替代者）
```

## 3. 参考代码

### C++

```cpp
class Solution {
  public:
    long long maxSum(vector<vector<int>>& grid, vector<int>& limits, int k) {
        vector<int> pool;
        for (int i = 0; i < (int)grid.size(); i++) {
            auto& row = grid[i];
            sort(row.rbegin(), row.rend());              // 行内降序
            for (int j = 0; j < limits[i]; j++) {
                pool.push_back(row[j]);                  // 只留前 limits[i] 大
            }
        }
        sort(pool.rbegin(), pool.rend());                // 池内降序
        long long ans = 0;
        for (int j = 0; j < k; j++) ans += pool[j];      // 取前 k 大（k <= 池大小）
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, grid: List[List[int]], limits: List[int], k: int) -> int:
        pool = []
        for row, lim in zip(grid, limits):
            row.sort(reverse=True)          # 行内降序
            pool.extend(row[:lim])          # 只留前 lim 大
        pool.sort(reverse=True)             # 池内降序
        return sum(pool[:k])                # 取前 k 大
```

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | O(n·m·log m + S·log S) | 行排序共 $O(nm\log m)$；池排序 $O(S\log S)$，$S=\sum\text{limits}[i]\le nm$。上界粗记为 $O(nm\log (nm))$ |
| 空间复杂度 | O(S) | 候选池最多存 $\sum\text{limits}[i]$ 个元素（行排序若原地做不额外耗空间） |

> 💡 读入矩阵本身就要 $O(nm)$，贪心只在其上叠了一个对数因子的排序开销；$n,m\le500$ 时总计不到 $10^6$ 级别的基本操作，非常宽裕。

## 5. 扩展：堆的多路归并与快速选择

**堆解法（`k` 很小时更优）**：行排序后，每行的候选天然是一段降序序列，可把问题看成 `n` 路归并取前 `k` 个——每行只把**当前头元素**（值, 行号）放进大顶堆，弹一次若该行还有候选就推入下一个。堆中始终至多 `n` 个元素：

```python
class Solution:
    def maxSum(self, grid: List[List[int]], limits: List[int], k: int) -> int:
        rows = [sorted(row, reverse=True)[:lim] for row, lim in zip(grid, limits)]
        heap = [(-r[0], i, 0) for i, r in enumerate(rows) if r]
        heapify(heap)
        ans = 0
        for _ in range(k):
            neg, i, j = heappop(heap)
            ans += -neg
            if j + 1 < len(rows[i]):
                heappush(heap, (-rows[i][j + 1], i, j + 1))
        return ans
```

时间 $O(nm\log m + (n+k)\log n)$：省掉了池排序，`k` 远小于 $S$ 时优势明显（本题 $S \le 2.5\times10^5$，两种写法都轻松通过）。

**快速选择**：最后一步「池内前 `k` 大」不必完整排序——C++ 的 `nth_element` / Python 的 `heapq.nlargest` 都能做到平均 $O(S)$，把总复杂度压到 $O(nm\log m + S)$；行内截取同理可用每行一次 `nth_element`（平均 $O(m)$）替代排序。

**变体思考**：

- 若**元素可能为负**："至多 `k` 个"就不再等价于"取满 `k` 个"，应在取前 `k` 大的过程中**提前停止**（下一个候选为负就不取了）；
- 若允许 `k > sum(limits)`：池子会被取空，答案就是全部候选之和——代码里取 `min(k, len(pool))` 个即可，本题约束已排除该情况。

## 6. 面试要点

1. **为什么每行只需考虑前 `limits[i]` 大的元素？**
   - 交换论证：行内用更大的未取元素替换已取的小元素，每行个数不变（不破坏配额），总和只增不减，故最优解中每行取的必是降序前缀。

2. **"至多 k 个"什么时候可以当成"恰好 k 个"处理？**
   - 需要两个条件：元素非负（多取不亏）且 `k <= sum(limits)`（池子够取）。本题两者都有；若元素可能为负，要在前 `k` 大里跳过负贡献者。

3. **直接取全局前 k 大为什么错？如何构造反例？**
   - 让大数扎堆在同一行且该行配额小：如 `[[10,9],[1,1]]`、`limits=[1,2]`、`k=2`，全局 top-2 是 `19` 但行配额只允许取一个，正确答案 `11`。

4. **为什么必须用 `long long`？**
   - 总和上界 $n \cdot m \cdot \max = 500 \times 500 \times 10^5 = 2.5\times10^{10} > 2^{31}-1 \approx 2.1\times10^9$，`int` 会溢出。

5. **排序解法和堆解法如何取舍？**
   - `k` 接近 $\sum\text{limits}$ 时池排序 $O(S\log S)$ 简单直接；`k` 很小时多路归并堆 $O(nm\log m + k\log n)$ 更省。两者都远好于"全量元素进堆再逐个检查配额"的 $O(nm\log (nm))$ 写法。
