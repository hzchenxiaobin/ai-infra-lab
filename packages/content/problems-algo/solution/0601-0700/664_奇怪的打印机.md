# LeetCode 奇怪的打印机 题解

## 1. 题目概述

- **标题 / 题号**：奇怪的打印机（#664，hard）
- **链接**：https://leetcode.cn/problems/strange-printer/
- **难度**：困难
- **标签**：动态规划、区间 DP、字符串

**题意**：有一台特殊的打印机，它有两个特点：

1. **每次操作只能打印同一种字符**：打印机在每一轮中只能选择一种字符，并在一个连续区间 `[left, right]` 上全部涂成该字符。
2. **新涂的字符会覆盖已有字符**：每一轮可以从任意位置开始、任意位置结束，并覆盖该区间内之前已涂的字符。

给定一个字符串 `s`，返回打印出 `s` 所需的**最少操作次数**。

**示例 1**：

```text
输入：s = "aaabbb"
输出：2
解释：先打印 "aaa"，再在后面打印 "bbb"，共 2 次。
```

**示例 2**：

```text
输入：s = "aba"
输出：2
解释：先打印 "aaa" 覆盖整段，再在中间打印 "b" 覆盖原 a，得到 "aba"。
```

**约束**：

- `1 <= s.length <= 100`
- `s` 由小写英文字母组成

> 💡 本题是**区间 DP 的经典困难题**，与 [516. 最长回文子序列](../0501-0600/516_最长回文子序列.md)、[312. 戳气球](../0301-0400/312_戳气球.md) 同属「`dp[i][j]` 表示子区间最优值」的家族。它的核心难点在于一个反直觉的观察：**两端字符相同时可以让右端「白嫖」一次涂色**——这正是「区间 DP + 同字符合并」的招牌套路，与 [546. 移除盒子](../0501-0600/546_移除盒子.md) 的「同色合并」思想一脉相承。

## 2. 解题思路

### 2.1 暴力思路：枚举每一轮的涂色区间

把问题看作「用若干次区间覆盖操作拼出 `s`」，每次操作选一个区间和一种字符。直接搜索所有操作序列，状态空间随长度指数膨胀，`n=100` 完全不可行，且存在大量重复子问题（同一段子区间被反复求解）。

### 2.2 核心观察：区间 DP + 同字符合并

![核心观察：一轮涂一段同字符可覆盖；s[k]==s[j] 时位置 j 可复用涂 s[k] 的那一轮](../images/strange_printer_concept.svg)

**关键性质**：打印 `s[i..j]` 的最优方案，可以围绕「**右端字符 `s[j]` 由哪一轮负责涂色**」来分治。

**定义**：`dp[i][j]` = 打印子串 `s[i..j]`（闭区间）所需的最少轮数。

**边界**：

```text
dp[i][i] = 1                 # 单字符只需 1 轮
dp[i][j] = 0   (i > j)        # 空段视为 0 轮，便于统一转移
```

**转移**（核心）：

```text
# 情况 A（默认）：给 s[j] 单独开一轮涂色
dp[i][j] = dp[i][j-1] + 1

# 情况 B（合并）：若存在 k ∈ [i, j-1] 使 s[k] == s[j]
#                则涂 s[j] 的那轮可并入「涂 s[k] 的那一轮」
for k in [i, j-1]:
    if s[k] == s[j]:
        dp[i][j] = min(dp[i][j], dp[i][k] + dp[k+1][j-1])
```

**两种转移的直觉**：

| 情况 | DP 来源 | 含义 |
|------|---------|------|
| **默认** | `dp[i][j-1] + 1` | `s[j]` 新开一轮（涂在 `[j,j]` 或延伸），代价 `+1` |
| **合并** | `dp[i][k] + dp[k+1][j-1]`（`s[k]==s[j]`） | 涂 `s[k]` 的那一轮顺带把整段 `[k..j]` 涂成 `s[k]`，位置 `j` 因字符相同而「免费」；中间 `[k+1..j-1]` 之后被各自覆盖 |

![区间 DP 转移：默认 dp[i][j-1]+1 / 合并 dp[i][k]+dp[k+1][j-1]](../images/strange_printer_dp_transition.svg)

> 💡 **为什么「合并」成立？** 涂 `s[k]` 的那一轮原本就要覆盖位置 `k`，把它延伸到覆盖 `[k..j]`（仍涂同一字符 `s[k]=s[j]`）不增加轮数。这一轮先把 `[k..j]` 整段刷成 `s[j]`，随后中间 `[k+1..j-1]` 的不同字符会被各自后续的轮次覆盖——这部分代价正是 `dp[k+1][j-1]`。而左段 `s[i..k]`（含位置 `k`，其那轮顺手涂了 `j`）的代价是 `dp[i][k]`。两者独立可加，故 `dp[i][k] + dp[k+1][j-1]`。

> ⚠️ **为什么枚举所有 `k` 而非只取最近的？** 合并的代价 `dp[i][k] + dp[k+1][j-1]` 随 `k` 变化：`k` 越靠左，左段越长、右段越短；越靠右反之。最优 `k` 不一定是离 `j` 最近的同字符位置，故需在 `[i, j-1]` 内遍历所有 `s[k]==s[j]` 取最小，这也是本题做到 `O(n³)` 的原因。

> 💡 **相邻相同字符可先压缩**：连续相同的字符（如 `"aaa"`）必然能在一轮内涂完，把它们压缩成单个字符不改变答案，却能缩小 `n`、降低常数。这是本题的经典预处理。

### 2.3 算法流程图

**完整步骤**：

1. **预处理**：用正则 `(.)\1+ → \1` 把 `s` 中相邻相同字符合并，得到去重后的串（仍记为 `s`，长度 `n`）。
2. **初始化**：`dp` 为 `n × n` 矩阵全 0；对每个 `i` 置 `dp[i][i] = 1`。
3. **按依赖顺序填表**：`i` 从 `n-1` 到 `0`（倒序），`j` 从 `i+1` 到 `n-1`（正序）：
   - 先取默认值 `dp[i][j] = dp[i][j-1] + 1`
   - 再枚举 `k ∈ [i, j-1]`，凡 `s[k] == s[j]` 即尝试 `dp[i][j] = min(dp[i][j], dp[i][k] + dp[k+1][j-1])`（`k+1 > j-1` 时右段为空，取 0）
4. **返回** `dp[0][n-1]`。

> ⚠️ **填表顺序**：`dp[i][j]` 依赖更短的子区间——左段 `dp[i][k]`（长度 ≤ 当前）、右段 `dp[k+1][j-1]`（长度严格更短）、以及 `dp[i][j-1]`（长度 −1）。让 `i` 倒序、`j` 正序，保证算大区间时所有更短子区间已就绪——这是区间 DP 的经典填表方向，与 516 完全一致。

### 2.4 示例演算

以 `s = "aba"` 为例（无相邻重复，`n = 3`）：

![示例演算：aba 的 dp 表逐格填充，答案 dp[0][2]=2](../images/strange_printer_example_walkthrough.svg)

**dp 表**（行 `i`、列 `j`，仅填上三角 `i ≤ j`；`i > j` 为空段 = 0）：

| | `j=0` (a) | `j=1` (b) | `j=2` (a) |
|------|-----------|-----------|-----------|
| `i=0` (a) | 1 | 2 | **2** |
| `i=1` (b) | — | 1 | 2 |
| `i=2` (a) | — | — | 1 |

**关键填表步骤**：

| 格子 | 默认值 | 是否合并 | 最终值 | 说明 |
|------|--------|----------|--------|------|
| `dp[0][0]` | — | — | 1 | 单字符边界 |
| `dp[0][1]` | `dp[0][0]+1=2` | `s[0]='a'≠s[1]='b'`，无 | 2 | `a`、`b` 不同，各一轮 |
| `dp[0][2]` | `dp[0][1]+1=3` | `s[0]=='a'==s[2]`，`k=0`：`dp[0][0]+dp[1][1]=1+1=2` | **2** | 两端 `a` 共用第 1 轮，中间 `b` 单独 1 轮 |

最终 `dp[0][2] = 2`：第 1 轮涂 `"aaa"` 覆盖整段，第 2 轮在中间涂 `"b"` 覆盖原 `a`，得到 `"aba"`。

> 💡 **对照示例 1**：`"aaabbb"` 经压缩变为 `"ab"`（`n=2`），`dp[0][1]`：默认 `dp[0][0]+1=2`，`s[0]='a'≠s[1]='b'` 无合并，故答案 `2`。压缩让 6 字符问题瞬间归约为 2 字符。

## 3. 参考代码

### C++

```cpp
// 奇怪的打印机.cpp —— 区间 DP + 同字符合并
// 编译: g++ -O2 -std=c++17 奇怪的打印机.cpp -o sp
class Solution {
  public:
    int strangePrinter(string s) {
        // 预处理：压缩相邻相同字符（不改变答案，缩小规模）
        string t;
        for (char c : s) {
            if (t.empty() || c != t.back()) t.push_back(c);
        }
        s = t;
        int n = s.size();
        vector<vector<int>> dp(n, vector<int>(n, 0));
        for (int i = n - 1; i >= 0; --i) {        // i 倒序
            dp[i][i] = 1;                          // 单字符边界
            for (int j = i + 1; j < n; ++j) {      // j 正序
                dp[i][j] = dp[i][j - 1] + 1;       // 默认：s[j] 单独一轮
                for (int k = i; k < j; ++k) {      // 枚举同字符合并点
                    if (s[k] == s[j]) {
                        int right = (k + 1 <= j - 1) ? dp[k + 1][j - 1] : 0;
                        dp[i][j] = min(dp[i][j], dp[i][k] + right);
                    }
                }
            }
        }
        return dp[0][n - 1];
    }
};
```

### Python

```python
import re

class Solution:
    def strangePrinter(self, s: str) -> int:
        s = re.sub(r'(.)\1+', r'\1', s)          # 压缩相邻相同字符
        n = len(s)
        dp = [[0] * n for _ in range(n)]
        for i in range(n - 1, -1, -1):           # i 倒序
            dp[i][i] = 1                          # 单字符边界
            for j in range(i + 1, n):             # j 正序
                dp[i][j] = dp[i][j - 1] + 1       # 默认：s[j] 单独一轮
                for k in range(i, j):             # 枚举同字符合并点
                    if s[k] == s[j]:
                        right = dp[k + 1][j - 1] if k + 1 <= j - 1 else 0
                        dp[i][j] = min(dp[i][j], dp[i][k] + right)
        return dp[0][n - 1]
```

> 💡 **实现细节**：① `dp` 初始化为 0，`i > j` 的下三角恒为 0（代表空段），所以 `k = j-1` 时 `dp[k+1][j-1] = dp[j][j-1] = 0`，相邻同字符对自动得到 `dp[i][j-1] + 0`——这正是「相邻同字符压缩」在 DP 内部的自然体现，也是为何预处理可选但推荐。② 用 `right = (k+1 <= j-1) ? dp[k+1][j-1] : 0` 显式处理空段，避免越界；也可直接依赖下三角为 0 省去判断。③ `i` 倒序、`j` 正序是关键，保证依赖的更短子区间已算完。

## 4. 复杂度分析

| 维度 | 区间 DP（本解） | 记忆化递归 |
|------|----------------|------------|
| **时间** | `O(n³)` | `O(n³)` |
| **空间** | `O(n²)` | `O(n²)` |
| **常数** | 较小（迭代填表） | 略大（递归栈 + 哈希/数组） |

> ⚠️ 时间 `O(n³)`：共约 `n²/2` 个区间 `(i,j)`，每格内层枚举 `k` 最多 `n` 次，总计 `O(n³)`。`n ≤ 100` 时约 $10^6$ 次操作，远低于时限。预处理压缩相邻字符可进一步减小实际 `n`（最坏全交替时仍为 `n`），降低常数。

> 💡 本题 `n ≤ 100` 是为 `O(n³)` 留出的甜区；若 `n` 放大到 $10^5$，则需转向贪心或字符串结构性质的线性/线性对数解法，已超出面试范围。

## 5. 扩展：记忆化递归写法

区间 DP 也可自顶向下递归 + 记忆化实现，思路与迭代版完全等价，但更贴近「分治」直觉：`dfs(i, j)` 返回打印 `s[i..j]` 的最少轮数，先默认 `dfs(i, j-1)+1`，再枚举同字符 `k` 合并。

```python
import re
from functools import lru_cache

class Solution:
    def strangePrinter(self, s: str) -> int:
        s = re.sub(r'(.)\1+', r'\1', s)
        n = len(s)

        @lru_cache(None)
        def dfs(i: int, j: int) -> int:
            if i > j:
                return 0
            if i == j:
                return 1
            res = dfs(i, j - 1) + 1               # 默认：s[j] 单独一轮
            for k in range(i, j):
                if s[k] == s[j]:
                    res = min(res, dfs(i, k) + dfs(k + 1, j - 1))
            return res

        return dfs(0, n - 1) if n else 0
```

> 💡 **迭代 vs 递归**：迭代版填表顺序显式可控、无递归栈开销，是面试主推写法；递归版更易讲清「分治 + 合并」的逻辑结构，适合先口述再落地。两者复杂度一致，`@lru_cache` 自动记忆化保证每个 `(i,j)` 只算一次。

### 与「移除盒子」的对照

[546. 移除盒子](../0501-0600/546_移除盒子.md) 是本题的「升级版」：同样是「同色合并」的区间 DP，但移除盒子还要记录「后面会一起消除的同色块数」，状态需升到三维 `dp[i][j][k]`。本题相当于 `k=0` 的退化情形——掌握 664 的合并思想，是理解 546 三维状态的关键台阶。

## 6. 面试要点

1. **`dp[i][j]` 的定义和转移方程是什么？**

   > `dp[i][j]` = 打印子串 `s[i..j]`（闭区间）的最少轮数。默认 `dp[i][j] = dp[i][j-1] + 1`（`s[j]` 单独一轮）；若存在 `k ∈ [i, j-1]` 使 `s[k] == s[j]`，则可合并：`dp[i][j] = min(dp[i][j], dp[i][k] + dp[k+1][j-1])`。边界 `dp[i][i] = 1`、`i > j` 为 0。答案 `dp[0][n-1]`。

2. **为什么 `s[k] == s[j]` 时可以「合并」？合并后代价为什么是 `dp[i][k] + dp[k+1][j-1]`？**

   > 涂 `s[k]` 的那一轮原本要覆盖位置 `k`，把它延伸到覆盖整段 `[k..j]`（仍涂同一字符）不增加轮数，位置 `j` 因 `s[k]==s[j]` 而「免费」得到正确字符。这一轮之后，中间 `[k+1..j-1]` 被各自后续轮次覆盖，代价为 `dp[k+1][j-1]`；左段 `s[i..k]`（含位置 `k`，其那轮顺手涂了 `j`）代价为 `dp[i][k]`。两段独立可加，故得 `dp[i][k] + dp[k+1][j-1]`。

3. **为什么要枚举所有 `k`，而不是只取离 `j` 最近的同字符位置？**

   > 合并代价 `dp[i][k] + dp[k+1][j-1]` 随 `k` 变化：`k` 靠左则左段长右段短，靠右反之。最优 `k` 不一定是最近的同字符位置，必须在 `[i, j-1]` 内遍历所有 `s[k]==s[j]` 取最小，这也是复杂度为 `O(n³)` 的根源。

4. **为什么要先压缩相邻相同字符？不压缩会怎样？**

   > 相邻相同字符（如 `"aaa"`）必然能在一轮内涂完，压缩成单个字符不改变答案，但能减小 `n`、降低常数。不压缩答案仍然正确——因为 `k = j-1` 且 `s[k]==s[j]` 时 `dp[i][k] + dp[k+1][j-1] = dp[i][j-1] + 0 = dp[i][j-1]`，恰与默认值相等，DP 内部已自然处理相邻重复。预处理只是优化。

5. **填表顺序为什么是 `i` 倒序、`j` 正序？**

   > `dp[i][j]` 依赖更短的子区间：`dp[i][j-1]`（长度 −1）、`dp[i][k]`（长度 ≤ 当前）、`dp[k+1][j-1]`（长度严格更短）。`i` 倒序保证行 `i+1`（更短区间所在行）已算完；`j` 正序保证同行 `j-1` 已算完。本质是按区间长度从短到长填表，与 516 等区间 DP 完全一致。

> 💡 **一句话总结**：664 是区间 DP 的困难代表——`dp[i][j]` 表示打印 `s[i..j]` 的最少轮数，默认 `dp[i][j-1]+1`，遇 `s[k]==s[j]` 则合并为 `dp[i][k]+dp[k+1][j-1]` 让右端「免费」复用一轮，按 `i` 倒序 `j` 正序填表，`O(n³)` 时间、`O(n²)` 空间。这个「同字符合并」思想是通往 546 移除盒子三维区间 DP 的关键台阶。
