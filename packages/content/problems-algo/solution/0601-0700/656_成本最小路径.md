# LeetCode 成本最小路径 题解

## 1. 题目概述

- **标题 / 题号**：成本最小路径（#656，hard）
- **链接**：https://leetcode.cn/problems/coin-path/
- **难度**：困难
- **标签**：动态规划、数组、贪心

**题意**：给定一个 **1-indexed** 的整数数组 $A$（长度为 $N$）和一个整数 $B$。$A_i$ 表示踏上第 $i$ 个位置需要支付的代价（硬币数）。若 $A_i = -1$，则该位置**不可踏入**。

- 你从下标 $1$ 出发，目标是到达下标 $N$。
- 一次移动可以从位置 $i$ 跳到 $i+1, i+2, \ldots, i+B$ 中的任意一个**可达**位置（目标 $j$ 满足 $A_j \neq -1$）。
- 踏上位置 $i$ 需支付 $A_i$ 枚硬币。

要求返回从 $1$ 到 $N$ 的**最小代价路径**（路径上各位置的 1-indexed 下标序列）。若存在多条代价相同的路径，返回**字典序最小**的那一条；若无法到达 $N$，返回空数组 `[]`。

**字典序定义**：路径 $Pa_1, Pa_2, \ldots, Pa_n$ 比 $Pb_1, Pb_2, \ldots, Pb_m$ 小，当且仅当在第一个不同的位置 $i$ 上 $Pa_i < Pb_i$；若不存在不同位置（即一条是另一条的前缀），则**较短者更小**。

**示例 1**：

```text
输入：A = [1,2,4,-1,2], B = 2
输出：[1,3,5]
解释：
  · 1-indexed：A₁=1, A₂=2, A₃=4, A₄=−1(禁入), A₅=2
  · 路径 1→3→5：代价 A₁+A₃+A₅ = 1+4+2 = 7
  · 1→3 跳 2 格(=B)，3→5 跳 2 格(越过禁入的第 4 格)
  · 备选 1→2→3→5 代价 1+2+4+2=9 > 7，非最优
```

**示例 2**：

```text
输入：A = [1,2,4,-1,2], B = 1
输出：[]
解释：B=1 时必须逐格前进 1→2→3→4→5，但 A₄=−1 禁入，无法到达 N=5
```

**约束**：

- $1 \le N \le 1000$
- $1 \le B \le 100$
- $A_1 \ge 0$（起点永远可达）
- $A_2, \ldots, A_N \in [-1, 100]$（$-1$ 表示禁入，否则为非负代价）

> 💡 这是一道 **Google 面试题**，考察「带字典序约束的最短路」这一经典套路。它和普通最短路的差别在于：**不仅要最小代价，还要在并列时输出字典序最小的路径**。这要求在 DP 状态设计之外，额外关心「后继选择」的 tie-breaking——这正是面试中最容易翻车的细节。

## 2. 解题思路

### 2.1 暴力思路：DFS 枚举所有跳法

最直接的做法是从位置 $1$ 出发，DFS 枚举每一步跳 $1 \sim B$ 格的所有组合，记录到达 $N$ 的所有路径及其代价，最后在最小代价路径中挑字典序最小的。

```text
def dfs(i, path, cost):
    if i == N:
        record(path, cost); return
    for j in range(i+1, min(i+B, N)+1):
        if A[j] != -1:
            dfs(j, path+[j], cost + A[j])
dfs(1, [1], A[1])
```

每步至多 $B$ 种选择，路径长度可达 $N$，最坏 $O(B^N)$。$N=1000$ 时完全不可行。但存在大量**重叠子问题**：从位置 $i$ 到 $N$ 的最小代价与如何到达 $i$ 无关——这正是 DP 的信号。

> ⚠️ 暴力法的另一个坑：朴素 DFS 收集「所有路径」再比字典序，路径数本身是指数级的。即便用记忆化记录最小代价，若不设计好「后继指针」，字典序最小这一要求仍难以高效满足。

### 2.2 核心观察：反向 DP（从终点倒推）+ 后继指针

**关键转换**：定义 $dp[i]$ 为「**从位置 $i$ 出发到达终点 $N$ 的最小代价**」（包含踏上 $i$ 与 $N$ 的代价）。于是状态转移天然向后看：

$$dp[i] = A_i + \min_{i < j \le \min(i+B,\, N)} dp[j] \quad (A_i \neq -1)$$

- **基例**：$dp[N] = A_N$（终点本身代价，若 $A_N = -1$ 则直接无解）。
- **禁入格**：$A_i = -1$ 时 $dp[i] = +\infty$，天然不参与后续 $\min$。
- **答案**：$dp[1]$（起点代价 + 到终点的最小代价）；若 $dp[1] = +\infty$ 则返回 `[]`。

**为什么反向（从 $N$ 往 $1$）而不是正向？** 因为反向 DP 让「从 $i$ 出发的最优后继」在计算 $dp[i]$ 时就一并确定——我们只需额外维护一个 $nxt[i]$ 数组记录「取得 $\min$ 的那个 $j$」。计算完后再从起点 $1$ 沿 $nxt$ 指针一路走到 $N$，即可 $O(N)$ 重建路径。正向 DP 则要先算「到达 $i$ 的最小代价」，重建时需要回溯前驱，字典序处理更绕。

![核心：dp[i] = A[i] + min(dp[i+1..i+B])，反向填表，nxt[i] 记最小代价后继](../images/coinpath_dp_concept.svg)

**字典序最小的关键 tie-breaking**：当窗口 $[i+1, i+B]$ 内有多个 $j$ 取得相同的 $\min dp[j]$ 时，$nxt[i]$ 应取**最小的 $j$**。原因如下——

> 💡 **贪心正确性**：路径形如 $[1, j_1, j_2, \ldots, N]$，字典序由左到右逐位比较决定。第一位恒为 $1$（起点固定），故最先起决定作用的是第二位 $j_1$。在所有最小代价路径中，应选**最小的 $j_1$**；选定 $j_1$ 后，第二位确定，再看第三位 $j_2$，同样选最小……这是一个标准的**贪心**：在保证「剩余子问题仍能以最小代价完成」的前提下，每一步选最小下标。由于 $dp[j] = dp[i] - A_i$ 恰好刻画「$j$ 位于某条最小代价路径上」，枚举窗口内所有满足该等式且 $dp[j] \neq \infty$ 的 $j$，取最小者即可。
>
> 工程上更简洁的实现：**反向填表时 $j$ 按 $i+1, i+2, \ldots$ 递增枚举，仅在 $A_i + dp[j] < dp[i]$（严格更小）时更新 $dp[i]$ 与 $nxt[i]$**。由于 $j$ 递增，第一个取得最终最小值的 $j$ 恰好就是所有最小值 $j$ 中最小的一个——并列的更大 $j$ 因「不严格更小」被自动跳过，无需显式判断并列。

**关于「较短者更小」的前缀规则**：所有合法路径都必须以 $N$ 结尾，因此一条最小代价路径不可能是另一条的严格前缀（前缀会止于 $N$ 之前，不合法）。所以前缀规则在本题中不会触发，逐位比较即等价于完整字典序。

### 2.3 算法流程图

![算法流程：边界检查 → 初始化 dp[N] → 反向枚举 i 与窗口 j → 沿 nxt 重建](../images/coinpath_algorithm_flow.svg)

**完整步骤**：

1. **边界检查**：若 $A$ 为空或 $A_N = -1$（终点禁入），返回 `[]`。
2. **初始化**：$dp[N] = A_N$，$nxt[N] = -1$（哨兵），其余 $dp[i] = +\infty$。
3. **反向填表**：$i$ 从 $N-1$ 递减到 $1$：
   - 若 $A_i = -1$：$dp[i]$ 保持 $+\infty$，跳过（禁入格）。
   - 否则枚举 $j \in [i+1, \min(i+B, N)]$：
     - 跳过 $dp[j] = +\infty$（不可达后继，含禁入格）。
     - 若 $A_i + dp[j] < dp[i]$：$dp[i] = A_i + dp[j]$，$nxt[i] = j$。
4. **可达判定**：若 $dp[1] = +\infty$，返回 `[]`。
5. **重建路径**：从 $i = 1$ 出发，循环 `path.append(i)`，`i = nxt[i]`，直到 $i = N$（追加 $N$ 后停止）。返回 $1$-indexed 序列。

### 2.4 示例演算

以 $A = [1,2,4,-1,2], B = 2$ 为例（对应示例 1）：

![示例演算：反向填出 dp[5..1]，沿 nxt 重建得到 [1,3,5]，代价 7](../images/coinpath_example_walkthrough.svg)

| $i$ | $A_i$ | 窗口 $dp[j]$ | $\min dp[j]$ | $dp[i]$ | $nxt[i]$ |
|-----|-------|--------------|--------------|---------|----------|
| 5 | 2 | —（终点基例） | — | 2 | −1 |
| 4 | −1 | 禁入 | — | $\infty$ | — |
| 3 | 4 | $dp[4]=\infty, dp[5]=2$ | 2（$j=5$） | $4+2=6$ | 5 |
| 2 | 2 | $dp[3]=6, dp[4]=\infty$ | 6（$j=3$） | $2+6=8$ | 3 |
| 1 | 1 | $dp[2]=8, dp[3]=6$ | 6（$j=3$） | $1+6=7$ | 3 |

**重建**：$i=1 \xrightarrow{nxt} 3 \xrightarrow{nxt} 5$（到达 $N$，停）。路径 $= [1, 3, 5]$，代价 $= A_1 + A_3 + A_5 = 1 + 4 + 2 = 7$。

> 💡 **为何能越过第 4 格？** 从 $i=3$ 出发，窗口是 $[4, 5]$。虽然 $A_4 = -1$ 禁入（$dp[4] = \infty$ 被排除），但 $B=2$ 允许一步从 3 直接跳到 5，无需经过 4。这正是「跳跃」模型相比「逐格走」的优势——禁入格只是不能**落脚**，并非不能**跨过**。

## 3. 参考代码

### C++

```cpp
// 成本最小路径.cpp —— 反向 DP + nxt 指针贪心重建（最小代价 & 字典序最小路径）
// 编译: g++ -O2 -std=c++17 成本最小路径.cpp -o coinpath
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
  public:
    vector<int> cheapestJump(vector<int>& A, int B) {
        int n = A.size();
        if (n == 0 || A[n - 1] == -1) return {};      // 终点禁入或空数组 → 无解
        const long long INF = LLONG_MAX / 4;          // 防 +A[i] 溢出
        vector<long long> dp(n, INF);
        vector<int> nxt(n, -1);                       // 后继下标(0-indexed)，用于重建
        dp[n - 1] = A[n - 1];                         // ① 终点基例
        for (int i = n - 2; i >= 0; --i) {            // ② 反向填表
            if (A[i] == -1) continue;                 //    禁入格：dp 留 ∞
            int hi = min(i + B, n - 1);
            for (int j = i + 1; j <= hi; ++j) {       //    j 递增枚举窗口
                if (dp[j] == INF) continue;           //    不可达后继跳过
                long long cost = (long long)A[i] + dp[j];
                if (cost < dp[i]) {                   //    严格更小才更新
                    dp[i] = cost;                     //    → 并列更大 j 自动跳过
                    nxt[i] = j;                       //      即取最小 j 保字典序
                }
            }
        }
        if (dp[0] == INF) return {};                  // ③ 起点无法到终点
        vector<int> path;                             // ④ 沿 nxt 重建(转 1-indexed)
        for (int i = 0; i != -1; i = nxt[i]) {
            path.push_back(i + 1);
            if (i == n - 1) break;                    //    到达终点停
        }
        return path;
    }
};
```

### Python

```python
class Solution:
    def cheapestJump(self, A: list[int], B: int) -> list[int]:
        n = len(A)
        if n == 0 or A[n - 1] == -1:        # 终点禁入或空数组 → 无解
            return []
        INF = float('inf')
        dp = [INF] * n                      # dp[i] = 从 i 到终点的最小代价
        nxt = [-1] * n                      # 后继下标，用于重建路径
        dp[n - 1] = A[n - 1]                # ① 终点基例
        for i in range(n - 2, -1, -1):      # ② 反向填表
            if A[i] == -1:                  #    禁入格：dp 留 ∞
                continue
            hi = min(i + B, n - 1)
            for j in range(i + 1, hi + 1):  #    j 递增枚举窗口
                if dp[j] == INF:            #    不可达后继跳过
                    continue
                cost = A[i] + dp[j]
                if cost < dp[i]:            #    严格更小才更新
                    dp[i] = cost            #    → 并列更大 j 自动跳过
                    nxt[i] = j              #      即取最小 j 保字典序
        if dp[0] == INF:                    # ③ 起点无法到终点
            return []
        path = []                           # ④ 沿 nxt 重建(转 1-indexed)
        i = 0
        while i != -1:
            path.append(i + 1)
            if i == n - 1:                  #    到达终点停
                break
            i = nxt[i]
        return path
```

> 💡 **关于 `j` 递增 + 严格 `<` 即得字典序最小**：这是本实现最精妙的一行。由于 $j$ 从 $i+1$ 起递增枚举，第一个把 $dp[i]$ 压到最终最小值的 $j$，必定是所有最小值 $j$ 中下标最小者；之后任何并列的更大 $j$ 都因 `cost < dp[i]` 不成立而被跳过，$nxt[i]$ 自然锁定为最小 $j$。无需额外并列判断，简洁且正确。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(N \cdot B)$ | 反向填表：每个 $i$ 枚举至多 $B$ 个后继；$N \le 1000, B \le 100$ 时约 $10^5$ 次比较 |
| **空间复杂度** | $O(N)$ | 两个长度 $N$ 的数组 `dp` 与 `nxt`；重建路径长度 $\le N$ |
| **最优时间** | $O(N \cdot B)$ | 每对 $(i, j)$ 至少考察一次才能确定最小代价，本解已达此界 |

> ⚠️ 用 `long long` / `float('inf')` 防 $A_i + dp[j]$ 累加溢出。$N=1000$、$A_i \le 100$ 时最大代价约 $10^5$，`int` 也不会溢出，但用 `INF = LLONG_MAX/4` 可保证「$\infty + A_i$ 不翻车」且不污染比较结果。

## 5. 扩展：正向 DP 与 BFS 的取舍

反向 DP 是本题最干净的解法，但面试中常被追问两种变体。

**变体 A：正向 DP 怎么写？** 定义 $f[i]$ 为「从起点 $1$ 到达 $i$ 的最小代价」，$f[i] = A_i + \min_{i-B \le k < i} f[k]$（$A_k \neq -1$），基例 $f[1] = A_1$。答案 $f[N]$。重建时需回溯前驱，字典序最小要在「多个前驱并列时选最小的 $k$」上做文章——但由于路径从左向右生长，前驱选择影响的是「已确定的前缀」，要让整条路径字典序最小，需在并列时选**最小前驱**，逻辑等价但实现略绕（要从 $N$ 向 $1$ 回溯，并最终反转路径）。结论：**反向 DP + 后继指针在字典序处理上更直观**。

**变体 B：能否用 BFS / Dijkstra？** 把每个位置看作节点，$i \to j$（$i < j \le i+B$）的有向边权为 $A_j$。求 $1$ 到 $N$ 的最短路。由于边权非负，Dijkstra 可解，复杂度 $O(NB \log N)$，比 DP 多一个 $\log$。但本题边权范围小、图结构规整（每个点至多 $B$ 条出边），DP 的 $O(NB)$ 严格更优。Dijkstra 的价值在于**边权不统一或图非链式**时的泛化。

| 解法 | 时间 | 空间 | 思路 | 适用场景 |
|------|------|------|------|----------|
| **反向 DP + nxt** | $O(NB)$ | $O(N)$ | 从终点倒推，后继指针保字典序 | 本题最优，链式跳跃模型 |
| 正向 DP + 前驱回溯 | $O(NB)$ | $O(N)$ | 从起点正推，回溯前驱重建 | 思维惯性写法，字典序处理略绕 |
| Dijkstra | $O(NB \log N)$ | $O(NB)$ | 建图求最短路 | 图结构复杂、边权非统一时泛化 |

> 💡 **面试建议**：先讲反向 DP（一表一指针，干净利落），再点出「正向 DP 也能做但字典序 tie-breaking 更绕」体现思考深度，最后用 Dijkstra 作为「图论视角的泛化」收尾。三段式能覆盖面试官可能追问的所有方向。

## 6. 面试要点

1. **为什么反向 DP 比正向更合适？**

   - 反向 DP 在计算 $dp[i]$ 时同时确定「最优后继」$nxt[i]$，重建只需从起点沿指针前进，$O(N)$ 且方向自然。
   - 正向 DP 记录的是前驱，重建需从终点回溯再反转，且字典序最小要在前驱并列时选最小 $k$，实现更易出错。

2. **字典序最小的 tie-breaking 如何保证？**

   - 窗口内 $j$ 递增枚举，仅在 $A_i + dp[j] < dp[i]$（严格更小）时更新 $nxt[i]$。
   - 第一个取得最终最小值的 $j$ 即所有最小值 $j$ 中最小者；并列的更大 $j$ 因不严格更小被跳过。
   - 本质是贪心：在保证剩余子问题仍以最小代价完成的前提下，每一步选最小下标，逐位确定字典序。

3. **$A_i = -1$ 的禁入格如何处理？**

   - 令 $dp[i] = +\infty$，它在后续 $\min$ 中天然被排除，无需特判。
   - 注意禁入只是不能**落脚**，仍可被**跨过**（从 $i$ 一步跳到 $i+2$ 越过 $i+1$ 是合法的）。
   - 特例：$A_N = -1$（终点禁入）直接返回 `[]`；$A_1$ 由约束恒 $\ge 0$，起点必可达。

4. **示例 2（$B=1$）为什么返回 `[]`？**

   - $B=1$ 时只能逐格前进 $1 \to 2 \to 3 \to 4 \to 5$，必须踏上第 4 格。
   - 但 $A_4 = -1$ 禁入，$dp[4] = \infty$ 导致 $dp[3] = \infty$ 一路传播到 $dp[1] = \infty$，返回 `[]`。

5. **「较短者更小」的前缀规则会触发吗？**

   - 不会。所有合法路径必须以 $N$ 结尾，一条最小代价路径不可能是另一条的严格前缀（前缀会止于 $N$ 之前，不合法）。
   - 因此逐位比较即等价于完整字典序，无需为前缀规则额外编码。

> 💡 **一句话总结**：成本最小路径是「带字典序约束的最短路」招牌题——反向 DP $dp[i] = A_i + \min dp[j]$ 配一个 $nxt$ 后继指针，$j$ 递增 + 严格 `<` 更新即可同时锁定最小代价与字典序最小路径。核心直觉是「从终点倒推让后继自然显现，贪心选最小下标逐位定字典序」。
