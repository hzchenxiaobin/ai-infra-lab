# LeetCode 执行所有后缀指令 题解

## 1. 题目概述

- **标题 / 题号**：执行所有后缀指令（#2120，medium）
- **链接**：https://leetcode.cn/problems/execution-of-all-suffix-instructions-staying-in-a-grid/
- **难度**：中等
- **标签**：数组、模拟、字符串

**题意**：现有一个 `n x n` 大小的网格，左上角坐标 `(0, 0)`，右下角坐标 `(n - 1, n - 1)`。机器人初始位于 `startPos = [startRow, startCol]`。

给定长度为 `m`、下标从 `0` 开始的指令串 `s`，每个字符是 `'L'`（左）、`'R'`（右）、`'U'`（上）、`'D'`（下）之一。

机器人可以从 `s` 中**任一第 `i` 条指令**开始执行，逐条执行到 `s` 末尾，但在满足下列条件之一时**停止**：

- 下一条指令会让机器人移动到**网格外**（此时该条指令不计数）。
- 没有指令可执行（到达 `s` 末尾）。

返回长度为 `m` 的数组 `answer`，其中 `answer[i]` 是机器人从第 `i` 条指令开始、能成功执行的**指令数目**。

**示例 1**：

```text
输入：n = 3, startPos = [0,1], s = "RRDDLU"
输出：[1,5,4,3,1,0]
解释：机器人从 (0,1) 出发，分别从第 i 条指令开始执行：
- 0: "RRDDLU" → 第 1 条 R 让列到 3（出界），只执行了 1 条 R。
- 1: "RDDLU"  → 全部 5 条都执行成功，终点 (0,0)。
- 2: "DDLU"   → 全部 4 条都执行成功，终点 (0,0)。
- 3: "DLU"    → 全部 3 条都执行成功，终点 (0,0)。
- 4: "LU"     → 第 2 条 U 让行到 -1（出界），只执行了 1 条 L。
- 5: "U"      → 第 1 条 U 让行到 -1（出界），执行 0 条。
```

**示例 2**：

```text
输入：n = 2, startPos = [1,1], s = "LURD"
输出：[4,1,0,0]
解释：
- 0: "LURD" 全部 4 条执行成功。
- 1: "URD"  → U 让行到 0 还在界内，但 R 让列到 2（出界），只执行了 1 条 U。
- 2: "RD"   → R 让列到 2（出界），执行 0 条。
- 3: "D"    → D 让行到 2（出界），执行 0 条。
```

**示例 3**：

```text
输入：n = 1, startPos = [0,0], s = "LRUD"
输出：[0,0,0,0]
解释：1×1 网格只有 (0,0) 一个格子，任意方向的第一步都会出界。
```

**约束**：

- $m == \text{s.length}$
- $1 \leq n, m \leq 500$
- $\text{startPos.length} == 2$
- $0 \leq \text{startRow}, \text{startCol} < n$
- `s` 仅由 `'L'`、`'R'`、`'U'`、`'D'` 组成

> 💡 **审题关键**：① **每个起点独立**——`answer[i]` 对应的执行**总是从 `startPos` 出发**，不是从上一轮终点出发，所以 `m` 次模拟互不依赖；② **出界即停且不计数**——一旦某条指令会让机器人越界，该条**不计入** `answer[i]`，立即停止后续指令；③ 起点本身在网格内（约束保证），所以 `answer[i]` 至少能开始判定第一条指令是否越界；④ $m \leq 500$，$O(m^2)$ 暴力完全可接受。

## 2. 解题思路

### 2.1 暴力思路：逐起点独立模拟

最直观的做法：对每个起点下标 `i`（$0 \leq i < m$），都从 `startPos` 重新出发，逐条执行 `s[i]`、`s[i+1]`、… 、`s[m-1]`，遇到会让机器人越界的指令就停下，记录成功执行的条数。

具体地，对每个起点 `i`：

1. 令 `r = startRow`, `c = startCol`, `cnt = 0`。
2. 遍历 `j` 从 `i` 到 `m-1`：
   - 根据 `s[j]` 计算目标位置 `(nr, nc)`。
   - 若 $0 \leq nr < n$ 且 $0 \leq nc < n$：接受这一步，`r = nr, c = nc, cnt += 1`。
   - 否则：**越界，停止**（这条不计数，后续也不再执行）。
3. `answer[i] = cnt`。

- **正确性**：完全复现题目描述的执行过程，必然得到正确答案。
- **效率**：每个起点最坏遍历剩余 $m - i$ 条指令，总时间 $\sum_{i=0}^{m-1}(m-i) = O(m^2)$，空间 $O(1)$（不计输出数组）。$m = 500$ 时约 $1.25 \times 10^5$ 次操作，毫秒级。

> ⚠️ 暴力已是本题的标准解法。约束 $m \leq 500$ 明确提示 $O(m^2)$ 可接受，无需追求更优复杂度。第 5 节给出一个利用「前缀位移 + 哈希」的 $O(m)$ 优化作为延伸阅读。

### 2.2 核心观察：每个起点独立 + 出界即停

![核心观察：每个起点都从 startPos 重新出发，越界即停](../images/2120_grid_walk_concept.svg)

整个解法建立在**两个关键观察**上。

**观察 1：每个 `answer[i]` 的执行都从 `startPos` 出发**

虽然名字叫「后缀指令」，但机器人**不是从上一轮终点继续走**，而是**每次都重置回 `startPos`** 重新执行 `s[i:]`。这意味着 `m` 次模拟完全独立，没有状态依赖——可以直接对每个 `i` 重新跑一遍，无需记忆化或复用前一轮结果。

> ⚠️ **易错点**：容易误以为「机器人从第 0 条指令开始一直走到末尾，`answer[i]` 是从某个中间状态开始的继续」。实际上每个 `i` 都是**从 `startPos` 重新开始**，执行 `s[i:]` 这一段后缀。

**观察 2：出界即停，且出界那条指令不计入**

机器人执行 `s[j]` 时，先检查目标位置是否在网格内：

| 情况 | 处理 |
|------|------|
| 目标在网格内 | 接受这一步，更新位置，`cnt += 1` |
| 目标在网格外 | **丢弃这一步**（不更新位置、不计数），立即停止后续 |

$$\text{answer}[i] = \min\{j - i \mid j \geq i,\ s[j]\ \text{使机器人越界}\}\ \ \text{或}\ \ m - i\ \text{（若全程未越界）}$$

**用示例 1 验证观察 2**：`n = 3, startPos = [0,1], s = "RRDDLU"`。

| $i$ | 后缀 | 越界指令 $j$ | $\text{answer}[i] = j - i$ |
|-----|------|--------------|----------------------------|
| 0 | `RRDDLU` | $j = 1$（第 2 个 `R` 让列到 3） | $1 - 0 = 1$ |
| 1 | `RDDLU` | 无（全部成功） | $6 - 1 = 5$ |
| 2 | `DDLU` | 无 | $6 - 2 = 4$ |
| 3 | `DLU` | 无 | $6 - 3 = 3$ |
| 4 | `LU` | $j = 5$（`U` 让行到 $-1$） | $5 - 4 = 1$ |
| 5 | `U` | $j = 5$（`U` 让行到 $-1$） | $5 - 5 = 0$ |

合计 `answer = [1,5,4,3,1,0]` ✓

### 2.3 算法流程图

![算法流程：外层遍历每个起点 i，内层从 startPos 模拟执行 s[i:]](../images/2120_algorithm_flow.svg)

**完整步骤**：

1. 令 `m = s.size()`，初始化 `answer` 数组长度为 `m`。
2. **外层循环** `i` 从 `0` 到 `m - 1`：
   - 令 `r = startRow`，`c = startCol`，`cnt = 0`。
   - **内层循环** `j` 从 `i` 到 `m - 1`：
     - 按 `s[j]` 算 `(nr, nc)`：`'L'`→`nc = c - 1`；`'R'`→`nc = c + 1`；`'U'`→`nr = r - 1`；`'D'`→`nr = r + 1`。
     - 若 $0 \leq nr < n$ 且 $0 \leq nc < n$：`r = nr, c = nc, cnt += 1`。
     - 否则：`break`（越界即停）。
   - `answer[i] = cnt`。
3. **返回** `answer`。

> 💡 **写法要点**：① `r, c` 在外层循环开头**重置**为 `startRow, startCol`，体现「每个起点独立」；② 内层用 `break` 而非 `continue`——越界后**立即停止**，不能跳过越界指令继续执行后续；③ 越界判定要同时检查 `nr` 和 `nc` 两个维度，但每次只有一个维度变化（`L/R` 改列、`U/D` 改行），所以另一个维度天然合法。

### 2.4 示例演算

以 `n = 3, startPos = [0,1], s = "RRDDLU"` 逐步演算 6 个起点：

![示例演算：6 个起点逐个模拟，绿色为成功步、红色为越界步](../images/2120_example_walkthrough.svg)

**逐起点拆解**：

- $i=0$：`(0,1)` →`R`→ `(0,2)` →`R`→ `(0,3)`✗ 出界。`answer[0] = 1`。
- $i=1$：`(0,1)` →`R`→ `(0,2)` →`D`→ `(1,2)` →`D`→ `(2,2)` →`L`→ `(2,1)` →`U`→ `(1,1)`。全部成功。`answer[1] = 5`。
- $i=2$：`(0,1)` →`D`→ `(1,1)` →`D`→ `(2,1)` →`L`→ `(2,0)` →`U`→ `(1,0)`。全部成功。`answer[2] = 4`。
- $i=3$：`(0,1)` →`D`→ `(1,1)` →`L`→ `(1,0)` →`U`→ `(0,0)`。全部成功。`answer[3] = 3`。
- $i=4$：`(0,1)` →`L`→ `(0,0)` →`U`→ `(-1,0)`✗ 出界。`answer[4] = 1`。
- $i=5$：`(0,1)` →`U`→ `(-1,1)`✗ 出界。`answer[5] = 0`。

$$\text{answer} = [1, 5, 4, 3, 1, 0] \checkmark$$

> 💡 **对照示例 3** `n = 1, startPos = [0,0], s = "LRUD"`：1×1 网格只有一个格子 `(0,0)`，任意方向第一步都越界，所以每个起点 `answer[i] = 0`。这是「起点在边界角上」的极端情况，暴力模拟天然处理，无需特判。

## 3. 参考代码

### 方法一：逐起点独立模拟（$O(m^2)$，推荐）

### C++

```cpp
class Solution {
public:
    vector<int> executeInstructions(int n, vector<int>& startPos, string s) {
        int m = s.size();
        vector<int> answer(m);
        int dr[128] = {}, dc[128] = {};
        dc['L'] = -1; dc['R'] = 1;
        dr['U'] = -1; dr['D'] = 1;
        for (int i = 0; i < m; ++i) {
            int r = startPos[0], c = startPos[1], cnt = 0;
            for (int j = i; j < m; ++j) {
                int nr = r + dr[(int)s[j]];
                int nc = c + dc[(int)s[j]];
                if (nr < 0 || nr >= n || nc < 0 || nc >= n) break;
                r = nr; c = nc; ++cnt;
            }
            answer[i] = cnt;
        }
        return answer;
    }
};
```

### Python

```python
class Solution:
    def executeInstructions(self, n: int, startPos: list[int], s: str) -> list[int]:
        m = len(s)
        delta = {'L': (0, -1), 'R': (0, 1), 'U': (-1, 0), 'D': (1, 0)}
        answer = []
        for i in range(m):
            r, c, cnt = startPos[0], startPos[1], 0
            for j in range(i, m):
                dr, dc = delta[s[j]]
                nr, nc = r + dr, c + dc
                if not (0 <= nr < n and 0 <= nc < n):
                    break
                r, c = nr, nc
                cnt += 1
            answer.append(cnt)
        return answer
```

> 💡 **写法要点**：① 用 `delta` 字典 / `dr, dc` 数组把方向编码解耦，避免长串 `if-else`；② 内层 `break` 实现「越界即停」；③ `r, c` 在外层循环开头重置，体现「每个起点独立」。C++ 版用 `dr[128]` / `dc[128]` 以字符 ASCII 为下标，省去 `map` 查找开销。

## 4. 复杂度分析

| 维度 | 方法 | 复杂度 | 说明 |
|------|------|--------|------|
| 时间 | 逐起点模拟 | $O(m^2)$ | 每个起点最坏遍历 $m - i$ 条，总和 $\sum_{i=0}^{m-1}(m-i) = \frac{m(m+1)}{2}$ |
| 空间 | 逐起点模拟 | $O(m)$ | 仅输出数组（不计输出则为 $O(1)$） |

> 💡 $m = 500$ 时 $O(m^2) \approx 1.25 \times 10^5$，毫秒级完成。约束刻意把 $m$ 限制在 500 以内，明确鼓励 $O(m^2)$ 暴力，无需过度优化。

## 5. 扩展：前缀位移 + 哈希的 $O(m)$ 优化

若把约束放大到 $m \leq 10^5$，$O(m^2)$ 就不够了。这里给出一个利用**前缀位移 + 哈希表**的 $O(m)$ 优化思路。

**核心转化**：设 `pref_r[k]`、`pref_c[k]` 为 `s[0..k-1]` 的累计行、列位移（`pref_r[0] = pref_c[0] = 0`）。执行 `s[i..j-1]` 后机器人位置为：

$$\big(\text{startRow} + \text{pref}_r[j] - \text{pref}_r[i],\ \ \text{startCol} + \text{pref}_c[j] - \text{pref}_c[i]\big)$$

`s[j]` 越界等价于执行 `s[i..j-1]` 后机器人停在**对应方向的边界**且 `s[j]` 指向界外：

| `s[j]` | 越界条件（位置等式） | 等价于 |
|--------|----------------------|--------|
| `'L'` | $\text{startCol} + \text{pref}_c[j] - \text{pref}_c[i] = 0$ | $\text{pref}_c[i] = \text{startCol} + \text{pref}_c[j]$ |
| `'R'` | $\text{startCol} + \text{pref}_c[j] - \text{pref}_c[i] = n - 1$ | $\text{pref}_c[i] = \text{startCol} + \text{pref}_c[j] - (n - 1)$ |
| `'U'` | $\text{startRow} + \text{pref}_r[j] - \text{pref}_r[i] = 0$ | $\text{pref}_r[i] = \text{startRow} + \text{pref}_r[j]$ |
| `'D'` | $\text{startRow} + \text{pref}_r[j] - \text{pref}_r[i] = n - 1$ | $\text{pref}_r[i] = \text{startRow} + \text{pref}_r[j] - (n - 1)$ |

**倒序扫描 `i`**（从 $m-1$ 到 $0$），维护四个哈希表 `mapL / mapR / mapU / mapD`，键为「所需的 `pref` 值」，值为「已扫描范围内最小的 `j`」。处理 `i` 时先把 $j = i$ 加入对应方向的哈希表（倒序扫描，后加入的 $j$ 更小，直接覆盖即可），再查询四个表得到最早越界 `j`。

```cpp
class Solution {
public:
    vector<int> executeInstructions(int n, vector<int>& startPos, string s) {
        int m = s.size();
        vector<int> prefr(m + 1, 0), prefc(m + 1, 0);
        for (int k = 0; k < m; ++k) {
            prefr[k + 1] = prefr[k] + (s[k] == 'D') - (s[k] == 'U');
            prefc[k + 1] = prefc[k] + (s[k] == 'R') - (s[k] == 'L');
        }
        unordered_map<int, int> mapL, mapR, mapU, mapD;
        vector<int> answer(m);
        for (int i = m; i >= 1; --i) {
            int j = i;                       // j 是 1-indexed 的指令下标
            char d = s[i - 1];
            if (d == 'L') mapL[prefc[j]] = j;
            else if (d == 'R') mapR[prefc[j]] = j;
            else if (d == 'U') mapU[prefr[j]] = j;
            else mapD[prefr[j]] = j;
            int best = INT_MAX;
            auto probe = [&](unordered_map<int, int>& mp, int key) {
                auto it = mp.find(key);
                if (it != mp.end()) best = min(best, it->second);
            };
            probe(mapL, startPos[1] + prefc[i - 1]);
            probe(mapR, startPos[1] + prefc[i - 1] - (n - 1));
            probe(mapU, startPos[0] + prefr[i - 1]);
            probe(mapD, startPos[0] + prefr[i - 1] - (n - 1));
            int start = i - 1;               // 0-indexed 起点
            if (best == INT_MAX) answer[start] = m - start;
            else answer[start] = best - start;
        }
        return answer;
    }
};
```

> ⚠️ **此优化对本题约束（$m \leq 500$）属「杀鸡用牛刀」**，且哈希常数较大、实现易错。面试中作为「如何把 $O(m^2)$ 优化到 $O(m)$」的延伸讨论即可，真正提交建议用方法一。核心思想是：**把「逐条模拟找越界」转化为「按 prefix 值哈希查询最早越界点」**，类似前缀和 + 哈希求「最早满足条件的右端点」。

## 6. 面试要点

**Q1：为什么每个 `answer[i]` 的模拟都要从 `startPos` 重新出发？**

> 题目要求「机器人从第 `i` 条指令**开始**执行」，且每次开始时都在 `startPos`。这相当于 `m` 次独立的模拟，前一轮的终点不影响后一轮的起点。容易误以为「机器人从 `s[0]` 一路走到末尾，`answer[i]` 是中途某段的计数」，但实际上每次都重置。

**Q2：越界的那条指令为什么不计入 `answer[i]`？**

> 题目明确「下一条指令**将会导致**机器人移动到网格外」时停止，意味着这条指令**没有真正执行**（位置不变），只是触发了停止条件。所以 `answer[i]` 数的是**成功执行**的指令条数，越界那条不算。代码中 `break` 在更新 `cnt` 之前，自然实现这一点。

**Q3：$O(m^2)$ 在 $m = 500$ 下是否真的够快？**

> $m = 500$ 时 $O(m^2) \approx 1.25 \times 10^5$ 次基本操作，C++ 毫秒级、Python 也仅几毫秒。LeetCode 中等题的常见时间限制是 1–2 秒，$10^5$ 量级完全安全。约束刻意把 $m$ 卡在 500，正是为了允许 $O(m^2)$。

**Q4：方向编码用 `if-else` 还是查表？**

> 查表更简洁且可扩展。用 `delta = {'L': (0,-1), 'R': (0,1), 'U': (-1,0), 'D': (1,0)}` 一行定义四个方向，内层循环只需 `dr, dc = delta[s[j]]`。C++ 可用 `dr[128]` / `dc[128]` 以字符 ASCII 为下标，省去 `unordered_map` 的开销。`if-else` 链在方向多时冗长，不推荐。

**Q5：如果 `s` 中包含无效字符或 `startPos` 已在网格外怎么办？**

> 约束保证 `s` 仅含 `'L'/'R'/'U'/'D'` 且 `0 ≤ startRow, startCol < n`，不会出现这些情况。若面试中放开约束，应先做输入校验：过滤无效字符、检查起点合法性。这是可以主动提出的边界讨论。

> 💡 **一句话总结**：每个起点从 `startPos` 重新模拟，遇越界即 `break`，$O(m^2)$ 时间、$O(1)$ 额外空间。核心是认清「每个 `answer[i]` 独立」+「越界即停且不计数」两点。
