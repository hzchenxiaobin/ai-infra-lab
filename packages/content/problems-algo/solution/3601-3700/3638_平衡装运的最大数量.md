# LeetCode 平衡装运的最大数量 题解

## 1. 题目概述

- **标题 / 题号**：平衡装运的最大数量（#3638，medium）
- **链接**：https://leetcode.cn/problems/maximum-balanced-shipments/
- **难度**：中等
- **标签**：栈、贪心、数组、动态规划、单调栈

**题意**：给你一个长度为 `n` 的整数数组 `weight`，表示按直线排列的 `n` 个包裹的重量。**装运**定义为包裹的一个**连续子数组**。如果一个装运满足**最后一个包裹的重量严格小于该装运中所有包裹的最大重量**，则称其为**平衡装运**。

选择若干个**不重叠**的连续平衡装运（部分包裹可以不被装运，每个包裹最多出现在一次装运中），返回可以形成的平衡装运的**最大数量**。

**示例 1**：

```text
输入：weight = [2,5,1,4,3]
输出：2
解释：装运 1 = [2,5,1]（最大重量 5 > 末尾 1，平衡）；
     装运 2 = [4,3]（最大重量 4 > 末尾 3，平衡）。
     无法划分出超过两个平衡装运。
```

**示例 2**：

```text
输入：weight = [4,4]
输出：0
解释：[4,4] 末尾 4 不严格小于最大值 4；单包 [4] 同样不平衡，无法形成任何平衡装运。
```

**约束**：

- `2 <= n <= 10^5`
- `1 <= weight[i] <= 10^9`

> 💡 **审题关键**：① 装运是**连续子数组**，且数量要**最多**而不是最长——直观上每段越短越好，但段末必须有一个「比段内最大值小」的包裹垫底；② 单个包裹永远无法构成平衡装运（末尾 = 最大值，不满足**严格**小于）；③ 包裹可以跳过不装运，所以这本质是「在数组上切出尽可能多段互不重叠的合法区间」的线性 DP。

## 2. 解题思路

### 2.1 暴力思路：记忆化搜索枚举段终点

从左往右扫，记 `solve(i)` 为「包裹 `i..n-1` 中最多能切的平衡装运数」：要么跳过包裹 `i`（`solve(i+1)`），要么枚举一段 `[i..e]`：只要 `max(weight[i..e]) > weight[e]` 即平衡，贡献 `1 + solve(e+1)`。配合前缀最大值，每个起点摊还 $O(n)$，总复杂度 $O(n^2)$。

- **正确性**：枚举覆盖了所有可能的切分方案，没有问题；
- **瓶颈**：$n \le 10^5$ 时 $O(n^2) = 10^{10}$，必然超时；
- **浪费所在**：对每个终点 `e` 逐一判断「段内有没有比 `weight[e]` 大的包裹」，重复扫了太多信息——而「`e` 左侧最近的严格更大元素」是**单调栈**的经典一步到位查询。

> ⚠️ 突破口在于把「平衡条件」翻译成**起点约束**：`[s..i]` 平衡 $\iff$ 段内存在比 `weight[i]` 大的包裹 $\iff$ 起点 $s$ 不越过 `i` 左侧最近的严格更大元素。于是合法起点是一段**前缀区间**，DP 转移从 $O(n)$ 塌缩成 $O(1)$。

### 2.2 核心观察：合法起点是前缀，「最近更大元素」划界 + 前缀 DP

![核心观察：j(i) 左侧全是合法起点，f[i] 由 f[j-1]+1 转移而来](../images/p3638_nearest_greater_concept.svg)

**观察一（平衡条件 → 起点前缀）**：固定装运终点 $i$，设 $j(i)$ 为 $i$ **左侧最近的满足** $weight[j] > weight[i]$ 的下标（不存在则记 $-1$）。由「最近」性，开区间 $(j(i), i)$ 内的所有重量都 $\le weight[i]$，于是：

$$[s..i]\ \text{平衡} \iff \max(s..i) > weight[i] \iff s \le j(i)$$

- $s \le j(i)$：段内含 $weight[j(i)] > weight[i]$，必然平衡；
- $s > j(i)$：段内除末尾外全 $\le weight[i]$，最大值恰为 $weight[i]$（末尾自己），**严格小于**不成立。

特别地 $j(i) = -1$（左侧没有更大的）时，**任何**以 $i$ 收尾的装运都不平衡——这就是示例 2 中 `[4,4]` 答案为 0 的原因。

**观察二（前缀 DP）**：设 $f[i]$ 为「前 $i+1$ 个包裹中最多能形成的平衡装运数」。包裹 $i$ 要么不属于任何装运（$f[i-1]$），要么是某段装运的**末尾**：

$$f[i] = \max\bigl(f[i-1],\ \ f[j(i)-1] + 1\bigr)\qquad(\text{约定 } f[-1] = 0,\ j(i) \ge 0 \text{ 时才有第二项})$$

装运 $[s..i]$ 与此前的装运互不重叠，此前的装运必须**整体落在前缀 $[0..s-1]$ 内**。由于 $f$ 单调不减（前缀越长限制越松，最优解不会变差），$\max_{s \le j(i)} f[s-1] = f[j(i)-1]$，即最优起点取 $s = j(i)$ 也不亏——转移 $O(1)$。

> ⚠️ **此处有个高频 ±1 陷阱**：第二项是 $f[j(i)-1] + 1$ 而**不是** $f[j(i)] + 1$。若误用 $f[j(i)]$，最优解可能包含一条**恰好以 $j(i)$ 收尾**的装运，与起点 $s \le j(i)$ 的新装运在下标 $j(i)$ 处重叠，凭空多算一段。反例 `weight = [5,2,1]`：正确答案 1（`[5,2]` 与 `[2,1]` 在下标 1 冲突，只能取其一），误用 $f[j]+1$ 会算出 2。

**观察三（单调栈求 $j(i)$）**：维护一个下标栈，栈内重量**严格递减**。处理 $i$ 时把所有 $weight[\text{栈顶}] \le weight[i]$ 的下标弹出——它们比 $weight[i]$ 小（或相等），不可能再当后续任何位置的「左侧更大元素」；弹出后新的栈顶（若有）正是 $j(i)$。每个下标至多入栈、出栈各一次，总代价均摊 $O(1)$。

> 💡 一句话总结：**「末尾严格小于段内最大值」⇔「起点不越过左侧最近更大元素」**——平衡条件被改写成起点的前缀可行域，DP + 单调栈一趟线性扫描解决。

### 2.3 算法流程图

![算法流程：弹栈找 j(i) → f[i] = max(f[i-1], f[j-1]+1) → i 入栈，一趟扫描](../images/p3638_algorithm_flow.svg)

**逻辑执行步骤**：

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `f[0..n-1]` 置 0，空栈 `st` | `f` 即答案 DP 数组，`st` 存下标、重量严格递减 |
| ② 弹栈 | `while st 非空且 weight[st.top()] <= weight[i]`：弹栈 | 弹掉的都不可能是 $j(i)$，也不可能是后续位置的 $j$ |
| ③ 定界 | `j = st 空 ? -1 : st.top()` | $j$ 即 $i$ 左侧最近严格更大元素的下标 |
| ④ 转移 | `f[i] = f[i-1]`；若 `j >= 0` 再与 `(j > 0 ? f[j-1] : 0) + 1` 取 max | 包裹 `i` 不装 / 作为装运末尾，二者取优 |
| ⑤ 入栈 | `st.push(i)` | 维护栈内重量严格递减的不变量 |
| ⑥ 输出 | 循环结束返回 `f[n-1]` | `f` 单调不减，末项即全局答案 |

> ⚠️ 弹栈条件是 `<=`（弹出相等者）而不是 `<`：$j(i)$ 要求**严格更大**，相等的元素留在栈里会把合法起点域误判小……恰恰相反——相等元素弹不弹只影响 $j$ 的取值正确性，弹掉相等者后栈顶才是真正严格更大的那一个，留着的相等元素则会让 `s ≤ j` 的界**偏小**，漏掉合法起点（如 `[4,4]` 中若 `w[0]=4` 未弹出，`j(1)=0` 会误判 `[4,4]` 平衡）。

### 2.4 示例演算（示例 1）

`weight = [2,5,1,4,3]`，逐位记录栈（存下标，对应重量）与 $f$：

| i | w[i] | 弹栈后栈内下标（重量） | j(i) | 转移 | f[i] |
|---|------|----------------------|------|------|------|
| 0 | 2 | `[]` | -1 | 无第二项，$f[-1]=0$ | 0 |
| 1 | 5 | 弹 0（2≤5）→ `[]` | -1 | 只有 $f[0]$ | 0 |
| 2 | 1 | `[1]`（5） | 1 | $\max(f[1],\, f[0]+1)$ | **1**（`[2,5,1]`） |
| 3 | 4 | 弹 2（1≤4）→ `[1]`（5） | 1 | $\max(f[2],\, f[0]+1)=\max(1,1)$ | 1 |
| 4 | 3 | `[1,3]`（5,4） | 3 | $\max(f[3],\, f[2]+1)=\max(1,2)$ | **2**（`[4,3]`） |

答案 `f[4] = 2`。✅ 注意第 4 行：$j(4)=3$（最近更大的 4），最优解让前一段装运 `[2,5,1]` 整体落在前缀 $[0..2]$ 即 $f[2]+1$，恰好躲开了下标 3 上的重叠——这正是转移式取 $f[j-1]$ 而非 $f[j]$ 的体现。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    int maxBalancedShipments(vector<int>& weight) {
        int n = weight.size();
        vector<int> f(n, 0);
        vector<int> st;                       // 下标栈，对应重量严格递减
        for (int i = 0; i < n; ++i) {
            while (!st.empty() && weight[st.back()] <= weight[i]) {
                st.pop_back();                // 弹掉 <= 当前值者，栈顶即左侧最近更大
            }
            if (i > 0) f[i] = f[i - 1];       // 包裹 i 不参与任何装运
            if (!st.empty()) {
                int j = st.back();
                f[i] = max(f[i], (j > 0 ? f[j - 1] : 0) + 1);   // 装运以 i 收尾
            }
            st.push_back(i);
        }
        return f[n - 1];
    }
};
```

> 💡 **写法要点**：
> - `j > 0 ? f[j-1] : 0` 对应约定 $f[-1]=0$：起点 $s=0$ 时前缀为空、此前装运数为 0。
> - 弹栈条件务必是 `<=`：相等元素不弹会把 $j$ 误指向相等者（见 2.3 的 ⚠️）。
> - 栈中存**下标**而非重量——转移需要 `f[j-1]`，只存重量会丢掉定位信息。

### Python

```python
class Solution:
    def maxBalancedShipments(self, weight: List[int]) -> int:
        n = len(weight)
        f = [0] * n
        st = []                               # 下标栈，对应重量严格递减
        for i, w in enumerate(weight):
            while st and weight[st[-1]] <= w:
                st.pop()
            if i:
                f[i] = f[i - 1]               # 包裹 i 不参与任何装运
            if st:
                j = st[-1]
                f[i] = max(f[i], (f[j - 1] if j else 0) + 1)
            st.append(i)
        return f[-1]
```

> 💡 **写法要点**：
> - `(f[j-1] if j else 0)`：`j == 0` 时取空前缀的 0，避免 `f[-1]` 悄悄绕到数组末尾——Python 的负下标不报错，是这类 DP 最阴的写错点。
> - `weight[st[-1]] <= w` 中 `<=` 缺不得（严格更大的要求）。
> - 一趟循环内「弹 → 查 → 转 → 压」四步顺序固定，先转移再入栈（`i` 自己不能当自己的 `j`）。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间复杂度** | $O(n)$ | 每个下标至多入栈一次、出栈一次，弹栈总代价均摊 $O(1)$；DP 转移每次 $O(1)$ |
| **空间复杂度** | $O(n)$ | DP 数组 $f$ 长度 $n$；单调栈最坏（严格递减输入）也是 $n$ |

> - 若只需答案，$f$ 数组不可省（转移依赖 $f[j-1]$ 的随机访问），但可以确认**没有隐藏的排序/二分**把复杂度抬上去——整趟只有栈操作和下标访问。
> - 与暴力 $O(n^2)$ 相比，加速来源正是把「段内是否存在更大元素」的重复扫描替换为单调栈的 $O(1)$ 查询。

## 5. 扩展：贪心「能切就切」的 $O(1)$ 空间写法

本题还有个更省的贪心：**从左到右维护当前开段的段内最大值 `cur`，一旦遇到 `weight[i] < cur`，立刻在此收尾切段**（新段从 `i+1` 开始），段数 +1。上面 DP 的正确性保证了它也为最优，也可直接交换论证：

> 设最优解的第一段为 $[s..e]$（平衡 $\Rightarrow \max(s..e-1) > weight[e]$，故 $e$ 是一个「可切点」），而贪心切在**最早**可切点 $i_0 \le e$；把 $[s..e]$ 换成 $[0..i_0]$（由可切点定义仍平衡，段数不变），最优解剩余的段全部落在 $[e+1..] \subseteq [i_0+1..]$ 中，对后缀归纳即得贪心不劣。

```python
class Solution:
    def maxBalancedShipments(self, weight: List[int]) -> int:
        ans, cur = 0, 0                # cur = 0 表示当前开段为空（重量 >= 1）
        for w in weight:
            if w < cur:                # 段内已有严格更大者 → 收尾
                ans += 1
                cur = 0                # 新段从下一个包裹开始
            else:
                cur = max(cur, w)
        return ans
```

> ⚠️ 切段后 `cur` 必须清零（新段从 `i+1` 开始，**收尾包裹不属于新段**）：若误置 `cur = w`（收尾元素残留），反例 `[3,2,1]` 会在下标 2 误判可切，把答案从 1 错成 2。贪心版虽简洁，这个边界比单调栈版更易踩。

## 6. 面试要点

**Q1：为什么「以 i 收尾的装运合法」等价于「起点 s 不越过左侧最近更大元素 j(i)」？**

> 记 $j(i)$ 为左侧最近满足 $weight[j] > weight[i]$ 的下标。若 $s \le j(i)$，段内含严格更大元素，平衡；若 $s > j(i)$，由「最近」性 $(j(i), i)$ 内全部 $\le weight[i]$，段最大值恰是末尾自己，不满足严格小于。两方向合起来即充要条件，且合法起点恰为一段前缀 $[0..j(i)]$——这让「枚举最优起点」退化为查一次 $f[j(i)-1]$。

**Q2：转移为什么是 f[j-1]+1 而不是 f[j]+1？差在这一格会怎样？**

> 新装运 $[s..i]$ 要求 $s \le j(i)$，此前的装运必须整体落在 $[0..s-1] \subseteq [0..j(i)-1]$ 内；而 $f[j(i)]$ 的最优解可能包含一条**以 $j(i)$ 收尾**的装运，与新区间在下标 $j(i)$ 重叠。反例 `[5,2,1]`：正确答案 1，误用 $f[j]+1$ 得 2（`[5,2]`、`[2,1]` 共用下标 1）。口诀：**切在哪，前缀就断在哪的前一格**。

**Q3：单调栈为什么是对的？弹掉的元素之后还用得到吗？**

> 栈内下标对应重量严格递减。处理 $i$ 时弹出所有 $weight[\text{top}] \le weight[i]$ 者：它们对 $i$ 不满足「严格更大」，对 $i$ 之后的下标 $k$ 同样不可能成为「左侧最近更大」——因为 $i$ 比它们更近且 $weight[i] \ge weight[\text{top}]$，最近的候选轮不到它们。所以弹掉不影响任何后续查询，每个元素进出栈各一次，均摊 $O(1)$。

**Q4：为什么 f 一定单调不减？转移里哪里用到了这一点？**

> $f[i] \ge f[i-1]$ 由定义直接成立：前缀 $[0..i-1]$ 的任意方案也是 $[0..i]$ 的合法方案（包裹 $i$ 留空即可）。单调性用在「合法起点是一段前缀」时取最优：$\max_{s \le j(i)} f[s-1] = f[j(i)-1]$，免去了对 $s$ 的显式枚举。

**Q5：贪心「能切就切」为什么不会切亏？什么情况下它比 DP 更易错？**

> 交换论证：贪心第一刀切在最早可切点 $i_0$，任何最优解的第一段终点 $e \ge i_0$（$e$ 本身就是可切点），替换后剩余材料只多不少，归纳可证不劣。易错点在**切段边界**：收尾包裹属于旧段、新段从下一格开始，`cur` 清零若写成保留旧值，会在相邻递减序列（如 `[3,2,1]`）上多切一刀；DP 版把边界显式写进 $f[j-1]$，反而不容易错。

> 💡 **一句话总结**：把「末尾严格小于段内最大值」翻译成「起点不越过左侧最近更大元素 $j(i)$」，DP $f[i]=\max(f[i-1],\,f[j(i)-1]+1)$ 配单调栈一趟线性求解；两处 ±1（$f[j-1]$ 与弹栈 `<=`）是全题的命门。
