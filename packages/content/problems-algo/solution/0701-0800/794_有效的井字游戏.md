# LeetCode 有效的井字游戏 题解

## 1. 题目概述

- **标题 / 题号**：有效的井字游戏（#794，medium）
- **链接**：https://leetcode.cn/problems/valid-tic-tac-toe-state/
- **难度**：中等
- **标签**：数组、字符串、数学

**题意**：给定一个用字符串数组 `board` 表示的 $3 \times 3$ 井字棋棋盘，每个元素是长度为 3 的字符串，字符为 `'X'`、`'O'` 或 `' '`（空格）。判定该棋盘**是否可能**是某个合法对局的局面。

合法对局规则：

1. **X 先手**，双方轮流落子；
2. 每次只能在空格上落子，不能覆盖已有棋子；
3. 一旦某方在**行、列、对角线**上率先连成三子，游戏**立即终止**。

> ⚠️ 关键点不是「模拟一局棋」，而是「**判定一个终局/中间局面是否自洽**」——只要存在某种合法落子序列能走到该局面即为 `true`，无需构造该序列。

**示例 1**：

```text
输入：board = ["O  ","   ","   "]
输出：false
解释：X 先手，O 的数量不可能多于 X。
```

**示例 2**：

```text
输入：board = ["XOX"," X ","   "]
输出：false
解释：xCount=3, oCount=1，差为 2，违反轮流落子规则。
```

**示例 3**：

```text
输入：board = ["XXX","   ","OOO"]
输出：false
解释：X 与 O 均三连胜，但 X 先达成即应终止，O 无机会补三连。
```

**约束**：

- `board.length == 3`
- `board[i].length == 3`
- `board[i][j]` 为 `'X'`、`'O'` 或 `' '`

> 💡 棋盘固定 $3 \times 3$，所有判定都是 $O(1)$。考点在于**把游戏规则翻译成可判定的不变式**，而非搜索或模拟。

## 2. 解题思路

### 2.1 暴力思路：模拟/回放所有对局？

最直白的做法：枚举所有可能的落子序列（X、O 交替，9 步内），看是否能生成给定棋盘。9 个格子的排列约 $9! = 362880$ 种，对每个局面做匹配，能过但**极不优雅**——既未利用规则的结构，也无法推广到更大棋盘。

> 💡 暴力法的失败提示我们：**棋盘是否合法，取决于它是否违反任何一条游戏规则导出的不变式**。与其构造序列，不如直接检验「不变式是否全部成立」——这是「判定问题」的通用思路：找充分必要条件，一次扫描定论。

### 2.2 核心观察：三条不变式

![核心观察：合法棋盘必须同时满足三条不变式](../images/tictactoe_concept.svg)

设 `xCount`、`oCount` 分别为棋盘上 X、O 的数量。由游戏规则可推出三条**必须同时成立**的不变式：

#### 不变式①：轮次交替

X 先手且双方轮流落子，所以**任意时刻** X 的数量要么等于 O（轮到 X 落子前），要么比 O 多 1（X 刚落子）：

$$\text{xCount} == \text{oCount} \quad \text{或} \quad \text{xCount} == \text{oCount} + 1$$

> 等价表述：`oCount == xCount` 或 `oCount == xCount - 1`。不满足此关系一定非法（如示例 1、2）。

#### 不变式②：不可同时获胜

游戏在**先达成三连的一方**落子后立即终止，败方**没有机会再落子**，更不可能补出自己的三连。因此：

$$\text{X 三连} \quad \text{与} \quad \text{O 三连} \quad \text{不可能同时成立}$$

> 示例 3 `["XXX","   ","OOO"]` 中 X、O 各占一行三连，看似自洽，但 X 先连成时游戏已结束，O 的三连不可能出现 → 非法。

#### 不变式③：获胜方 = 刚落子方

终结局面是**获胜方那一手**造成的，所以获胜方的棋子数必须反映「它刚下完」：

- **X 胜** ⇒ 最后一手是 X ⇒ $\text{xCount} == \text{oCount} + 1$
- **O 胜** ⇒ 最后一手是 O ⇒ $\text{xCount} == \text{oCount}$

> 💡 **不变式②其实是③的推论**：若 X、O 同时三连，按③需 `xCount == oCount+1`（X 胜）又需 `xCount == oCount`（O 胜），两者矛盾，故必有一假。代码中甚至无需显式判「双赢」——两条③的校验互斥，自动排除该情况。

### 2.3 算法流程图

![算法流程：先校轮次，再校胜负归属](../images/tictactoe_algorithm_flow.svg)

判定分两层：

1. **轮次校验**（不变式①）：统计 `xCount`、`oCount`，若 `oCount ∉ {xCount, xCount-1}` → 直接 `false`。
2. **胜负校验**（不变式③，含②）：
   - 计算 `xWin = win('X')`、`oWin = win('O')`（检查 8 条线：3 行 + 3 列 + 2 对角线）。
   - 若 `xWin` 且 `xCount != oCount + 1` → `false`。
   - 若 `oWin` 且 `xCount != oCount` → `false`。
3. **其余通过** → `true`（无胜负时只要轮次正确即合法，中间局面也允许）。

> ⚠️ **为何不显式判「双赢」？** 若 `xWin && oWin`，则③的两条校验同时触发：需 `xCount == oCount+1` 且 `xCount == oCount`，矛盾 → 必然走到某一条 `return false`。把②折叠进③，代码更短且不易遗漏。

### 2.4 示例演算

![示例演算：两组非法 + 一组合法](../images/tictactoe_example_walkthrough.svg)

| 棋盘 | xCnt | oCnt | 轮次① | xWin | oWin | 胜负③ | 结论 |
|------|------|------|-------|------|------|-------|------|
| `["O  ","   ","   "]` | 0 | 1 | ✗（O 多于 X） | — | — | — | `false` |
| `["XOX"," X ","   "]` | 3 | 1 | ✗（差 2） | — | — | — | `false` |
| `["XXX","   ","OOO"]` | 3 | 3 | ✓ | ✓ | ✓ | ✗（X 胜需 +1，O 胜需相等，矛盾） | `false` |
| `["XOX","OXO","XOX"]` | 5 | 4 | ✓（差 1） | ✓（主对角） | ✗ | ✓（X 胜且 `5 == 4+1`） | `true` |

> 💡 注意第四组 `["XOX","OXO","XOX"]`：主对角线 `(0,0)-(1,1)-(2,2)` 全为 X，X 获胜；`xCount=5 == oCount+1=5`，满足③ → 合法。这是「终局且 X 胜」的典型合法局面。

## 3. 参考代码

### C++

```cpp
// 794. 有效的井字游戏 —— 三条不变式一次扫描判定
// 编译: g++ -O2 -std=c++17 valid_tictactoe.cpp -o vttt
#include <vector>
#include <string>
using namespace std;

class Solution {
    // 判定 player 是否已在 8 条线（3 行 + 3 列 + 2 对角线）上连成三子
    bool win(const vector<string>& b, char p) {
        for (int i = 0; i < 3; ++i) {
            if (b[i][0] == p && b[i][1] == p && b[i][2] == p) return true; // 行
            if (b[0][i] == p && b[1][i] == p && b[2][i] == p) return true; // 列
        }
        if (b[0][0] == p && b[1][1] == p && b[2][2] == p) return true;     // 主对角
        if (b[0][2] == p && b[1][1] == p && b[2][0] == p) return true;     // 副对角
        return false;
    }

  public:
    bool validTicTacToe(vector<string>& board) {
        int xcnt = 0, ocnt = 0;
        for (const auto& row : board)
            for (char c : row) {
                if (c == 'X')      ++xcnt;
                else if (c == 'O') ++ocnt;
            }

        // 不变式①：轮次交替，O 数量只能是 xcnt 或 xcnt-1
        if (ocnt != xcnt && ocnt != xcnt - 1) return false;

        // 不变式③（含②）：获胜方必为刚落子方
        if (win(board, 'X') && xcnt != ocnt + 1) return false;
        if (win(board, 'O') && xcnt != ocnt)     return false;
        return true;
    }
};
```

### Python

```python
class Solution:
    def validTicTacToe(self, board: list[str]) -> bool:
        xcnt = sum(r.count('X') for r in board)
        ocnt = sum(r.count('O') for r in board)

        def win(p: str) -> bool:
            # 3 行 + 3 列
            for i in range(3):
                if all(board[i][j] == p for j in range(3)):
                    return True
                if all(board[j][i] == p for j in range(3)):
                    return True
            # 2 对角线
            if all(board[i][i] == p for i in range(3)):
                return True
            if all(board[i][2 - i] == p for i in range(3)):
                return True
            return False

        # 不变式①
        if ocnt not in (xcnt, xcnt - 1):
            return False
        # 不变式③（含②）
        if win('X') and xcnt != ocnt + 1:
            return False
        if win('O') and xcnt != ocnt:
            return False
        return True
```

> ⚠️ **三个易错点**：
> 1. **轮次判断方向**：是 `ocnt ∈ {xcnt, xcnt-1}`，不是 `xcnt ∈ {ocnt, ocnt+1}` 的反面——两者等价，但写成「O 的数量不超过 X 且差不超过 1」更不易写反。常见错误是写成 `xcnt != ocnt && xcnt != ocnt + 1`，逻辑相同但容易把 `&&` 和 `||` 搞混。
> 2. **空格也是合法字符**：`board[i]` 含空格 `' '`，统计时只数 `'X'`/`'O'`，不要误把空格当 O（如用 `row.count('O')` 没问题，但若遍历字符忘了排除空格会出错）。
> 3. **别显式判双赢**：很多人会多写一句 `if xw and ow: return False`，虽不算错但冗余——③的两条校验已互斥地覆盖此情况。理解这点能更深地把握「不变式③蕴含②」的结构。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(1)$ | 棋盘固定 $3 \times 3 = 9$ 格，统计与 8 条线判定均为常数次字符比较 |
| 空间复杂度 | $O(1)$ | 仅几个计数与布尔变量 |

> 💡 严格来说是 $O(mn)$，其中 $m=n=3$ 为常数，故退化为 $O(1)$。即便推广到 $n \times n$ 棋盘，复杂度也仅 $O(n^2)$（统计）+ $O(n)$（每条线 $n$ 格，共 $2n+2$ 条线），仍非常高效。

## 5. 扩展：为什么不需要构造落子序列？

一个自然的疑问：满足三条不变式就**一定**存在合法落子序列吗？会不会出现「不变式都成立但实际走不到」的反例？

> 💡 **结论**：对 $3 \times 3$ 井字棋，三条不变式是合法性的**充分必要条件**。这是井字棋的一个经典结论，证明思路是构造性回填——按某种顺序（如从少到多）补落子，可证明不变式成立时总能补出合法序列。本题的官方判定正是基于此。

直观理解：

1. **轮次正确**保证了「棋子总数对应某个合法步数」。
2. **胜负归属正确**保证了「终局那一手确实由获胜方下，且败方之后没再下」。
3. **没有双赢**保证了「没有两个矛盾的同时终局」。

这三条合起来排除了所有「规则层面」的矛盾，剩余的中间局面总是可达的（因为没有任何规则限制「某格必须先于另一格下」，只要数量和胜负关系对得上，总能安排顺序）。

> ⚠️ 此充分性**不显然**，且对更复杂的规则（如禁手、连珠要求 5 子）可能不成立。但对标准 $3 \times 3$ 井字棋，这是公认结论，可作为结论使用。

## 6. 面试要点

1. **为什么不用模拟/搜索所有落子序列？**

   > 棋盘固定 $3 \times 3$，模拟虽能过（$9!$ 量级），但既慢又错失考点。本题考的是「**把游戏规则翻译成不变式**」的判定思维——找充分必要条件，一次扫描定论，$O(1)$ 解决。这是「判定问题」的通用范式：与其构造，不如检验。

2. **三条不变式分别从哪条规则推出？**

   > ①轮次交替 ← 「X 先手 + 双方轮流」；②不可双赢 ← 「先达成三连即终止」；③获胜方=刚落子方 ← 「终局那一手属获胜方」。三者层层递进：①管数量关系，②管胜负共存性，③管胜负与数量的对应。且②是③的推论（③的两条校验互斥即排除双赢）。

3. **为什么不显式判「X 和 O 同时三连」？**

   > 因为不变式③已隐含此判定：若 X、O 同时三连，则需 `xCount == oCount+1`（X 胜）又需 `xCount == oCount`（O 胜），矛盾，必有一条校验失败。显式判虽不算错但冗余，理解「③蕴含②」能让代码更短、思路更清晰。

4. **`win` 函数要检查哪些线？**

   > 共 8 条：3 行（每行 3 格同字符）、3 列、2 对角线（主对角 `(0,0)-(1,1)-(2,2)`、副对角 `(0,2)-(1,1)-(2,0)`）。注意副对角的下标规律是 `(i, 2-i)`，常被误写成 `(i, i-2)` 或漏掉。$n \times n$ 推广时仍是 $2n+2$ 条线。

5. **如果棋盘上出现非法字符或格子数不对怎么办？**

   > 本题约束保证 `board` 恒为 3 个长度 3 的字符串、字符仅 `'X'/'O'/' '`，无需额外校验。若推广到健壮实现，可加输入校验：长度、字符集、空格数非负等。但 LeetCode 判题不要求，加了反而冗余。

> 💡 **一句话总结**：794 是「**规则翻译成不变式**」的招牌题——三条不变式（轮次交替、不可双赢、获胜方=刚落子方）一次扫描判定，$O(1)$ 时空。核心洞察是②③互斥折叠：双赢被胜负归属校验自动排除，无需显式判断。
