# LeetCode 不同国家的天气类型 题解

## 1. 题目概述

- **标题 / 题号**：不同国家的天气类型（#1294，easy）
- **链接**：https://leetcode.cn/problems/weather-type-in-each-country/
- **难度**：简单
- **标签**：数据库、SQL、JOIN、CASE WHEN、WHERE 过滤

**题意**：给定两张表：`Countries`（国家）和 `Weather`（天气记录）。编写 SQL 查询，找出 **2019-11-15** 当天每个国家的**天气类型**，返回 `country_name` 和 `weather_type` 两列。

天气类型按 `weather_state` 分三档：

| weather_state 范围 | weather_type |
|--------------------|--------------|
| $\leq 15$ | `Cold` |
| $\geq 30$ | `Hot` |
| $15 < \text{weather\_state} < 30$ | `Warm` |

**表结构**：

```text
Table: Countries
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| country_id  | int     |  ← 主键
| country_name| varchar |
+-------------+---------+

Table: Weather
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| country_id    | int     |  ← 与 day 联合主键
| weather_state | int     |
| day           | date    |
+---------------+---------+
```

- `Countries.country_id` 是主键。
- `Weather` 表的 `(country_id, day)` 是联合主键——同一国家每天最多一条天气记录。
- `Weather.country_id` 是指向 `Countries.country_id` 的外键。

**示例 1**：

```text
输入：
Countries 表：
+------------+--------------+
| country_id | country_name |
+------------+--------------+
| 2          | USA          |
| 3          | Australia    |
| 7          | Peru         |
| 5          | China        |
| 8          | Morocco      |
| 9          | Spain        |
+------------+--------------+

Weather 表（节选）：
+------------+---------------+------------+
| country_id | weather_state | day        |
+------------+---------------+------------+
| 2          | 15            | 2019-11-01 |
| 2          | 12            | 2019-10-28 |
| 3          | -2            | 2019-11-10 |
| 5          | 16            | 2019-11-07 |
| 8          | 25            | 2019-11-05 |
| 8          | 27            | 2019-11-15 |
| 8          | 31            | 2019-11-25 |
| 9          | 7             | 2019-10-23 |
| ...        | ...           | ...        |
+------------+---------------+------------+

输出：
+--------------+--------------+
| country_name | weather_type |
+--------------+--------------+
| Morocco      | Warm         |
+--------------+--------------+
```

**解释**：在 `2019-11-15` 当天，只有 `Morocco`（country_id=8）有天气记录，`weather_state = 27`。由于 $15 < 27 < 30$，归类为 `Warm`。其余国家在该日没有天气记录，不出现在结果中。

> 💡 本题是 SQL **「JOIN + CASE WHEN 区间映射」** 的入门招牌题。核心只有三步：`WHERE` 过滤到指定日期、`JOIN` 补上国家名、`CASE WHEN` 把数值区间映射为字符串标签。无需聚合（每个国家该日只有一条记录），逐行分类即可。

**约束**：

- `weather_state` 为整数，可能为负值（如澳大利亚 `-2`）
- `day` 为 `date` 类型，查询固定为 `'2019-11-15'`
- 结果只包含当天有天气记录的国家；当天无记录的国家不输出

## 2. 解题思路

### 2.1 暴力思路：逐国家查找

最直觉的过程式思路：遍历 `Countries` 表的每个国家，拿它的 `country_id` 去 `Weather` 表里找 `day = '2019-11-15'` 的记录；找到就读出 `weather_state`，用 if-else 判断属于 Cold/Hot/Warm 哪一档，输出 `country_name` 和分类结果。

```text
for each country in Countries:
    row = Weather[country_id == country.id AND day == '2019-11-15']
    if row 不存在: continue
    if row.weather_state <= 15: type = 'Cold'
    elif row.weather_state >= 30: type = 'Hot'
    else: type = 'Warm'
    output(country.country_name, type)
```

但**纯 SQL 没有显式逐行循环**——「按国家关联天气记录再分类」需换成集合式表达：一次 `JOIN` 把两表按 `country_id` 拼接，`WHERE` 过滤日期，`CASE WHEN` 逐行做区间映射。这正是关系代数中 **θ-join（等值连接）+ 选择 + 投影** 的标准组合。

### 2.2 核心观察：JOIN + CASE WHEN 区间映射

![核心思路：WHERE 过滤日期 + JOIN 关联国家 + CASE WHEN 分类](../images/weather_type_concept.svg)

**三个关键点**：

1. **`WHERE day = '2019-11-15'` 先过滤再 JOIN**：`Weather` 表存了多日多国的记录，但题目只关心一天。先用 `WHERE` 把行集缩到当天，再做 `JOIN`，既正确又高效——参与连接的行数最少。

2. **`JOIN Countries ON country_id` 补国家名**：`Weather` 表只有 `country_id`，题目要输出 `country_name`，必须关联 `Countries` 表。用 `INNER JOIN`（默认）即可——当天无记录的国家自然不会出现在连接结果里。

3. **`CASE WHEN` 把数值区间映射为字符串标签**：

   $$
   \text{weather\_type} = \begin{cases} \text{Cold} & \text{if } \text{weather\_state} \leq 15 \\ \text{Hot} & \text{if } \text{weather\_state} \geq 30 \\ \text{Warm} & \text{otherwise} \end{cases}
   $$

   `CASE WHEN` 的分支按顺序求值，命中即返回。两条边界分支写在前，`ELSE 'Warm'` 兜底中间区间，逻辑清晰无遗漏。

> 💡 **为什么不需要 `GROUP BY`？** `(country_id, day)` 是联合主键，同一国家同一天最多一条记录。`WHERE day = '2019-11-15'` 后每个国家至多一行，不存在「同国家多行需合并」的情况，自然不需要聚合。这是本题比 [1211. 查询结果的质量和占比](1211_查询结果的质量和占比.md)（需 `GROUP BY` + `AVG`）更简单的根本原因。

> ⚠️ **边界归属**：`weather_state = 15` 归 `Cold`，`weather_state = 30` 归 `Hot`，中间值（$15 < x < 30$）归 `Warm`。`CASE WHEN` 的分支顺序保证边界值被正确捕获——先判 `≤ 15` 再判 `≥ 30`，两者都不命中才走 `ELSE`。

### 2.3 算法流程图

![SQL 执行流程：WHERE 过滤 → JOIN → CASE WHEN 分类](../images/weather_type_flow.svg)

**逻辑执行步骤**：

| 步骤 | SQL 子句 | 作用 |
|------|----------|------|
| ① | `FROM Weather WHERE day = '2019-11-15'` | 只保留当天的天气记录，缩小行集 |
| ② | `JOIN Countries ON country_id` | 用 `country_id` 关联到 `country_name` |
| ③ | `CASE WHEN ... THEN ... END` | 把 `weather_state` 区间映射为 Cold/Hot/Warm |
| ④ | `SELECT country_name, weather_type` | 投影输出两列 |

> 💡 **SQL 子句执行顺序**：`FROM`（含 `WHERE`）→ `JOIN` → `SELECT`（含 `CASE WHEN`）→ `ORDER BY` → `LIMIT`。`WHERE` 在 `JOIN` **前**先过滤 `Weather`，减少参与连接的行数；`CASE WHEN` 在 `SELECT` 阶段对连接后的每一行做分类。

> ⚠️ **`WHERE` 过滤的位置**：如果把 `day = '2019-11-15'` 写在 `JOIN ... ON` 的连接条件里（`ON W.country_id = C.country_id AND W.day = '2019-11-15'`），对 `INNER JOIN` 而言效果等价。但写在 `WHERE` 中语义更清晰——「先过滤日期，再关联国家」，也便于将来改成 `LEFT JOIN`（求所有国家当天天气，无记录则天气类型为 NULL）时行为可控。

### 2.4 示例演算

以示例 1 数据为例，观察从全表到最终输出的完整流程：

![示例演算：过滤 → JOIN → CASE 分类](../images/weather_type_walkthrough.svg)

**第一步：`WHERE day = '2019-11-15'` 过滤 Weather**

`Weather` 表共 17 行（多日多国），过滤后只剩 1 行：

| country_id | weather_state | day |
|------------|---------------|-----|
| 8 | 27 | 2019-11-15 |

> ⚠️ 只有 Morocco（country_id=8）在 2019-11-15 有记录。其余国家当天没有天气数据，不会进入后续流程。

**第二步：`JOIN Countries ON country_id`**

用 `country_id = 8` 关联 `Countries` 表，补上国家名：

| country_name | weather_state | day |
|--------------|---------------|-----|
| Morocco | 27 | 2019-11-15 |

**第三步：`CASE WHEN` 分类**

对 `weather_state = 27` 逐一判断分支：

| 判断 | 结果 |
|------|------|
| $27 \leq 15$？ | 否 |
| $27 \geq 30$？ | 否 |
| `ELSE` | → `Warm` |

**第四步：输出**

| country_name | weather_type |
|--------------|--------------|
| Morocco | Warm |

> 💡 **如果当天有多个国家有记录呢？** 比如 2019-11-15 同时有 Morocco(27)、USA(12)、Spain(35)，则输出三行：Morocco→Warm、USA→Cold、Spain→Hot。每行独立用 `CASE WHEN` 分类，互不影响——这就是「逐行映射」的本质。

## 3. 参考代码

### MySQL（解法 A：WHERE + INNER JOIN + CASE WHEN，推荐）

```sql
# 1294. 不同国家的天气类型
# 思路：WHERE 过滤到 2019-11-15 → JOIN Countries 补国家名 → CASE WHEN 区间映射
SELECT
    c.country_name,
    CASE
        WHEN w.weather_state <= 15 THEN 'Cold'
        WHEN w.weather_state >= 30 THEN 'Hot'
        ELSE 'Warm'
    END AS weather_type
FROM Weather w
JOIN Countries c ON w.country_id = c.country_id
WHERE w.day = '2019-11-15';
```

> 💡 **写法要点**：
> - **`WHERE w.day = '2019-11-15'`**：先过滤 `Weather` 到当天，再做 `JOIN`，减少连接行数。
> - **`JOIN Countries c ON w.country_id = c.country_id`**：`INNER JOIN`（`JOIN` 默认即内连接），用 `country_id` 关联国家名。当天无记录的国家不会出现在结果中。
> - **`CASE WHEN ... END AS weather_type`**：两边界分支 + `ELSE` 兜底。`≤ 15`→Cold，`≥ 30`→Hot，其余→Warm。分支按顺序求值，命中即返回。
> - **表别名 `w`/`c`**：`Weather w`、`Countries c`，引用列时写 `w.weather_state`、`c.country_name`，避免列名歧义。

### MySQL（解法 B：过滤条件放进 ON 子句）

```sql
SELECT
    c.country_name,
    CASE
        WHEN w.weather_state <= 15 THEN 'Cold'
        WHEN w.weather_state >= 30 THEN 'Hot'
        ELSE 'Warm'
    END AS weather_type
FROM Countries c
JOIN Weather w
    ON w.country_id = c.country_id
    AND w.day = '2019-11-15';
```

> 💡 **与解法 A 的区别**：把 `day = '2019-11-15'` 从 `WHERE` 移到 `JOIN ... ON` 的连接条件里。对 `INNER JOIN` 而言两者完全等价——优化器会生成相同的执行计划。区别仅在语义表达：解法 A 强调「先过滤再连接」，解法 B 强调「连接条件包含日期匹配」。推荐解法 A 的写法，`WHERE` 与 `ON` 职责分离更清晰。

### Python（pandas）

```python
import pandas as pd

def weather_type(countries: pd.DataFrame, weather: pd.DataFrame) -> pd.DataFrame:
    w = weather[weather['day'] == '2019-11-15']
    merged = w.merge(countries, on='country_id', how='inner')
    merged['weather_type'] = merged['weather_state'].apply(
        lambda s: 'Cold' if s <= 15 else ('Hot' if s >= 30 else 'Warm')
    )
    return merged[['country_name', 'weather_type']]
```

> 💡 **pandas 对照**：
> - `weather['day'] == '2019-11-15'` 对应 `WHERE day = '2019-11-15'`。
> - `merge(countries, on='country_id', how='inner')` 对应 `JOIN Countries ON country_id`（内连接）。
> - `apply(lambda s: ...)` 对应 `CASE WHEN` 区间映射：`<= 15`→Cold、`>= 30`→Hot、其余→Warm。
> - 返回 `[['country_name', 'weather_type']]` 对应 `SELECT` 投影两列。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | $O(N + M)$ | $N$ = `Weather` 行数，$M$ = `Countries` 行数；扫描 `Weather` 过滤 $O(N)$ + 哈希连接 $O(M)$（`country_id` 有索引时）|
| **空间** | $O(K + M)$ | $K$ = 当天有记录的国家数（过滤后行集），$M$ = `Countries` 哈希表 |
| **排序开销** | 无 | 题目不要求排序，结果任意顺序 |

> ⚠️ 若 `Weather(day)` 上无索引，`WHERE day = '2019-11-15'` 需全表扫描 $O(N)$；建索引后可降为 $O(\log N + K)$。`country_id` 作为外键通常有索引，`JOIN` 走索引嵌套循环或哈希连接，效率高。

## 5. 扩展：CASE WHEN 的区间映射模式

### 5.1 CASE WHEN 两种形式

`CASE WHEN` 有两种语法，本题用的是**搜索型 `CASE`**（按条件表达式匹配）：

```sql
-- 搜索型 CASE（本题用法）：按条件表达式分支
CASE
    WHEN weather_state <= 15 THEN 'Cold'
    WHEN weather_state >= 30 THEN 'Hot'
    ELSE 'Warm'
END

-- 简单型 CASE：按单值等值匹配
CASE weather_state
    WHEN 15 THEN 'Cold-exact'
    WHEN 30 THEN 'Hot-exact'
    ELSE 'Other'
END
```

> 💡 **区间映射只能用搜索型 `CASE`**：简单型 `CASE` 只做等值匹配（`=`），无法表达 `≤`、`≥`、`BETWEEN` 等区间条件。区间分类必须用搜索型 `CASE WHEN <条件表达式>`。

### 5.2 分支顺序的重要性

`CASE WHEN` 的分支**按书写顺序求值，命中即返回**，不会继续判断后续分支。因此分支顺序影响边界归属：

| 写法 | `weather_state = 15` 归属 | `weather_state = 30` 归属 |
|------|--------------------------|--------------------------|
| 先 `≤ 15` 再 `≥ 30` | Cold ✓ | Hot ✓ |
| 先 `≥ 30` 再 `≤ 15` | Cold ✓ | Hot ✓ |
| 先 `> 30` 再 `< 15`（无边界） | Warm ✗ | Warm ✗ |

> ⚠️ 本题两个边界区间不重叠（`≤ 15` 与 `≥ 30` 互斥），分支顺序不影响结果。但当区间有重叠（如 `≤ 20` 与 `≥ 15`）时，顺序决定边界值的归属，需格外小心。

### 5.3 相关变体题

| 变体 | 需求 | 关键差异 |
|------|------|----------|
| **1294（本题）** | 当天天气类型 | `WHERE` + `JOIN` + `CASE WHEN`，无聚合 |
| 按月统计天气类型 | 每国每月天气类型 | 加 `GROUP BY country, month` + 聚合 `AVG(weather_state)` 后再 `CASE` |

## 6. 面试要点

1. **为什么用 `INNER JOIN` 而不是 `LEFT JOIN`？**

   > 题目要求找出「2019-11-15 当天有天气记录的国家」的天气类型。`INNER JOIN` 只保留两表都匹配的行——当天无记录的国家在 `Weather` 过滤后不存在，自然不会出现在连接结果中。若改用 `LEFT JOIN`（以 `Countries` 为左表），当天无记录的国家也会输出一行 `country_name` + `NULL` 天气类型，与题意不符。

2. **`WHERE` 过滤和 `JOIN ... ON` 过滤有什么区别？**

   > 对 `INNER JOIN` 两者完全等价——优化器生成相同执行计划。语义上，`WHERE` 强调「行级过滤」（先筛再连），`ON` 强调「连接条件」（连接时匹配）。但对 `LEFT JOIN` 两者行为不同：`ON` 中的过滤条件不影响左表行是否保留（左表行始终保留，右表不匹配则填 NULL），而 `WHERE` 中的过滤会剔除整行。本题用 `INNER JOIN` 故无区别，推荐 `WHERE` 写法以保持职责清晰。

3. **`CASE WHEN` 的分支顺序重要吗？**

   > 重要。`CASE WHEN` 按书写顺序求值，命中即返回。本题两个边界分支 `≤ 15` 与 `≥ 30` 互斥，顺序不影响结果。但当区间有重叠时，顺序决定边界值归属。习惯上把更严格的条件或特殊边界写在前，`ELSE` 兜底通用情况。

4. **为什么不需要 `GROUP BY`？**

   > `(country_id, day)` 是 `Weather` 的联合主键，同一国家同一天最多一条记录。`WHERE day = '2019-11-15'` 后每个国家至多一行，不存在「同国家多行需合并」的场景，因此不需要 `GROUP BY` 聚合。`CASE WHEN` 直接对每行做逐行映射即可。若题目改为「统计每国该月平均天气类型」，则需 `GROUP BY` + `AVG(weather_state)` 后再 `CASE`。

5. **如果 `weather_state` 可能为 NULL 怎么办？**

   > `CASE WHEN` 中任何与 `NULL` 的比较（`<= 15`、`>= 30`）都返回 `NULL`（既非真也非假），两个分支都不命中，最终走 `ELSE 'Warm'`。这会把缺失数据误判为 Warm。若需正确处理，应加显式判断：`WHEN w.weather_state IS NULL THEN NULL` 放在最前面，或用 `WHERE w.weather_state IS NOT NULL` 过滤掉缺失行。

> 💡 **一句话总结**：1294 是 SQL **「JOIN + CASE WHEN 区间映射」入门招牌题**——核心就三步：`WHERE day = '2019-11-15'` 过滤当天、`JOIN Countries` 补国家名、`CASE WHEN` 把 `weather_state` 数值区间映射为 Cold/Hot/Warm 字符串标签。无需聚合（主键保证每日每国一行），逐行分类即可。掌握 `CASE WHEN` 的区间映射模式，所有「数值分档转标签」的 SQL 题都能套用。
