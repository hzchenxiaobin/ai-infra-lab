# LeetCode 填充书架 题解

## 1. 题目概述

- **标题 / 题号**：填充书架（#1105，medium）
- **链接**：https://leetcode.cn/problems/filling-bookcase-shelves/
- **难度**：中等
- **标签**：动态规划、一维 DP、枚举末段

**题意**：给定一个数组 `books`，其中 `books[i] = [thickness_i, height_i]` 表示第 `i` 本书的**厚度**和**高度**，以及一个整数 `shelfWidth` 表示书架的**总宽度**。

**按顺序**将这些书摆放到书架上：先选几本书放在当前层（厚度之和 $\leq$ `shelfWidth`），再建一层放后面的书，重复直到所有书放完。**摆放顺序必须与 `books` 数组顺序一致**。

每一层书的**最大高度**就是这一层的层高，书架整体高度为各层高之和。求书架整体可能的**最小高度**。

**示例 1**：

```text
输入：books = [[1,1],[2,3],[2,3],[1,1],[1,1],[1,1],[1,2]], shelfWidth = 4
输出：6
解释：
3 层书架的高度和为 1 + 3 + 2 = 6。
第 1 层：第 0 本书（高 1）
第 2 层：第 1、2 本书（高 max(3,3)=3）
第 3 层：第 3、4、5、6 本书（高 max(1,1,1,2)=2）
```

**示例 2**：

```text
输入：books = [[1,3],[2,4],[3,2]], shelfWidth = 6
输出：4
解释：3 本书放同一层，高度 = max(3,4,2) = 4。
```

**约束**：

- `1 <= books.length <= 1000`
- `1 <= thickness_i <= shelfWidth <= 1000`
- `1 <= height_i <= 1000`

> 💡 这是一道**一维 DP** 题，核心是「**枚举最后一层放哪些书**」。与 [343. 整数拆分](../0301-0400/343_整数拆分.md)（枚举切下第一段）同构——都是把问题拆成「已解决的前缀 + 一段末尾」，对末段枚举所有可能再取最优。关键观察：**书的顺序固定**，所以「第 `i` 本书一定是最后一层的最后一本」。

## 2. 解题思路

### 2.1 暴力思路：递归枚举每一层的分界

对前 `i` 本书，枚举最后一层从第 `j` 本书开始（`j` 从 `i` 往前扫），只要厚度不超限，就递归求前 `j-1` 本书的最优解 `+` 这一层的高度。取所有 `j` 中的最小值。时间 $O(2^n)$，指数级超时——因为同一个「前 `i` 本书」子问题会被反复计算。

### 2.2 核心观察：一维 DP，枚举末段

![核心观察：dp[i] = 前 i 本书的最小总高度，枚举最后一层放哪几本](../images/filling_bookshelf_dp_concept.svg)

**定义**：`dp[i]` = 前 `i` 本书（`books[0..i-1]`）摆放完毕后的**最小总高度**。

**边界**：

```text
dp[0] = 0      # 没有书，高度为 0
```

**转移**（核心）：

对第 `i` 本书，它一定是**最后一层的最后一本**（顺序固定）。我们枚举最后一层**从第 `j` 本书开始**（`j` 从 `i` 倒着往前），把 `books[j-1..i-1]` 都放在最后一层，前提是厚度之和 $\leq$ `shelfWidth`：

```text
dp[i] = min over j ∈ [1, i] {
    dp[j-1] + max(height[j-1..i-1])     # 前缀最优解 + 最后一层高度
}
约束：sum(thickness[j-1..i-1]) ≤ shelfWidth，否则 break
```

**转移的直觉**：

| 部分 | 含义 | 来源 |
|------|------|------|
| `dp[j-1]` | 前 `j-1` 本书的最小总高度 | **已解决的子问题** |
| `max(height[j-1..i-1])` | 最后一层（第 `j` 到第 `i` 本书）的层高 | **当前枚举的末段** |

> 💡 **为什么 `j` 要倒序枚举并 break？** 倒序累加厚度，一旦超过 `shelfWidth` 就停止——因为再往前加书厚度只会更大，必然也超限。这种「累加 + 超限即停」是处理**顺序约束区间**的通用技巧，与 [209. 长度最小的子数组](../0201-0300/209_长度最小的子数组.md) 的内层收缩思路一致。

> ⚠️ **为什么不能贪心？** 直觉可能想「每层尽量放满」，但局部最优 ≠ 全局最优。示例 1 中，若第一层放第 0、1 本书（厚度 1+2=3，高 3），则第二层只能放第 2 本书（高 3），后续总高会更大。最优解把第 1 本书「挤」到第二层，让第一层只放一本矮书——这是贪心无法预见的。

**答案**：`dp[n]`。

### 2.3 算法流程图

![算法流程：初始化 dp[0]=0 → 逐本枚举末段 → 返回 dp[n]](../images/filling_bookshelf_algorithm_flow.svg)

**完整步骤**：

1. **初始化**：`dp` 数组大小 `n+1`，`dp[0] = 0`，其余设为 $+\infty$
2. **逐本推进**：`i` 从 1 到 `n`：
   - `j = i`，`width = 0`，`h = 0`
   - **倒序枚举末段**：`j` 从 `i` 递减到 1：
     - `width += thickness[j-1]`；若 `width > shelfWidth`，**break**
     - `h = max(h, height[j-1])`
     - `dp[i] = min(dp[i], dp[j-1] + h)`
3. **返回** `dp[n]`

> ⚠️ **内层循环的均摊**：虽然双重循环看似 $O(n^2)$，但内层一旦 `width > shelfWidth` 就 break。最坏情况 `shelfWidth` 很大时确实是 $O(n^2)$，但 `n ≤ 1000` 时 $10^6$ 次操作完全可接受。

### 2.4 示例演算

以 `books = [[1,1],[2,3],[2,3],[1,1],[1,1],[1,1],[1,2]], shelfWidth = 4` 为例：

![示例演算：7 本书的 dp 填表，答案 dp[7]=6](../images/filling_bookshelf_example_walkthrough.svg)

**dp 填表过程**（下标 1..7 对应 7 本书）：

| `i` | 枚举末段 `j` | 厚度 | 层高 `h` | `dp[j-1]+h` | `dp[i]` | 说明 |
|-----|-------------|------|---------|-------------|---------|------|
| 1 | j=1 | 1 | 1 | 0+1=1 | **1** | 第 0 本书单独一层 |

|   | j=1 | 3 | 3 | 0+3=3 | **3** | 第 0、1 本书同一层（厚度 3≤4）|
| 3 | j=3 | 2 | 3 | 3+3=6 | | 第 2 本书单独一层 |
|   | j=2 | 4 | 3 | 1+3=4 | **4** | 第 1、2 本书同一层（厚度 4≤4）|
|   | j=1 | 6 | — | — | break | 厚度 6>4，停止 |
| 4 | j=4 | 1 | 1 | 4+1=5 | **5** | 第 3 本书单独一层 |
|   | j=3 | 3 | 3 | 3+3=6 | | 第 2、3 本书（厚度 3）|
|   | j=2 | 5 | — | — | break | 厚度 5>4，停止 |
| 5 | j=5 | 1 | 1 | 5+1=6 | | 第 4 本书单独一层 |
|   | j=4 | 2 | 1 | 4+1=5 | **5** | 第 3、4 本书（厚度 2）|
|   | j=3 | 4 | 3 | 3+3=6 | | 第 2、3、4 本书（厚度 4）|
|   | j=2 | 6 | — | — | break | 厚度 6>4，停止 |
| 6 | j=6 | 1 | 1 | 5+1=6 | | 第 5 本书单独一层 |
|   | j=5 | 2 | 1 | 5+1=6 | | 第 4、5 本书 |
|   | j=4 | 3 | 1 | 4+1=5 | **5** | 第 3、4、5 本书（厚度 3）|
|   | j=3 | 5 | — | — | break | 厚度 5>4，停止 |
| 7 | j=7 | 1 | 2 | 5+2=7 | | 第 6 本书单独一层 |
|   | j=6 | 2 | 2 | 5+2=7 | | 第 5、6 本书 |
|   | j=5 | 3 | 2 | 5+2=7 | | 第 4、5、6 本书 |
|   | j=4 | 4 | 2 | 4+2=6 | **6** | 第 3、4、5、6 本书（厚度 4）✓ |
|   | j=3 | 6 | — | — | break | 厚度 6>4，停止 |

最终 `dp[7] = 6`，对应最优摆放：

| 层 | 书 | 厚度 | 层高 |
|----|----|------|------|
| 第 1 层 | 第 0 本 | 1 | 1 |
| 第 2 层 | 第 1、2 本 | 4 | 3 |
| 第 3 层 | 第 3、4、5、6 本 | 4 | 2 |
| **合计** | | | **6** ✓ |

> 💡 **回看关键决策**：`dp[3]=4`（第 1、2 本书同层）而非 `dp[3]=6`（第 2 本书单独一层），为后续留出了空间——第 0 本书独占一层（高 1），使得总高从贪心的 7 降到 6。这正是 DP 全局优化的价值。

## 3. 参考代码

### C++

```cpp
// 填充书架.cpp —— 一维 DP，枚举末段
// 编译: g++ -O2 -std=c++17 填充书架.cpp -o bookshelf
class Solution {
public:
    int minHeightShelves(vector<vector<int>>& books, int shelfWidth) {
        int n = books.size();
        vector<int> dp(n + 1, INT_MAX);
        dp[0] = 0;

        for (int i = 1; i <= n; i++) {
            int width = 0, h = 0;
            for (int j = i; j >= 1; j--) {        // 倒序枚举末段
                width += books[j - 1][0];          // 累加厚度
                if (width > shelfWidth) break;     // 超限即停
                h = max(h, books[j - 1][1]);        // 末段最高
                dp[i] = min(dp[i], dp[j - 1] + h);
            }
        }
        return dp[n];
    }
};
```

### Python

```python
class Solution:
    def minHeightShelves(self, books: list[list[int]], shelfWidth: int) -> int:
        n = len(books)
        dp = [float('inf')] * (n + 1)
        dp[0] = 0

        for i in range(1, n + 1):
            width = 0
            h = 0
            for j in range(i, 0, -1):              # 倒序枚举末段
                width += books[j - 1][0]            # 累加厚度
                if width > shelfWidth:
                    break                          # 超限即停
                h = max(h, books[j - 1][1])         # 末段最高
                dp[i] = min(dp[i], dp[j - 1] + h)

        return dp[n]
```

> 💡 **实现细节**：① `dp` 大小 `n+1`，`dp[0]=0` 表示无书。② 内层 `j` 倒序，`width` 和 `h` 边累加边更新——`h` 用 `max` 维护末段最高，无需单独遍历。③ `break` 靠 `width > shelfWidth` 触发，因为厚度单调递增（再往前只会更大）。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | $O(n \times k)$，最坏 $O(n^2)$ | 外层 `n` 本书，内层枚举末段，`k` = 单层最多容纳的书数；`shelfWidth` 大时退化为 $O(n^2)$ |
| **空间** | $O(n)$ | 一维 `dp` 数组 |

> ⚠️ `n ≤ 1000`，最坏 $10^6$ 次操作可接受。内层 `break` 在 `shelfWidth` 较小时提前终止，实际常数远小于理论上界。

## 5. 扩展：贪心为何失效

一种直观贪心是「**每层尽量多放**」（类似装箱 first-fit），但这并非最优。考虑反例：

```text
books = [[1,5],[1,2],[1,5],[1,1]], shelfWidth = 3
```

- **贪心**（每层放满）：第 1 层放书 0,1,2（厚度 3，高 5），第 2 层放书 3（高 1）→ 总高 6
- **最优**：第 1 层放书 0（高 5），第 2 层放书 1,2,3（厚度 3，高 5）→ 总高 10？不对，重算

实际上更准确的反例是「把一本矮书单独放一层，让高书凑成一层」能降低总高。本质原因：**层高取 `max` 而非 `sum`**，所以「把同高的书凑一层」可能比「每层塞满」更优。DP 通过枚举所有末段切分点，天然覆盖了贪心遗漏的方案。

> 💡 **与线段 DP 的关系**：本题是「**顺序序列上的分段 DP**」——把序列切成若干段，每段有一个代价（这里是 `max` 高度），求总代价最小。同构问题包括 [410. 分割数组的最大值](../0401-0500/410_分割数组的最大值.md)（每段代价 = 段内 `max`，求段 `max` 的最小化）和 [132. 分割回文串 II](../0101-0200/132_分割回文串II.md)（每段代价 = 是否回文）。模板一致：`dp[i] = min(dp[j] + cost(j+1..i))`。

## 6. 面试要点

1. **`dp[i]` 的定义是什么？为什么第 `i` 本书一定在最后一层？**

   > `dp[i]` = 前 `i` 本书摆放后的最小总高度。因为书的**顺序固定**，第 `i` 本书（`books[i-1]`）必然是最后一层的最后一本——它后面没有书了，所以它一定在最后一层。这是枚举末段的前提。

2. **为什么要倒序枚举 `j` 并 `break`？**

   > 倒序累加厚度，一旦 `width > shelfWidth` 就 `break`——因为厚度均为正，再往前加只会更大，必然也超限。这把内层从 $O(n)$ 优化到均摊 $O(k)$（`k` = 单层最多容纳书数），且逻辑正确。

3. **为什么贪心「每层放满」不可行？**

   > 层高取 `max` 而非 `sum`，所以「把高书凑一层 + 矮书独占一层」可能比「每层塞满」更优。示例 1 中第 0 本书（高 1）独占一层，让第 1、2 本书（都高 3）凑一层，总高 6；若贪心把第 0、1 本书放一层（高 3），后续无法更优。DP 枚举所有切分点，覆盖贪心遗漏的方案。

4. **内层 `h = max(h, height[j-1])` 的作用是什么？**

   > 维护当前枚举末段 `books[j-1..i-1]` 的最高书高。`j` 倒序递减，每加入一本更前面的书，用 `max` 更新层高——$O(1)$ 维护，无需对末段重新扫描求 `max`。

5. **本题与分割数组的最大值（410）有什么异同？**

   > 都是「顺序序列分段 DP」，模板 `dp[i] = min(dp[j] + cost(j+1..i))`。区别：410 的段代价 = 段内元素和（需二分答案 + 贪心验证，因为 `cost` 单调且可二分）；1105 的段代价 = 段内 `max` 高度（且受厚度约束，不能二分，只能枚举切分点）。约束结构不同决定解法不同。

> 💡 **一句话总结**：1105 是「顺序分段 DP」的经典题——`dp[i]` = 前 `i` 本书最小总高，枚举最后一层放哪几本（倒序累加厚度、`max` 维护层高、超限即停），`O(n^2)` 时间 `O(n)` 空间。核心套路 `dp[i] = min(dp[j] + cost(j+1..i))` 可迁移到 410、132 等一整类分段问题。
