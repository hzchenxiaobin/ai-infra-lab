# LeetCode IP 地址无效化 题解

## 1. 题目概述

- **标题 / 题号**：IP 地址无效化（#1108，easy）
- **链接**：https://leetcode.cn/problems/defanging-an-ip-address/
- **难度**：简单
- **标签**：字符串

**题意**：给你一个有效的 [IPv4](https://baike.baidu.com/item/IPv4) 地址 `address`，返回这个 IP 地址的「无效化」版本。

所谓无效化 IP 地址，就是用 `"[.]"` 代替了每个 `"."`。

**示例 1**：

```text
输入：address = "1.1.1.1"
输出："1[.]1[.]1[.]1"
```

**示例 2**：

```text
输入：address = "255.100.50.0"
输出："255[.]100[.]50[.]0"
```

**约束**：

- 给出的 `address` 是一个有效的 IPv4 地址（即由 4 段数字、3 个 `.` 分隔而成，每段数字在 `0`–`255` 之间，无前导零）

> 💡 IPv4 地址形如 `a.b.c.d`，其中 `a`、`b`、`c`、`d` 是 0–255 的十进制数。本题只需把分隔符 `.` 换成字面量 `[.]`，不涉及数字校验。

## 2. 解题思路

### 2.1 暴力思路

最直观的做法是：遍历字符串的每个字符，遇到 `'.'` 时往结果里追加三个字符 `'['`、`'.'`、`']'`，其余字符原样追加。这本身已经是 $O(n)$ 的最优解，没有更暴力的「笨办法」可优化——真正的区别只在于「手动遍历」还是「调用内置替换函数」。

### 2.2 核心观察：逐字符扫描 + 条件追加

![逐字符扫描：遇到 "." 替换为 "[.]"，其余原样保留](../images/defang_ip_concept.svg)

这道题的本质是一次**单趟线性扫描**：每个字符只被处理一次，判定规则极简——

- 若 `address[i] == '.'`：向结果串追加 `"[.]"`（3 个字符替代 1 个字符）
- 否则：向结果串追加 `address[i]`（原样保留）

> 💡 **关键点**：替换是「1 → 3」的膨胀，但并不影响扫描——我们遍历的是**原始**字符串的下标，结果串只负责追加，不需要回填或移动后续字符。这就保证了每个字符恰好处理一次。

### 2.3 算法流程图

![算法流程：i 从 0 扫到 len-1，点号追加 "[.]" 否则追加原字符](../images/defang_ip_algorithm_flow.svg)

流程是一个标准的 **for 循环 + if-else 分支**：

1. 初始化空字符串 `res`
2. `i` 从 `0` 遍历到 `len(address) - 1`
3. 若 `address[i]` 是 `'.'`，`res += "[.]"`
4. 否则 `res += address[i]`
5. 循环结束后返回 `res`

### 2.4 示例演算

以 `address = "1.1.1.1"` 为例，逐字符扫描过程如下：

![示例演算：1.1.1.1 → 1[.]1[.]1[.]1](../images/defang_ip_example_walkthrough.svg)

| 步骤 | 当前字符 | 是否 `'.'` | 操作 | `res` 累积 |
|------|----------|-----------|------|-----------|
| i=0 | `'1'` | 否 | 追加 `'1'` | `"1"` |
| i=1 | `'.'` | 是 | 追加 `"[.]"` | `"1[.]"` |
| i=2 | `'1'` | 否 | 追加 `'1'` | `"1[.]1"` |
| i=3 | `'.'` | 是 | 追加 `"[.]"` | `"1[.]1[.]"` |
| i=4 | `'1'` | 否 | 追加 `'1'` | `"1[.]1[.]1"` |
| i=5 | `'.'` | 是 | 追加 `"[.]"` | `"1[.]1[.]1[.]"` |
| i=6 | `'1'` | 否 | 追加 `'1'` | `"1[.]1[.]1[.]1"` |

最终结果为 `"1[.]1[.]1[.]1"`。原串 7 个字符中有 3 个 `'.'`，每个膨胀为 3 个字符，结果长度 $= 7 + 3 \times 2 = 13$。

## 3. 参考代码

### C++（逐字符扫描）

```cpp
class Solution {
  public:
    string defangIPaddr(string address) {
        string res;
        for (char c : address) {
            if (c == '.') {
                res += "[.]";
            } else {
                res += c;
            }
        }
        return res;
    }
};
```

### Python（内置 replace）

```python
class Solution:
    def defangIPaddr(self, address: str) -> str:
        return address.replace('.', '[.]')
```

> ⚠️ **两种写法的取舍**：C++ 手动遍历展示底层逻辑，适合面试白板推演；Python 的 `str.replace` 是一行惯用写法，底层同样是 $O(n)$ 单趟扫描，实际开发中应优先使用内置函数。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(n)$ | $n$ 为字符串长度，每个字符恰好处理一次 |
| 空间复杂度 | $O(n)$ | 结果串长度最多为 $n + 2 \times 3 = n + 6$（3 个 `.` 各膨胀 2 个字符），与 $n$ 同级 |

## 5. 扩展：C++ 原地修改 vs 新建字符串

上面的 C++ 解法新建了一个 `res` 字符串。也可以选择**原地修改**：由于 `.` 被替换为 `[.]` 是「1 变 3」，需要先统计 `.` 的数量、`resize` 扩容，再**从右向左**搬运字符，避免覆盖未处理的部分。

```cpp
class Solution {
  public:
    string defangIPaddr(string address) {
        int dots = count(address.begin(), address.end(), '.');
        int n = address.size();
        address.resize(n + dots * 2); // 每个 . 多 2 个字符
        for (int i = n - 1, j = address.size() - 1; i >= 0; --i) {
            if (address[i] == '.') {
                address[j--] = ']';
                address[j--] = '.';
                address[j--] = '[';
            } else {
                address[j--] = address[i];
            }
        }
        return address;
    }
};
```

> 💡 **为什么要从右向左？** 从左向右写入 `[.]` 会覆盖后面尚未处理的字符；从右向左则先填充末尾，已处理区域始终在被写入位置的右侧，不会破坏未读数据。这与「数组原地删除/插入」的从后往前搬运技巧同源。

原地修改虽然省去了额外字符串分配，但代码复杂度上升、可读性下降。在实际工程中，新建字符串的写法更清晰且性能差异可忽略。

## 6. 面试要点

1. **为什么时间复杂度是 $O(n)$ 而不是 $O(3n)$？**

   - 每个字符只被扫描一次（$n$ 次比较），结果串的追加操作总计也是 $O(n)$ 级别（3 个 `.` 各追加 3 个字符）。常数因子不改变渐进复杂度，$O(3n) = O(n)$。

2. **结果字符串的长度如何计算？**

   - 原串有 $n$ 个字符，其中 $k$ 个是 `'.'`。每个 `.` 从 1 个字符膨胀为 3 个字符（`[.]`），净增 2。所以结果长度 $= n + 2k$。IPv4 恰好有 3 个 `.`，故结果长度 $= n + 6$。

3. **能否用正则表达式替换？**

   - 可以，如 Python 的 `re.sub(r'\.', '[.]', address)` 或 JavaScript 的 `address.replace(/\./g, '[.]')`。但正则引擎有额外的编译与匹配开销，对本题这种「替换固定字面量」的场景属于杀鸡用牛刀，直接 `str.replace` 更高效。

4. **C++ 中 `res += "[.]"` 和 `res += '['; res += '.'; res += ']'` 有区别吗？**

   - 功能等价。`+= "[.]"` 一次性追加 3 个字符（`const char*` 版本的 `append`），可能比逐字符追加少两次容量检查，但现代 `std::string` 实现中差异极小。可读性上 `"[.]"` 更直观。

5. **如果输入可能包含非 IPv4 格式的字符串怎么办？**

   - 本题保证输入是有效 IPv4 地址，无需校验。若需增强健壮性，可先做格式校验（4 段、每段 0–255、无前导零），再执行替换。校验逻辑可参考 [468. 验证 IP 地址](https://leetcode.cn/problems/validate-ip-address/)。
