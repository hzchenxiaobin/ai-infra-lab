# LeetCode 解码异或后的排列 题解

## 1. 题目概述

- **标题 / 题号**：解码异或后的排列（#1734，medium）
- **链接**：https://leetcode.cn/problems/decode-xored-permutation/
- **难度**：中等
- **标签**：位运算、异或性质、数组、排列、前缀异或

**题意**：未知整数数组 `arr` 由 $n$ 个**正整数**组成，且 `arr` 是前 $n$ 个正整数 $[1, 2, \dots, n]$ 的一个**排列**（$n$ 为**奇数**）。经编码后变为长度为 $n-1$ 的数组 `encoded`，其中：

$$
\text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i+1]
$$

与 [1720. 解码异或后的数组](https://leetcode.cn/problems/decode-xored-array/) 的区别：**不再给定首元素 `first`**，只给 `encoded`，要求还原原排列 `arr`。可以证明答案存在且唯一。

**示例 1**：

```text
输入：encoded = [3,1]
输出：[1,2,3]
解释：若 arr = [1,2,3]，那么
      encoded = [1 XOR 2, 2 XOR 3] = [3,1]
```

**示例 2**：

```text
输入：encoded = [6,5,4,6]
输出：[2,4,1,5,3]
```

**约束**：

- $3 \le n \le 10^5$
- $n$ 为奇数
- $\text{encoded.length} = n - 1$（偶数）
- $1 \le \text{arr}[i] \le n$，`arr` 为 $[1..n]$ 的排列

> 💡 **关键差异**：1720 白送了 `arr[0] = first`，于是整条链可逐项递推展开。本题藏起了首元素，若直接套 1720 的递推会因「未知起点」而卡死。破局点在于利用「`arr` 是 $[1..n]$ 的排列」这一额外结构——它暴露了全集异或的信息，使我们能**反推出 `arr[0]`**，之后便退化为 1720。

## 2. 解题思路

### 2.1 暴力思路：枚举首元素后递推

最直觉的暴力做法：对 `arr[0]` 在值域 $[1,\,n]$ 内**逐一枚举**候选值 $v$，套用 1720 的递推公式生成完整 `arr`，再校验 `arr` 是否恰为 $[1..n]$ 的排列（去重 + 范围检查）。

```text
for v in 1 .. n:                       # 枚举 arr[0]
    arr[0] = v
    for i in 0 .. n-2:                 # 1720 递推
        arr[i+1] = arr[i] ^ encoded[i]
    if arr 是 [1..n] 的排列:
        return arr
```

每个候选 $v$ 需要 $O(n)$ 递推 + $O(n)$ 校验，共 $n$ 个候选，复杂度 $O(n^2) \approx 10^{10}$，必然超时。

> ⚠️ **症结**：暴力把「求 `arr[0]`」当成**搜索问题**，在 $n$ 个候选里逐一试错。但实际上，排列的全集异或信息已**唯一确定** `arr[0]`，根本无需枚举。把「可计算」的量当作「可枚举」的量去扫描，是暴力低效的根源——这与 1720 中暴力枚举下一项的误区同构。

### 2.2 核心观察：排列全集异或 + 奇偶配对抵消

![核心概念：奇偶配对抵消，反推首元素 arr[0]](../images/1734_concept.svg)

破局分两步：先求全集异或，再用奇偶配对消去 `arr[1..n-1]`。

**第一步：全集异或已知。** 由于 `arr` 是 $[1..n]$ 的排列，全数组异或值 $P$ 可直接计算：

$$
P = \text{arr}[0] \oplus \text{arr}[1] \oplus \dots \oplus \text{arr}[n-1] = 1 \oplus 2 \oplus \dots \oplus n
$$

$P$ 不依赖排列的具体顺序，只与 $n$ 有关，可在 $O(n)$ 内预算。

**第二步：奇偶配对消去 `arr[1..n-1]`。** 把 $P$ 中 `arr[0]` 单独拆出：

$$
\text{arr}[0] = P \oplus (\text{arr}[1] \oplus \text{arr}[2] \oplus \dots \oplus \text{arr}[n-1])
$$

关键来了——$n$ 为**奇数**，故 $n-1$ 为**偶数**，$\text{arr}[1..n-1]$ 恰好偶数项，可两两配对：

$$
(\text{arr}[1],\,\text{arr}[2]),\quad (\text{arr}[3],\,\text{arr}[4]),\quad \dots,\quad (\text{arr}[n-2],\,\text{arr}[n-1])
$$

每对的异或正是 `encoded` 的**奇数下标**元素：

$$
\text{arr}[1] \oplus \text{arr}[2] = \text{encoded}[1]
$$
$$
\text{arr}[3] \oplus \text{arr}[4] = \text{encoded}[3]
$$
$$
\dots
$$
$$
\text{arr}[n-2] \oplus \text{arr}[n-1] = \text{encoded}[n-2]
$$

于是 $\text{arr}[1..n-1]$ 的异或等于 `encoded` 所有奇数下标元素的异或：

$$
\text{arr}[1] \oplus \dots \oplus \text{arr}[n-1] = \text{encoded}[1] \oplus \text{encoded}[3] \oplus \dots \oplus \text{encoded}[n-2]
$$

代入即得首元素：

$$
\boxed{\;\text{arr}[0] = P \oplus \text{encoded}[1] \oplus \text{encoded}[3] \oplus \dots \oplus \text{encoded}[n-2]\;}
$$

> 💡 **为什么 $n$ 必须为奇数？** 配对要求 $\text{arr}[1..n-1]$ 有偶数项（即 $n-1$ 为偶数），才能从 `arr[1]` 起两两配对、每对对应一个 `encoded` 奇数下标。若 $n$ 为偶数，$n-1$ 为奇数，$\text{arr}[1..n-1]$ 有奇数项，配对后会剩一个孤立项无法消去，上述推导失效——这正是题目限定 $n$ 为奇数的根本原因。
>
> 💡 **异或的消去律**：上述推导的底层是异或的**消去律**——若 $a \oplus b = a \oplus c$ 则 $b = c$（两边同时异或 $a$ 即得）。把 $P$ 看作「全体异或」，用 `arr[0]` 与 `arr[1..n-1]` 的异或拼成 $P$，再消去 `arr[1..n-1]` 这部分（靠配对抵消），剩下的就是 `arr[0]`。与 1720 用自反性反解单项属同一族思想，只是这里消去的是「一段之和」而非「一个量」。

### 2.3 算法流程图

![算法流程：两阶段——求 arr[0] + 逐项递推](../images/1734_algorithm_flow.svg)

算法分两阶段：

**阶段一（求 `arr[0]`，$O(n)$）**：

1. **算全集异或 $P$**：遍历 $1$ 到 $n$，累积异或，得到 $P = 1 \oplus 2 \oplus \dots \oplus n$。
2. **算奇数下标异或 $S$**：遍历 `encoded` 的奇数下标 $i = 1, 3, \dots, n-2$，累积异或得到 $S$。
3. **求 `arr[0]`**：$\text{arr}[0] = P \oplus S$。

**阶段二（逐项递推，$O(n)$，退化为 1720）**：

4. 从 `arr[0]` 出发，对 $i = 0, 1, \dots, n-2$ 执行 $\text{arr}[i+1] = \text{arr}[i] \oplus \text{encoded}[i]$。
5. 填满后返回 `arr`。

两阶段各单趟扫描，总复杂度 $O(n)$。

### 2.4 示例演算

以示例 1 `encoded = [3,1]`（$n = 3$，`arr` 是 $[1,2,3]$ 的排列）为例：

![示例演算：两阶段解码 encoded=[3,1] 得到 arr=[1,2,3]](../images/1734_example_walkthrough.svg)

**阶段一**：

| 量 | 来源 | 计算 | 结果 |
|----|------|------|------|
| $P$ | $1..n$ 全集异或 | $1 \oplus 2 \oplus 3$ | **0** |
| $S$ | `encoded` 奇数下标 | $\text{encoded}[1] = 1$ | **1** |
| `arr[0]` | $P \oplus S$ | $0 \oplus 1$ | **1** |

**阶段二**（与 1720 完全相同）：

| 步骤 $k$ | `arr[k]` 的来源 | 计算 | `arr[k]` |
|----------|-----------------|------|----------|
| 0 | 阶段一求得 | — | **1** |
| 1 | $\text{arr}[0] \oplus \text{encoded}[0]$ | $1 \oplus 3$ | **2** |
| 2 | $\text{arr}[1] \oplus \text{encoded}[1]$ | $2 \oplus 1$ | **3** |

最终 `arr = [1, 2, 3]` ✓，恰为 $[1..3]$ 的排列。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> decode(vector<int>& encoded) {
        int n = encoded.size() + 1;

        // 阶段一：求 arr[0]
        int P = 0;
        for (int i = 1; i <= n; ++i) P ^= i;          // 1..n 全集异或

        int S = 0;
        for (int i = 1; i < n - 1; i += 2) S ^= encoded[i];  // encoded 奇数下标

        vector<int> arr(n);
        arr[0] = P ^ S;

        // 阶段二：逐项递推（与 1720 完全相同）
        for (int i = 0; i + 1 < n; ++i) {
            arr[i + 1] = arr[i] ^ encoded[i];
        }
        return arr;
    }
};
```

### Python

```python
class Solution:
    def decode(self, encoded: List[int]) -> List[int]:
        n = len(encoded) + 1

        # 阶段一：求 arr[0]
        P = 0
        for i in range(1, n + 1):
            P ^= i                          # 1..n 全集异或

        S = 0
        for i in range(1, n - 1, 2):
            S ^= encoded[i]                 # encoded 奇数下标

        # 阶段二：逐项递推（与 1720 完全相同）
        arr = [P ^ S]
        for e in encoded:
            arr.append(arr[-1] ^ e)
        return arr
```

> 💡 **两阶段解耦**：阶段一的 $P$ 与 $S$ 各自独立计算，最后一步 `arr[0] = P ^ S` 才合并——这对应公式里「全集异或」与「奇数下标配对异或」两个信息源的汇合。阶段二直接复用 1720 的递推骨架，从 `[P ^ S]` 起逐个 `append`，写法最简洁。
>
> ⚠️ **下标边界**：`encoded` 长度为 $n-1$（偶数），奇数下标为 $1, 3, \dots, n-2$，故循环条件 `i < n - 1`（即 `i` 不超过最后一个有效下标 $n-2$）。C++ 中 `i += 2` 配合 `i < n - 1` 恰好遍历 $1, 3, \dots, n-2$；Python 中 `range(1, n - 1, 2)` 同理。下标越界是本题最常见的实现失误。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(n)$ | 阶段一：算 $P$ 遍历 $1..n$ 共 $n$ 次异或；算 $S$ 遍历 $\frac{n-1}{2}$ 个奇数下标。阶段二：递推 $n-1$ 次。总计约 $2n$ 次位运算 |
| 空间复杂度 | $O(1)$ | 不计返回的 `arr`，仅用 $P$、$S$ 等常数个额外变量；若计输出则为 $O(n)$ |

> 💡 本题 $n \le 10^5$，$O(n)$ 极其宽裕。瓶颈在访存而非运算——异或是 CPU 单周期指令，$2n \approx 2 \times 10^5$ 次位运算远快于一次缓存未命中的代价。

## 5. 扩展：全集异或的 $O(1)$ 预算与 $n$ 为偶数的困境

### 5.1 全集异或 $P$ 的 $O(1)$ 公式

阶段一中 $P = 1 \oplus 2 \oplus \dots \oplus n$ 的计算可进一步优化到 $O(1)$。观察异或结果随 $n$ 的周期性（周期为 4）：

| $n \bmod 4$ | $P = 1 \oplus 2 \oplus \dots \oplus n$ |
|-------------|----------------------------------------|
| $0$ | $n$ |
| $1$ | $1$ |
| $2$ | $n + 1$ |
| $3$ | $0$ |

本题 $n$ 为奇数，故 $n \bmod 4 \in \{1, 3\}$：当 $n \bmod 4 = 1$ 时 $P = 1$，当 $n \bmod 4 = 3$ 时 $P = 0$。可据此把阶段一的 $P$ 计算从 $O(n)$ 降到 $O(1)$，但整体复杂度仍为 $O(n)$（阶段二的递推不可省），所以仅是常数优化。

### 5.2 若 $n$ 为偶数会怎样？

若取消「$n$ 为奇数」的限制，本题是否仍可解？答案是否定的——**信息不足，答案不唯一**。当 $n$ 为偶数时，$n - 1$ 为奇数，$\text{arr}[1..n-1]$ 有奇数项，无法两两配对消去。此时 `encoded` 仍为偶数长度，但奇数下标只有 $1, 3, \dots, n-3$（少一个），无法覆盖最后一个元素 `arr[n-1]`，导致 `arr[0]` 无法被反推。

> 💡 **信息论视角**：`encoded` 有 $n-1$ 个值，排列 `arr` 有 $n!$ 种可能但受 `encoded` 约束。$n$ 为奇数时约束恰好「锁定」唯一解；$n$ 为偶数时约束存在一个自由度（平移对称性未被打破），答案不唯一。题面限定 $n$ 为奇数正是为了保证唯一可解。

## 6. 面试要点

**Q1：为什么不能直接套 1720 的递推？缺了什么？**
> 1720 的递推 `arr[i+1] = arr[i] ⊕ encoded[i]` 需要一个**起点** `arr[0]`。1720 白送了 `first`，本题藏起了首元素，递推链无处起步。破局的关键是利用「`arr` 是 $[1..n]$ 的排列」这一额外结构，反推出 `arr[0]`，之后便完全退化为 1720。

**Q2：为什么 $n$ 必须是奇数？偶数时推导哪一步失效？**
> 配对消去要求 $\text{arr}[1..n-1]$ 有偶数项，即 $n-1$ 为偶数、$n$ 为奇数。$n$ 为奇数时，从 `arr[1]` 起两两配对，每对恰好对应 `encoded` 的一个奇数下标（$1, 3, \dots, n-2$），全部消去后只剩 `arr[0]`。若 $n$ 为偶数，$\text{arr}[1..n-1]$ 有奇数项，配对后剩一个孤立元素无法消去，`arr[0]` 无法被反推，答案不唯一。

**Q3：为什么用 `encoded` 的奇数下标而非偶数下标？**
> 配对方式是 $(\text{arr}[1],\text{arr}[2])$、$(\text{arr}[3],\text{arr}[4])$、…，每对的异或是 $\text{arr}[2k-1] \oplus \text{arr}[2k] = \text{encoded}[2k-1]$，下标恰好是奇数。若改成 $(\text{arr}[0],\text{arr}[1])$、$(\text{arr}[2],\text{arr}[3])$ 配对，对应的是 `encoded` 偶数下标，但这样消去的是 $\text{arr}[0..n-2]$，剩下 `arr[n-1]`——同样能求出 `arr[n-1]`，再**反向**递推。两种配对等价，奇数下标更直观（直接求首元素）。

**Q4：阶段二能否从尾部反向递推？**
> 可以。若改用偶数下标配对求出 `arr[n-1]`，则反向递推 $\text{arr}[i] = \text{arr}[i+1] \oplus \text{encoded}[i]$（由 $\text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i+1]$ 两边异或 $\text{arr}[i+1]$ 得）。两种方向等价，正向（求 `arr[0]`）更符合从左到右的直觉，且与 1720 的递推方向一致、代码可直接复用。

**Q5：暴力 $O(n^2)$ 枚举 `arr[0]` 为什么必然超时？如何识别「搜索 vs 计算」的误区？**
> 暴力对 $n$ 个候选逐一试错，每个候选 $O(n)$ 递推 + 校验，总计 $O(n^2) \approx 10^{10}$ 必然超时。识别信号：当待求量能由已知信息经**等式推导**唯一确定时，应直接计算而非搜索。本题的等式是 $P = \text{arr}[0] \oplus S$，其中 $P$ 由排列性质已知、$S$ 由奇数下标已知，故 `arr[0] = P ⊕ S` 一步可得。这与 1720 中「下一项可由等式反解而非枚举」的误区同构。
