# LeetCode 能看到海景的建筑物 题解

## 1. 题目概述

- **标题 / 题号**：能看到海景的建筑物（#1762，medium）
- **链接**：https://leetcode.cn/problems/buildings-with-an-ocean-view/
- **难度**：中等
- **标签**：数组、单调栈、贪心

**题意**：有 $n$ 栋建筑排成一行，给定整数数组 `heights` 表示每栋建筑的高度。海洋在建筑物的**右侧**。若一栋建筑**右侧所有建筑的高度都比它矮**（严格小于），则该建筑能看到海景。

返回能看到海景的建筑物**下标列表**（0-indexed），按下标**升序**排列。

**示例 1**：

```text
输入：heights = [4,2,3,1]
输出：[0,2,3]
解释：下标 1 的建筑（高度 2）右侧有更高建筑（高度 3），被遮挡，看不到海景。
```

**示例 2**：

```text
输入：heights = [4,3,2,1]
输出：[0,1,2,3]
解释：高度从左到右递减，每栋建筑右侧都比它矮，全部能看到海景。
```

**示例 3**：

```text
输入：heights = [1,3,2,4]
输出：[3]
解释：只有最右侧建筑（高度 4）能看到海景，其余均被右侧更高的建筑遮挡。
```

**约束**：

- $1 \le heights.length \le 10^5$
- $1 \le heights[i] \le 10^9$

**进阶**：能否用 $O(n)$ 时间、$O(1)$ 额外空间（不计输出）解决？

> 💡 **关键直觉**：「右侧所有建筑都比它矮」等价于「它比右侧最大值还高」。于是只需知道每个位置右侧的最大高度——而从右向左扫描一遍即可滚动维护这个最大值，无需对每个位置重新扫右半段。

## 2. 解题思路

### 2.1 暴力思路：逐个位置向右扫描求最大值

最直观的做法：对每个下标 $i$，扫描 $i+1 \dots n-1$ 找右侧最大高度 $\max_{j>i} heights[j]$，若 $heights[i]$ 大于该最大值则入选。

```text
for i in 0..n-1:
    rightMax = max(heights[i+1..n-1])   // 朴素扫描 O(n)
    if heights[i] > rightMax:
        ans.append(i)
```

每个位置求右侧最大值是 $O(n)$，总体 $O(n^2)$。对 $n = 10^5$ 约需 $10^{10}$ 次比较，**超时**。问题在于：相邻位置的「右侧最大值」高度重叠——$i$ 的右侧最大值与 $i+1$ 的右侧最大值只差一个元素，却被重复计算。

### 2.2 核心观察：从右向左滚动维护右侧最大值

![核心观察：从右向左维护右侧最大高度 maxRight，h[i] > maxRight 即可看海](../images/1762_concept.svg)

**观察 1（等价转化）**：建筑 $i$ 能看海 $\iff$ 右侧所有建筑都比它矮 $\iff heights[i] > \max_{j > i} heights[j]$。把「右侧全部更矮」这个全局条件，压缩成与「右侧最大值」的一次比较。

**观察 2（单向依赖）**：定义 $R_i = \max_{j > i} heights[j]$（位置 $i$ 右侧的最大高度）。注意到递推关系：

$$
R_i = \max(R_{i+1},\ heights[i+1])
$$

即 $i$ 的右侧最大值 = 「$i+1$ 的右侧最大值」与「$heights[i+1]$」取较大。$R_i$ **只依赖 $i+1$ 处的信息**——这正是从右向左滚动的天然方向。

> 💡 因此只需从 $i = n-1$ 向 $0$ 扫一遍，用一个变量 `maxH` 滚动记录「当前已扫过的右侧最大高度」。最右端 $i = n-1$ 右侧无建筑，$R_{n-1} = 0$（高度恒 $\ge 1$，故最右建筑必入选）。每步比较 $heights[i] > maxH$：成立则入选并更新 $maxH = heights[i]$；否则跳过。

**观察 3（maxH 单调递增）**：`maxH` 只在「入选」时被更新为更大的 $heights[i]$，故随扫描从右到左**单调递增**。入选的建筑高度恰好是 `maxH` 的更新序列——一个**严格递增**的子序列（从右看）。这也解释了为什么等高的两栋建筑，靠左的那栋会被靠右的那栋遮挡（$heights[i] == maxH$ 时不满足严格大于）。

> ⚠️ **严格大于还是大于等于？** 题面要求右侧「严格更矮」（smaller height），故 $heights[i] > maxH$ 用**严格大于**。若右侧存在等高建筑（$heights[i] == maxH$），则 $i$ 被遮挡、不能看海。若题面改成「不高于」，则改为 $\ge$ 即可。

### 2.3 算法流程图

![算法流程：从右向左单遍扫描，维护右侧最大高度 maxH](../images/1762_algorithm_flow.svg)

实现步骤：

1. 初始化 `maxH = 0`、`res = []`，令 $i = n - 1$；
2. 循环 while $i \ge 0$：
   - 若 $heights[i] > maxH$：把 $i$ 追加进 `res`，并更新 $maxH = heights[i]$；
   - $i \mathrel{-}= 1$（向左移动）；
3. 扫描结束后 `res` 中的下标自右向左递减，`reverse` 得到升序，返回。

> 💡 **为何要 reverse？** 扫描方向是 $n-1 \to 0$，入选下标按收集顺序是**递减**的（如 `[3, 2, 0]`）。题目要求升序，故最后翻转一次。也可改用双端队列从头部插入，但 `reverse` 一次 $O(k)$ 同样简洁。

### 2.4 示例演算

以 `heights = [4, 2, 3, 1]`（$n = 4$）为例，从 $i = 3$ 扫到 $i = 0$：

![示例演算：heights = [4,2,3,1]，从右向左追踪 maxH 与 res](../images/1762_example_walkthrough.svg)

| 扫描 $i$ | $heights[i]$ | $maxH$（比较前） | 判定 $heights[i] > maxH$ | 动作 | `res`（更新后） |
|----------|--------------|------------------|--------------------------|------|-----------------|
| 3 | 1 | 0 | $1 > 0$ ✓ 是 | 入选，$maxH \to 1$ | `[3]` |
| 2 | 3 | 1 | $3 > 1$ ✓ 是 | 入选，$maxH \to 3$ | `[3, 2]` |
| 1 | 2 | 3 | $2 > 3$ ✗ 否 | 跳过（$maxH$ 不变） | `[3, 2]` |
| 0 | 4 | 3 | $4 > 3$ ✓ 是 | 入选，$maxH \to 4$ | `[3, 2, 0]` |

扫描结束 `res = [3, 2, 0]`，`reverse` 后得 `[0, 2, 3]` ✓，与示例 1 一致。

- 对照示例 2 `[4,3,2,1]`：`maxH` 走 $0 \to 1 \to 2 \to 3 \to 4$，每步都入选，`res = [3,2,1,0]`，翻转得 `[0,1,2,3]` ✓。
- 对照示例 3 `[1,3,2,4]`：$i=3$（$h=4$）入选 $maxH=4$；$i=2$（$h=2$）、$i=1$（$h=3$）、$i=0$（$h=1$）均 $\le 4$ 被挡，`res=[3]` ✓。

> ⚠️ **边界**：$n = 1$ 时循环只跑一轮，$maxH = 0$，$heights[0] > 0$ 必成立，`res = [0]`，正确（唯一建筑右侧无遮挡）。

## 3. 参考代码

### Python

```python
class Solution:
    def findBuildings(self, heights: List[int]) -> List[int]:
        n = len(heights)
        res = []
        max_h = 0
        for i in range(n - 1, -1, -1):      # 从右向左扫描
            if heights[i] > max_h:          # 比右侧最大值还高 → 能看海
                res.append(i)
                max_h = heights[i]          # 更新右侧最大高度
        res.reverse()                       # 收集顺序递减，翻转为升序
        return res
```

### C++

```cpp
class Solution {
public:
    vector<int> findBuildings(vector<int>& heights) {
        int n = heights.size();
        vector<int> res;
        int maxH = 0;
        for (int i = n - 1; i >= 0; i--) {  // 从右向左扫描
            if (heights[i] > maxH) {        // 比右侧最大值还高 → 能看海
                res.push_back(i);
                maxH = heights[i];          // 更新右侧最大高度
            }
        }
        reverse(res.begin(), res.end());    // 收集顺序递减，翻转为升序
        return res;
    }
};
```

> 💡 **实现细节**：① `maxH` 初值取 $0$ 而非 `INT_MIN`：高度恒 $\ge 1$，最右建筑右侧无遮挡，$> 0$ 必成立，省去对 $i = n-1$ 的特判。② 比较用 `>`（严格大于），等高即被挡——由题面「smaller height」（严格更矮）决定。③ `res` 用 `push_back` 顺序收集为递减下标，最后 `reverse` 一次 $O(k)$ 即得升序；若想免翻转，可改用 `deque` 的 `push_front`，但 `vector + reverse` 通常更快（缓存友好）。④ `maxH` 会超过 `int` 上界？不会——它始终取自某个 $heights[i]$，而 $heights[i] \le 10^9 < 2^{31}$，`int` 足够。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | $O(n)$ | 从右向左单遍扫描，每个位置做 $O(1)$ 比较与可能的更新；末尾 `reverse` $O(k) \le O(n)$ |
| 空间 | $O(1)$ | 仅 `maxH` 与循环变量，不计输出数组 `res`；满足进阶要求 |

> ⚠️ 暴力法对每个 $i$ 重新扫右半段求最大值，是 $O(n^2)$。关键优化在于识别 $R_i$ 对 $R_{i+1}$ 的单向依赖，把 $n$ 次独立「求右侧最大值」**塌缩**成一次从右向左的滚动——本质上是用「一个变量滚动记最大」代替「每个位置重扫右半段」。

## 5. 扩展：单调栈解法（从左向右）

除「从右向左滚动最大值」外，本题也可用**单调栈**从左向右一遍解决，与 [739. 每日温度](../0701-0800/739_每日温度.md) 同属「下一个更大元素」家族。

**思路**：维护一个**严格递减**的下标栈（栈底到栈顶高度递减）。从左向右遍历，遇到 $heights[i]$ 时，栈顶若高度 $\le heights[i]$，说明栈顶建筑被右侧的 $i$ 挡住（$i$ 在其右且更高或等高），弹栈直至栈顶高度 $> heights[i]$ 或栈空；然后压入 $i$。遍历结束，栈中残留的下标就是能看到海景的建筑，且天然升序。

```cpp
vector<int> findBuildings(vector<int>& heights) {
    vector<int> st;                          // 严格递减下标栈
    for (int i = 0; i < (int)heights.size(); i++) {
        while (!st.empty() && heights[st.back()] <= heights[i])
            st.pop_back();                   // 被右侧的 i 遮挡，弹出
        st.push_back(i);
    }
    return st;                               // 栈内下标自然升序，无需 reverse
}
```

**两种解法对照**：

| 维度 | 从右向左滚动最大值 | 单调栈（从左向右） |
|------|-------------------|-------------------|
| 方向 | 右 $\to$ 左 | 左 $\to$ 右 |
| 数据结构 | 单变量 `maxH` | 下标栈 |
| 额外空间 | $O(1)$ | $O(k)$（栈最深 $k$ 个入选建筑） |
| 输出顺序 | 递减收集 → `reverse` | 天然升序 |
| 本质 | 维护「右侧最大值」逐一比较 | 维护「未被遮挡的候选集」实时踢人 |

> 💡 **为何等价？** 单调栈弹栈的条件是「栈顶高度 $\le heights[i]」，即栈顶被右侧的 $i$ 挡住；这正对应滚动法中「$heights[\text{栈顶}] \le maxH$ 被跳过」。两种解法篮出的「幸存者集合」完全相同——都是那条从右向左看**严格递增**的高度子序列对应的下标。滚动法只记最大值（$O(1)$ 空间），单调栈记全部幸存者（$O(k)$ 空间），故前者更省空间、满足进阶要求。

## 6. 面试要点

1. **「右侧所有建筑都比它矮」如何等价成一次比较？**

   > 「右侧全部更矮」$\iff$「比右侧最大值还高」，即 $heights[i] > \max_{j > i} heights[j]$。把全局条件压缩成与右侧最大值的一次比较，是本题降阶的关键。

2. **为什么要从右向左扫描？从左向右不行吗？**

   > 位置 $i$ 的右侧最大值 $R_i$ 依赖 $R_{i+1}$（$R_i = \max(R_{i+1}, heights[i+1])$），信息流向是右 $\to$ 左。从右向左扫一遍即可用单变量滚动维护 $R_i$，$O(n)$。从左向右则需栈实时踢除被挡候选（单调栈解法），也能 $O(n)$ 但多花 $O(k)$ 栈空间。

3. **比较用严格大于还是大于等于？等高建筑能看海吗？**

   > 题面要求右侧「严格更矮」（smaller height），故用 $>$ 严格大于。等高建筑（$heights[i] == maxH$）被右侧等高者遮挡，不能看海。若题面改成「不高于」，把 $>$ 换成 $\ge$ 即可，方向不变。

4. **如何满足 $O(1)$ 额外空间的进阶要求？**

   > 从右向左滚动最大值法只用 `maxH` 一个变量（不计输出 `res`），即 $O(1)$ 额外空间。输出数组本身题目通常不计入空间复杂度。单调栈解法需 $O(k)$ 栈空间，不满足进阶要求。

5. **最右侧建筑一定入选吗？`maxH` 初值为何取 0？**

   > 最右建筑 $i = n-1$ 右侧无任何建筑，无遮挡，必看海。高度恒 $\ge 1$，故 `maxH` 初值取 $0$ 即可让 $heights[n-1] > 0$ 恒成立，省去特判。若高度可能为负或含 0，则需取 $-\infty$ 或对 $i = n-1$ 单独处理。

6. **`maxH` 的单调性有什么用？**

   > `maxH` 只在入选时更新为更大的 $heights[i]$，故随扫描从右到左单调递增。入选建筑的高度恰为 `maxH` 的更新序列——从右看严格递增。这一单调性保证了每个 $heights[i]$ 只与当前 `maxH` 比一次即可定论，无需回溯，是 $O(n)$ 的根基。

> 💡 **一句话总结**：从右向左滚动维护右侧最大高度 `maxH`，$heights[i] > maxH$ 即入选并更新 `maxH`，最后翻转收集顺序——$O(n)$ 时间、$O(1)$ 额外空间，满足进阶。
