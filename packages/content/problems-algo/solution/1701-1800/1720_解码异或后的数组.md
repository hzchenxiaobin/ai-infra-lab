# LeetCode 解码异或后的数组 题解

## 1. 题目概述

- **标题 / 题号**：解码异或后的数组（#1720，easy）
- **链接**：https://leetcode.cn/problems/decode-xored-array/
- **难度**：简单
- **标签**：位运算、异或性质、数组、模拟

**题意**：未知整数数组 `arr` 由 $n$ 个**非负整数**组成。经编码后变为长度为 $n-1$ 的另一个整数数组 `encoded`，其中：

$$
\text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i+1]
$$

例如 `arr = [1,0,2,1]` 经编码得到 `encoded = [1,2,3]`。现给定编码后的数组 `encoded` 和原数组的首元素 `first`（即 `arr[0]`），请解码返回原数组 `arr`。可以证明答案存在且唯一。

**示例 1**：

```text
输入：encoded = [1,2,3], first = 1
输出：[1,0,2,1]
解释：若 arr = [1,0,2,1]，那么 first = 1 且
      encoded = [1 XOR 0, 0 XOR 2, 2 XOR 1] = [1,2,3]
```

**示例 2**：

```text
输入：encoded = [6,2,7,3], first = 4
输出：[4,2,0,7,4]
```

**约束**：

- $2 \le n \le 10^4$
- $\text{encoded.length} = n - 1$
- $0 \le \text{encoded}[i] \le 10^5$
- $0 \le \text{first} \le 10^5$

> 💡 **关键结构**：编码关系 `encoded[i] = arr[i] ⊕ arr[i+1]` 把相邻两项「绑」在一起。只要知道其中一项，就能用异或的可逆性立刻推出另一项。题目白送了 `arr[0] = first`，于是整条链可以**逐项递推**展开——这正是「链式约束 + 已知起点」的典型信号。

## 2. 解题思路

### 2.1 暴力思路：逐位枚举候选值

最直觉的暴力做法是：对每个待求位置 $k$（从 $1$ 到 $n-1$），在值域 $[0,\,10^5]$ 内**逐一枚举**候选值 $v$，检验是否满足约束 $\text{arr}[k-1] \oplus v = \text{encoded}[k-1]$，命中则填入 `arr[k]`。

```text
for k in 1 .. n-1:
    for v in 0 .. 10^5:                 # 枚举候选
        if arr[k-1] XOR v == encoded[k-1]:
            arr[k] = v; break
```

每个位置最坏扫描整个值域 $V = 10^5$，共 $n-1$ 个位置，复杂度 $O(n \cdot V) \approx 10^9$，远超时限。

> ⚠️ **症结**：暴力把「求 $v$」当成**搜索问题**，但实际上约束 $\text{arr}[k-1] \oplus v = \text{encoded}[k-1]$ 是一个**等式**——$v$ 被唯一确定，根本不需要搜索。把「可计算」的量当作「可枚举」的量去扫描，是暴力低效的根源。

### 2.2 核心观察：XOR 自反性——编码可一步反解

![核心概念：XOR 自反性使编码可逆，arr[i+1] = arr[i] ⊕ encoded[i]](../images/1720_concept.svg)

关键洞察来自异或运算的**自反性**（self-inverse）：

$$
a \oplus a = 0,\qquad a \oplus 0 = a
$$

由此，对任意 $a, b$ 都有

$$
(a \oplus b) \oplus a = b \oplus (a \oplus a) = b \oplus 0 = b
$$

即「异或两次同一个数等于没异或」。把这一性质套到编码等式 $\text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i+1]$ 上，两边同时异或 $\text{arr}[i]$，立刻得到解码公式：

$$
\boxed{\;\text{arr}[i+1] = \text{arr}[i] \oplus \text{encoded}[i]\;}
$$

于是从已知的 `arr[0] = first` 出发，每一步只需做**一次异或**即可推出下一项，整条链逐项展开，无需任何搜索或回溯。

> 💡 **异或的可逆性**：异或运算是其自身的逆运算——用同一个数异或两次就还原。这使得 `a ⊕ b = c` 中任意一个量都能由另外两个直接求出（`a = b ⊕ c`、`b = a ⊕ c`、`c = a ⊕ b`）。本题正是利用「已知 $a$ 和 $c$ 求 $b$」这一方向。对比加法：$a + b = c$ 中 $b = c - a$ 需要**另一种运算**（减法）；而异或的逆仍是异或，无需引入新运算，这正是它在编码/加密场景中好用的原因。

### 2.3 算法流程图

![算法流程：arr[0]=first → 循环 arr[i+1]=arr[i]⊕encoded[i] → i 达 n-1 返回](../images/1720_algorithm_flow.svg)

1. **初始化**：构造长度为 $n = \text{encoded.length} + 1$ 的结果数组 `arr`，令 `arr[0] = first`。
2. **递推**：从 $i = 0$ 起，重复执行 $\text{arr}[i+1] = \text{arr}[i] \oplus \text{encoded}[i]$，直到填满整个数组。
3. **终止**：$i$ 达到 $n-1$（即所有 `encoded` 元素已消费完），返回 `arr`。

每轮仅一次异或 + 一次自增，共 $n-1$ 轮，总复杂度 $O(n)$。

### 2.4 示例演算

以示例 1 `encoded = [1,2,3]`、`first = 1` 为例：

![示例演算：first=1 起，逐项异或解码得到 arr=[1,0,2,1]](../images/1720_example_walkthrough.svg)

| 步骤 $k$ | `arr[k]` 的来源 | 计算 | `arr[k]` |
|----------|-----------------|------|----------|
| 0 | 已知 `first` | — | **1** |
| 1 | $\text{arr}[0] \oplus \text{encoded}[0]$ | $1 \oplus 1$ | **0** |
| 2 | $\text{arr}[1] \oplus \text{encoded}[1]$ | $0 \oplus 2$ | **2** |
| 3 | $\text{arr}[2] \oplus \text{encoded}[2]$ | $2 \oplus 3$ | **1** |

最终 `arr = [1, 0, 2, 1]` ✓。注意第 2 步：`arr[1] = 0` 时，`0 ⊕ 2 = 2`——0 异或任何数等于该数本身，这正是自反性中 $0 \oplus a = a$ 的体现。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> decode(vector<int>& encoded, int first) {
        int n = encoded.size() + 1;
        vector<int> arr(n);
        arr[0] = first;
        for (int i = 0; i + 1 < n; ++i) {
            arr[i + 1] = arr[i] ^ encoded[i];
        }
        return arr;
    }
};
```

### Python

```python
class Solution:
    def decode(self, encoded: List[int], first: int) -> List[int]:
        arr = [first]
        for e in encoded:
            arr.append(arr[-1] ^ e)
        return arr
```

> 💡 **就地追加 vs 预分配**：Python 版直接从 `[first]` 起逐个 `append`，写法最简洁；C++ 版预分配 `vector(n)` 再按下标填入，避免动态扩容的搬运开销。两种写法本质相同——都是「前一项 ⊕ encoded[i] → 追加到尾部」。
>
> ⚠️ **溢出无忧**：异或是**按位**运算，不产生进位，结果位数不超过操作数位数。本题值域 $\le 10^5 < 2^{17}$，`int` 完全足够，无需担心溢出（与加法/乘法题不同）。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(n)$ | 单趟遍历 `encoded`，每轮一次异或 $O(1)$；$n \le 10^4$ 时约 $10^4$ 次位运算 |
| 空间复杂度 | $O(1)$ | 不计返回的 `arr`（题目要求输出该数组），仅用常数额外变量；若计输出则为 $O(n)$ |

> 💡 本题 $n \le 10^4$，$O(n)$ 极其宽裕。即便 $n$ 放大到 $10^7$，单趟线性扫描仍可接受。瓶颈永远不在运算本身——异或是 CPU 单周期指令，远快于访存。

## 5. 扩展：当 `first` 未知——解码异或后的排列

本题之所以简单，关键在于**白送了 `arr[0] = first`**。若把首元素也藏起来，问题立刻升级——这正是 [1734. 解码异或后的排列](https://leetcode.cn/problems/decode-xored-permutation/)。

**1734 题面**：`arr` 是前 $n$ 个正整数的**排列**（即 $[1, 2, \dots, n]$ 的某种排列），$n$ 为**奇数**；同样给定 `encoded[i] = arr[i] ⊕ arr[i+1]`，但**不给 `first`**，要求还原 `arr`。

**破局点**：利用排列的全集异或。由于 `arr` 是 $[1..n]$ 的排列，全数组异或已知：

$$
P = 1 \oplus 2 \oplus \dots \oplus n
$$

而 $P = \text{arr}[0] \oplus \text{arr}[1] \oplus \dots \oplus \text{arr}[n-1]$。把 `arr[0]` 单独拆出：

$$
\text{arr}[0] = P \oplus (\text{arr}[1] \oplus \text{arr}[2] \oplus \dots \oplus \text{arr}[n-1])
$$

由于 $n$ 为奇数，$n-1$ 为偶数，$\text{arr}[1..n-1]$ 恰好可两两配对：$(\text{arr}[1],\text{arr}[2])$、$(\text{arr}[3],\text{arr}[4])$、…、$(\text{arr}[n-2],\text{arr}[n-1])$，每对的异或正是 `encoded[1]`、`encoded[3]`、…、`encoded[n-2]`。于是：

$$
\text{arr}[0] = P \oplus (\text{encoded}[1] \oplus \text{encoded}[3] \oplus \dots \oplus \text{encoded}[n-2])
$$

求出 `arr[0]` 后，剩余部分**退化为 1720**，逐项异或解码即可。

> 💡 **方法对照**：1720 与 1734 的解码主循环完全相同（都是 `arr[i+1] = arr[i] ⊕ encoded[i]`），差异只在「如何拿到 `arr[0]`」。1720 直接给定，1734 靠「排列的全集异或 + 奇偶配对抵消」反推。这正是「简单题给进阶题铺路」的典型设计——掌握 1720 的递推骨架，1734 只需补一个求首元素的预处理。

## 6. 面试要点

**Q1：为什么能用 `arr[i] ⊕ encoded[i]` 直接求 `arr[i+1]`？数学依据是什么？**
> 依据异或的**自反性**：$a \oplus a = 0$ 且 $a \oplus 0 = a$。由编码等式 $\text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i+1]$，两边同时异或 $\text{arr}[i]$，得 $\text{arr}[i] \oplus \text{encoded}[i] = \text{arr}[i] \oplus \text{arr}[i] \oplus \text{arr}[i+1] = 0 \oplus \text{arr}[i+1] = \text{arr}[i+1]$。异或是其自身的逆运算，无需引入新运算。

**Q2：异或运算有哪些性质在解题中常用？**
> 四条核心性质：① **自反性** $a \oplus a = 0$；② **恒等性** $a \oplus 0 = a$；③ **交换律与结合律** $a \oplus b \oplus a = b$；④ **消去律** 若 $a \oplus b = a \oplus c$ 则 $b = c$（两边异或 $a$ 即得）。本题用自反性做反解，[136. 只出现一次的数字](https://leetcode.cn/problems/single-number/) 用自反性做去重，[26. 删除重复项] 类问题与之思想同源。

**Q3：为什么暴力的 $O(n \cdot V)$ 枚举不可取？如何识别「搜索 vs 计算」的误区？**
> 暴力把待求量当作「在值域中搜索满足等式的候选」，忽略了等式本身已**唯一确定**该量。识别信号：当约束是「$f(a, b) = c$」形式的等式，且 $f$ 可逆（异或、加法、乘法在非零下均可逆），就能直接反解而非搜索。本题 $n \cdot V \approx 10^9$ 必然超时，而 $O(n)$ 递推只需 $10^4$ 次。

**Q4：如果不给 `first`，还能解码吗？什么条件下可以？**
> 仅靠 `encoded` 不行——首元素缺失会使整条链平移任意偏移，答案不唯一（题目也强调「答案存在且唯一」依赖 `first`）。但若附加约束暴露了首元素信息则可解：如 1734 中 `arr` 是 $[1..n]$ 的排列且 $n$ 为奇数，可由全集异或 $1 \oplus 2 \oplus \dots \oplus n$ 与偶数项配对抵消反推 `arr[0]`。本质是用「额外结构」补上缺失的首元素。

**Q5：代码中 `arr[i+1] = arr[i] ^ encoded[i]` 为什么不会溢出？**
> 异或是**按位**运算，不产生进位，结果的有效位数不超过操作数的最高位。本题值域 $\le 10^5 < 2^{17}$，异或结果仍在 17 位以内，远小于 32 位 `int` 上限 $2^{31}-1$。这与加法/乘法题不同——后者可能因进位/放大而溢出，需考虑 `long long`。
