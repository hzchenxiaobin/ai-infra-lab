# LeetCode 石子游戏 VI 题解

## 1. 题目概述

- **标题 / 题号**：石子游戏 VI（#1686，medium）
- **链接**：https://leetcode.cn/problems/stone-game-vi
- **难度**：中等
- **标签**：贪心、博弈、排序

**题意**：Alice 和 Bob 轮流玩一个游戏，Alice 先手。一堆石子里总共有 `n` 个石子，轮到某个玩家时，他可以**移除**一个石子并得到这个石子的价值。Alice 和 Bob 对石子价值有**不一样的评判标准**，双方都知道对方的评判标准。

给你两个长度为 `n` 的整数数组 `aliceValues` 和 `bobValues`，`aliceValues[i]` 和 `bobValues[i]` 分别表示 Alice 和 Bob 认为第 `i` 个石子的价值。所有石子都被取完后，得分较高的人为胜者；得分相同则为平局。两位玩家都会采用**最优策略**。

- Alice 赢返回 `1`；Bob 赢返回 `-1`；平局返回 `0`。

**示例 1**：

```text
输入：aliceValues = [1,3], bobValues = [2,1]
输出：1
解释：Alice 拿石子 1（下标从 0 开始）得到 3 分；Bob 只能拿石子 0 得到 2 分。Alice 获胜。
```

**示例 2**：

```text
输入：aliceValues = [1,2], bobValues = [3,1]
输出：0
解释：Alice 拿石子 0，Bob 拿石子 1，两人都得 1 分，打平。
```

**示例 3**：

```text
输入：aliceValues = [2,4,3], bobValues = [1,6,7]
输出：-1
解释：无论 Alice 怎么操作，Bob 都可以得到比 Alice 更高的得分。Bob 获胜。
```

**约束**：

- `n == aliceValues.length == bobValues.length`
- `1 <= n <= 10^5`
- `1 <= aliceValues[i], bobValues[i] <= 100`

> 💡 本题是「石子游戏」系列的变体。与 [877. 石子游戏](../0801-0900/877_石子游戏.md)（固定取首/尾、区间 DP 博弈）不同，本题**可任取任意一颗石子**，且**双方对同一颗石子的估值不同**。关键转化是：取走一颗石子既让自己得分，又剥夺了对手的得分，于是「有效优先级」= 两人估值之和 $a[i] + b[i]$，双方对此排序完全一致 → 贪心即可。

## 2. 解题思路

### 2.1 暴力思路：枚举所有取法

博弈树有 $n!$ 种取法分支（每个玩家每步可任取剩余石子），$n \leq 10^5$ 完全不可行。需要找到双方「不冲突」的统一优先级，把博弈降为排序。

### 2.2 核心观察：取一颗石子 = 自己得分 + 剥夺对手得分

![核心观察：取走石子 i 让自己得到本方估值，同时令对手失去那份估值，故对分差的净影响 = a[i] + b[i]](../images/1686_concept.svg)

每颗石子 $i$ 有两套估值：Alice 视为 $a[i]$，Bob 视为 $b[i]$。**取走石子 $i$ 产生两个效果**：

1. **自己得分**：取的人获得本方估值（Alice 取则得 $a[i]$，Bob 取则得 $b[i]$）。
2. **剥夺对手**：对手再也拿不到这颗，少得对手估值（Alice 取则 Bob 少得 $b[i]$；Bob 取则 Alice 少得 $a[i]$）。

从「**分差（Alice − Bob）**」视角看，无论谁取，这颗石子对分差的**绝对影响幅度**都是 $a[i] + b[i]$：

- Alice 取 $i$：分差 $+a[i]$（Alice 进账）$+b[i]$（Bob 本可得的被剥夺，等价于相对多领先 $b[i]$）→ 净 $+s[i]$，其中 $s[i] = a[i] + b[i]$。
- Bob 取 $i$：分差 $-b[i]$（Bob 进账）$-a[i]$（Alice 本可得的被剥夺）→ 净 $-s[i]$。

> 💡 **关键转化**：定义每颗石子的**有效优先级** $s[i] = a[i] + b[i]$。$s[i]$ 越大，这颗石子对分差的影响越大，越该被**先取**。下文 2.5 用交换论证证明：Alice 和 Bob 对 $s[i]$ 的排序**完全一致**，无博弈分歧，因此双方都贪心取当前 $s$ 最大的石子即为最优。

### 2.3 算法流程图

![算法流程：求 s[i]=a[i]+b[i] → 按 s 降序排 → Alice 取偶数位、Bob 取奇数位 → 比分定胜负](../images/1686_algorithm_flow.svg)

既然双方都按 $s[i]$ 降序贪心取，整个游戏等价于：

1. 对每个石子求 $s[i] = a[i] + b[i]$。
2. 将石子按 $s[i]$ **降序**排列（得到取石顺序）。
3. Alice 先手取排序后的**偶数位**（下标 0, 2, 4, …），Bob 取**奇数位**（下标 1, 3, 5, …）。
4. Alice 得分 $= \sum_{k \text{ 偶}} a[\text{order}[k]]$，Bob 得分 $= \sum_{k \text{ 奇}} b[\text{order}[k]]$。
5. 比分：Alice 大返回 `1`，Bob 大返回 `-1`，相等返回 `0`。

### 2.4 示例演算

以示例 1（`a = [1, 3]`，`b = [2, 1]`）和示例 3（`a = [2, 4, 3]`，`b = [1, 6, 7]`）为例：

![示例演算：示例1 按 s=[3,4] 降序得石子1、0，Alice 取1得3、Bob 取0得2 → 返回1；示例3 按 s=[3,10,10] 降序，Alice 得4+2=6、Bob 得7 → 返回-1](../images/1686_example_walkthrough.svg)

**示例 1**：$s = [3, 4]$，降序为石子 1（$s=4$）、石子 0（$s=3$）。Alice 取石子 1 得 $a[1]=3$；Bob 取石子 0 得 $b[0]=2$。$3 > 2$ → 返回 `1`。

**示例 3**：$s = [3, 10, 10]$，降序为石子 1、石子 2（同和可互换）、石子 0。Alice 取石子 1 得 $4$、Bob 取石子 2 得 $7$、Alice 取石子 0 得 $2$。Alice 共 $6$、Bob 共 $7$，$6 < 7$ → 返回 `-1`。

> ⚠️ 示例 3 中石子 1、2 的 $s$ 相等（均为 10），谁排前都不影响最终比分——见 2.5 末尾「同和无害」结论。

### 2.5 贪心最优性证明（交换论证）

**引理（两颗石子的交换论证）**：考虑任意两颗石子 $i$、$j$，假设当前轮到某玩家 $P$ 选择（$P$ 为 Alice 或 Bob），且两颗都会被取走（同一人或分给两人）。比较两种取法对「$P$ 的净领先」的贡献：

- $P$ 取 $i$、对手取 $j$：贡献 $= v_P[i] - v_{\text{对手}}[j]$
- $P$ 取 $j$、对手取 $i$：贡献 $= v_P[j] - v_{\text{对手}}[i]$

两者之差：

$$\bigl(v_P[i] - v_{\text{对手}}[j]\bigr) - \bigl(v_P[j] - v_{\text{对手}}[i]\bigr) = \bigl(a[i] + b[i]\bigr) - \bigl(a[j] + b[j]\bigr) = s[i] - s[j]$$

> 验证：若 $P$ = Alice，$v_P = a$、$v_{\text{对手}} = b$，差 $= (a[i]-b[j])-(a[j]-b[i]) = s[i]-s[j]$；若 $P$ = Bob，$v_P = b$、$v_{\text{对手}} = a$，差 $= (b[i]-a[j])-(b[j]-a[i]) = s[i]-s[j]$。**两种角色下公式完全相同**。

- 若 $s[i] > s[j]$：差为正 → $P$ 取 $i$ 更优。**无论 $P$ 是 Alice 还是 Bob 结论一致**。
- 若 $s[i] = s[j]$：差为零 → 两种取法对 $P$ 的净领先贡献相同，**无差别**。

**定理**：双方都贪心取当前 $s$ 最大的石子，是博弈的最优解（Nash 均衡）。

> 由引理，任意一步若某玩家未取 $s$ 最大的可用石子 $g$、而取了 $s$ 较小的石子 $i$，则存在一个交换使其不劣：若 $g$ 与 $i$ 归同一人，交换顺序不改变归属、得分不变；若归两人，由引理当前玩家取 $g$ 净赚 $s[g]-s[i] > 0$。反复交换可把任意取法序列调整为按 $s$ 降序而不损害当前玩家利益。因此贪心取法不劣于任何策略，对双方均最优。$\square$

> 💡 **同和无害**：$s[i]=s[j]$ 时两种取法对分差贡献相同，故同和石子的相对顺序**不影响最终比分**，排序稳定与否皆可。

## 3. 参考代码

### Python

```python
class Solution:
    def stoneGameVI(self, aliceValues: List[int], bobValues: List[int]) -> int:
        n = len(aliceValues)
        # 按第三方值 s[i] = a[i] + b[i] 降序排石子下标
        order = sorted(range(n),
                       key=lambda i: aliceValues[i] + bobValues[i],
                       reverse=True)
        # Alice 取偶数位，Bob 取奇数位
        alice = sum(aliceValues[order[k]] for k in range(0, n, 2))
        bob   = sum(bobValues[order[k]]   for k in range(1, n, 2))
        if alice > bob:
            return 1
        if alice < bob:
            return -1
        return 0
```

### C++

```cpp
// 1686. 石子游戏 VI.cpp —— 贪心：按 a[i]+b[i] 降序排，交替取石子
// 编译: g++ -O2 -std=c++17 1686.cpp -o sg6
class Solution {
public:
    int stoneGameVI(vector<int>& aliceValues, vector<int>& bobValues) {
        int n = aliceValues.size();
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int i, int j) {
            return aliceValues[i] + bobValues[i] > aliceValues[j] + bobValues[j];
        });
        long long alice = 0, bob = 0;
        for (int k = 0; k < n; k++) {
            if (k & 1) bob   += bobValues[order[k]];   // 奇数位 → Bob
            else       alice += aliceValues[order[k]]; // 偶数位 → Alice
        }
        return alice > bob ? 1 : (alice < bob ? -1 : 0);
    }
};
```

> 💡 **实现细节**：① Python 用 `sorted(range(n), key=...)` 对下标排序，避免动原数组；`range(0, n, 2)` / `range(1, n, 2)` 简洁地分出偶/奇位。② C++ 用 `iota` 生成下标数组 + lambda 排序；`n ≤ 10^5`、值 `≤ 100`，总分上限 $10^7$，`int` 足够但用 `long long` 更稳妥。③ 不需要真正模拟博弈——排序后一次遍历即可定胜负。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | $O(n \log n)$ | 排序主导；求和与比分为 $O(n)$ |
| **空间** | $O(n)$ | 存下标数组 `order` |

> ⚠️ $n \le 10^5$，$O(n \log n)$ 约 $1.7 \times 10^6$ 次比较，远低于时限。值域 $[1, 100]$ 可用计数排序做到 $O(n)$，但常数收益有限、可读性变差，此处不必。

## 5. 扩展：值域计数排序的 $O(n)$ 写法

由于 $a[i], b[i] \in [1, 100]$，$s[i] \in [2, 200]$，可用桶排序替代通用排序：

```python
class Solution:
    def stoneGameVI(self, aliceValues: List[int], bobValues: List[int]) -> int:
        n = len(aliceValues)
        buckets = [[] for _ in range(201)]          # s ∈ [2, 200]
        for i in range(n):
            buckets[aliceValues[i] + bobValues[i]].append(i)
        alice = bob = 0
        turn = 0                                    # 0 = Alice, 1 = Bob
        for s in range(200, 1, -1):                  # 从大到小取
            for i in buckets[s]:
                if turn == 0:
                    alice += aliceValues[i]
                else:
                    bob += bobValues[i]
                turn ^= 1
        return 1 if alice > bob else (-1 if alice < bob else 0)
```

时间 $O(n + V)$，$V = 200$；空间 $O(n)$。当 $n$ 极大、值域小时比 $O(n \log n)$ 更优。

## 6. 面试要点

1. **为什么优先级是 $a[i] + b[i]$ 而不是只看自己的估值 $a[i]$？**

   > 取走一颗石子有两个效果：自己得分 + 剥夺对手得分。只看自己估值会忽略「剥夺」部分——一颗对 Alice 估值不高但对 Bob 估值很高的石子，Alice 先取可重创 Bob。$a[i] + b[i]$ 恰好度量了这颗石子对分差的总影响幅度。

2. **为什么两人都用同一个排序就是最优？不会出现「Alice 想先取 $i$、Bob 想先取 $j$」的冲突吗？**

   > 不会。由交换论证，对任意两颗石子 $i, j$，Alice 偏好取 $s$ 大的那颗（差 $= s[i]-s[j]$），Bob 同样偏好取 $s$ 大的那颗（公式完全相同）。两人对优先级的排序**完全一致**，无博弈分歧，因此贪心是双方的最优响应。

3. **同和（$s[i] = s[j]$）时谁排前会影响结果吗？**

   > 不会。由引理，$s[i]=s[j]$ 时两种取法对任一玩家的净领先贡献相同（差为零）。故同和石子的相对顺序不影响最终比分，排序是否稳定皆可。

4. **本题与 877「石子游戏」的区别？**

   > 877 只能从两端取（区间 DP 博弈，`dfs(l,r)` 四态转移），且双方估值相同；本题可任取、双方估值不同，但通过 $a[i]+b[i]$ 把异构估值统一为单一优先级，反而更简单（排序贪心，无需 DP）。

5. **为什么不需要记忆化搜索或 DP？**

   > 因为双方优先级一致，博弈退化为「按固定顺序交替取」——没有「分支选择」需要搜索。排序后偶/奇位即确定归属，一遍求和即可。这是「博弈但无博弈树」的典型：当存在双方共识的统一优先级时，贪心即可。

> 💡 **一句话总结**：1686 的关键是发现取一颗石子对分差的净影响 $= a[i]+b[i]$（自己得分 + 剥夺对手），且 Alice、Bob 对此排序一致 → 按 $s$ 降序排、Alice 取偶数位 Bob 取奇数位、比分定胜负。$O(n \log n)$ 时间、$O(n)$ 空间。
