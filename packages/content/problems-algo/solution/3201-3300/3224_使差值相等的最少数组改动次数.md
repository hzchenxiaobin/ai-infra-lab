# LeetCode 使差值相等的最少数组改动次数 题解

## 1. 题目概述

- **标题 / 题号**：使差值相等的最少数组改动次数（#3224，medium）
- **链接**：https://leetcode.cn/problems/minimum-array-changes-to-make-differences-equal/
- **难度**：中等
- **标签**：数组、哈希表、前缀和、计数

**题意**：给你一个长度为 $n$ 的整数数组 `nums`，$n$ 是**偶数**，同时给你一个整数 $k$。你可以对数组进行一些操作：每次操作中，你可以将数组中**任一**元素替换为 $0$ 到 $k$ 之间的**任一**整数。

执行完所有操作以后，你需要确保最后得到的数组满足以下条件：存在一个整数 $X$，满足对于所有的 $0 \le i < n/2$ 都有 $\text{abs}(a_i - a_{n-i-1}) = X$。

请你返回满足以上条件的**最少**修改次数。

**示例 1**：

```text
输入：nums = [1,0,1,2,4,3], k = 4
输出：2
解释：将 nums[1] 变为 2、nums[3] 变为 3，得到 [1,2,1,3,4,3]，
     三对 (1,3)、(2,4)、(1,3) 的差值都等于 X = 2。
```

**示例 2**：

```text
输入：nums = [0,1,2,3,3,6,5,4], k = 6
输出：2
解释：将 nums[3] 变为 0、nums[4] 变为 4，得到 [0,1,2,0,4,6,5,4]，
     四对 (0,4)、(1,5)、(2,6)、(0,4) 的差值都等于 X = 4。
```

**约束**：

- $2 \le n = \text{nums.length} \le 10^5$
- $n$ 是偶数
- $0 \le \text{nums}[i] \le k \le 10^5$

> 💡 **审题关键**：① 「**存在**一个整数 $X$」说明 $X$ 没有事先给定——我们其实可以**自由枚举** $X \in [0, k]$ 取最优（改完后所有元素都在 $[0, k]$ 内，差值不可能超过 $k$，所以 $X > k$ 无需考虑）；② 数组按中心对称配成 $n/2$ 对 $(a_i, a_{n-i-1})$，**各对之间完全独立、零交互**，总修改次数就是各对代价之和；③ 每对代价上界是 2（大不了两个都改）——这三点合起来暗示了「枚举 $X$ + 按对分桶计数」的解法。

## 2. 解题思路

### 2.1 暴力思路：枚举 X × 逐对判定

最直接的做法：外层枚举 $X$ 从 $0$ 到 $k$（共 $k+1$ 种），内层遍历 $n/2$ 对，逐对判定改成差值 $X$ 的最小代价并求和，最后对所有 $X$ 取最小。

逐对判定本身是 $O(1)$ 的（只需比较 $X$ 与下面要讲的两个量 $d$、$M$），但总复杂度 $O(n \cdot k)$，在 $n = k = 10^5$ 时是 $10^{10}$，必然超时。

瓶颈在于：**同一对的信息被不同的 $X$ 反复重算**。反过来看，每对的代价只由两个数决定——如果先把「对」按这两个数分桶计数，那么「每个 $X$ 求总代价」就能从 $O(n)$ 摊销到 $O(1)$，整体降到 $O(n + k)$。

### 2.2 核心观察：单对代价三档 + 两桶计数

![核心观察：单改一个数可达差值 [0, M]，单对代价只有 0/1/2 三档](../images/p3224_pair_cost_concept.svg)

**观察 1（改一个数能到哪些差值）**：固定一对 $(a, b)$。只改 $a$（新值 $a' \in [0, k]$）时，$a'$ 从 $b$ 滑向 $0$ 让 $|a'-b|$ 覆盖 $[0, b]$，从 $b$ 滑向 $k$ 让它覆盖 $[0, k-b]$；只改 $b$ 同理覆盖 $[0, \max(a, k-a)]$。合并四种「单改」方案的可达差值，恰好是连续区间：

$$[0, M], \qquad M = \max(a,\ b,\ k-a,\ k-b)$$

（四个候选分别来自 $a \to 0$、$a \to k$、$b \to 0$、$b \to k$。）

**观察 2（单对代价只有三档）**：固定目标 $X \in [0, k]$，记 $d = |a - b|$，一对 $(a, b)$ 的最少修改次数为：

| 条件 | 代价 | 说明 |
|------|------|------|
| $X = d$ | $0$ | 本来就是目标差值 |
| $X \le M$ 且 $X \ne d$ | $1$ | 改一个数即可送到位 |
| $X > M$ | $2$ | 单改无解，两个都改：$a' = X,\ b' = 0$ |

关键在于三档判定**只依赖 $(d, M)$ 两个数**，与 $a$、$b$ 的具体取值无关。注意 $d \le \max(a, b) \le M$ 恒成立，三档互斥且完备；而 $X \le k$ 保证了两改方案 $a' = X,\ b' = 0$ 永远可行，所以单对代价确实封顶于 2。

**观察 3（$M$ 的下界）**：$a$ 与 $k - a$ 必有一个 $\ge \lceil k/2 \rceil$，故 $M \ge \lceil k/2 \rceil$ 恒成立。推论：当 $X \le \lceil k/2 \rceil$ 时根本不存在「两改」对，且 $cnt$ 桶只会在值域右半边非空——这既是正确性的 sanity check，也提示扫描的前半程公式退化为 $\text{cost}(X) = n/2 - diff[X]$。

**观察 4（总代价公式）**：把 $n/2$ 对全部按 $(d, M)$ 分桶——$diff[x]$ 记 $d = x$ 的对数（零改桶），$cnt[m]$ 记 $M = m$ 的对数（单改上限桶）。固定 $X$ 时：

$$\text{cost}(X) = \underbrace{\left(\frac{n}{2} - diff[X]\right)}_{d \ne X\ \text{的对，至少一改且一改够用}} + \underbrace{\#\{M < X\}}_{M < X\ \text{的对补第二次}}$$

推导：$d \ne X$ 的对至少改一次；其中 $M \ge X$ 的恰改一次即可，$M < X$ 的必须改两次（在一改的基础上再加一）。对 $cnt$ 做前缀和即可 $O(1)$ 拿到 $\#\{M < X\}$，于是 $k+1$ 个候选 $X$ 全部算完只要线性一趟。

### 2.3 算法流程图

![算法流程：两桶计数 + 一次线性扫描 X ∈ [0, k]，O(n + k)](../images/p3224_sweep_formula.svg)

| 步骤 | 操作 | 作用 |
|------|------|------|
| ① 配对 | $i \leftrightarrow n-1-i$，逐对算 $d = \|a-b\|$ 与 $M = \max(a, b, k-a, k-b)$ | 把 $10^5$ 个数压缩成 $n/2$ 个 $(d, M)$ 二元组 |
| ② 入桶 | $diff[d]{+}{=}1$；$cnt[M]{+}{=}1$ | 按代价判定的两个关键量分类计数 |
| ③ 扫描 | $X$ 从 $0$ 到 $k$：$\text{cost}(X) = n/2 - diff[X] + less$，**先取值后累加** $less \mathrel{+}= cnt[X]$ | $less$ 滞后一步累加，恰好维护 $\#\{M < X\}$ |
| ④ 取最小 | 答案 $= \min_X \text{cost}(X)$ | 值域枚举收口 |

### 2.4 示例演算

![示例演算：nums = [0,1,2,3,3,6,5,4]，k = 6 的 X 扫描全过程](../images/p3224_example_walkthrough.svg)

拿示例 2 走一遍。$n = 8$，配出 4 对：$(0,4)$、$(1,5)$、$(2,6)$、$(3,3)$，对应 $(d, M)$ 为 $(4,6)$、$(4,5)$、$(4,6)$、$(0,3)$。于是 $diff = \{0{:}1,\ 4{:}3\}$，$cnt = \{3{:}1,\ 5{:}1,\ 6{:}2\}$。

扫描 $X = 0 \ldots 6$（`less` 初值 0，每到新 $X$ 先算 $\text{cost} = 4 - diff[X] + less$，再把 $cnt[X]$ 吃进 `less`）：

| $X$ | $diff[X]$ | less（$\#\{M<X\}$） | cost = $4 - diff + less$ | 备注 |
|-----|-----------|--------------------|--------------------------|------|
| 0 | 1 | 0 | 3 | (3,3) 白嫖 |
| 1 | 0 | 0 | 4 | |
| 2 | 0 | 0 | 4 | |
| 3 | 0 | 0 | 4 | 用完后 less 吃进 $cnt[3]=1$ |
| **4** | **3** | **1** | **2 ★** | 三对白嫖，(3,3) 两改 |
| 5 | 0 | 1 | 5 | less 吃进 $cnt[5]=1$ |
| 6 | 0 | 2 | 6 | |

最小值 2 出现在 $X = 4$：$(0,4)$、$(1,5)$、$(2,6)$ 三对的差值**本来**就是 4（零修改），只剩 $M = 3 < 4$ 的 $(3,3)$ 需要两改成 $(0,4)$——与官方示例「`nums[3]` 变 0、`nums[4]` 变 4」完全吻合。注意 $X \le \lceil 6/2 \rceil = 3$ 的行 `less` 全是 0，正印证了观察 3。

## 3. 参考代码

### C++

```cpp
class Solution {
public:
    int minChanges(vector<int>& nums, int k) {
        int n = nums.size(), half = n / 2;
        vector<int> diff(k + 1, 0), cnt(k + 1, 0);
        for (int i = 0; i < half; ++i) {
            int a = nums[i], b = nums[n - 1 - i];
            ++diff[abs(a - b)];                    // 零改桶：差值本来就是 d
            ++cnt[max({a, b, k - a, k - b})];      // 单改上限桶：X <= M 一改够用
        }
        int ans = INT_MAX;
        for (int X = 0, less = 0; X <= k; ++X) {   // less = #{M < X}
            ans = min(ans, half - diff[X] + less);
            less += cnt[X];                        // 滞后一步累加
        }
        return ans;
    }
};
```

> 💡 **写法要点**：`less += cnt[X]` 必须放在 `ans` 更新**之后**——$X$ 处需要的是 $M < X$（即 $M \le X-1$）的对数，$M = X$ 的对在 $X$ 处仍属「一改够用」，要等 $X$ 用完才能计入。两个桶大小都是 $k+1$：$d \in [0, k]$ 自不必说，$M = \max(a, b, k-a, k-b)$ 四个分量都不超过 $k$。

### Python

```python
class Solution:
    def minChanges(self, nums: List[int], k: int) -> int:
        half = len(nums) // 2
        diff = [0] * (k + 1)   # 零改桶：d = x 的对数
        cnt = [0] * (k + 1)    # 单改上限桶：M = m 的对数
        for i in range(half):
            a, b = nums[i], nums[-1 - i]
            diff[abs(a - b)] += 1
            cnt[max(a, b, k - a, k - b)] += 1
        ans, less = float('inf'), 0
        for X in range(k + 1):
            ans = min(ans, half - diff[X] + less)
            less += cnt[X]     # 先用后加：保证 less = #{M < X}
        return ans
```

> 💡 想验证正确性，可以写一个 $O(nk)$ 的暴力对拍版：枚举每个 $X$、逐对按「$d = X$ → 0 / $X \le M$ → 1 / 否则 2」累加。两者在小数据全区间一致即可放心提交。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| **时间** | $O(n + k)$ | 一趟配对遍历 $O(n)$ + 一趟值域扫描 $O(k)$ |
| **空间** | $O(k)$ | `diff` 与 `cnt` 两个计数桶 |
| 暴力对照 | $O(n \cdot k)$ | 枚举 $X \times$ 逐对判定，$10^{10}$ 不可行 |

## 5. 扩展：孪生题 1674 与「枚举答案值域」范式

本题的母题是 [1674. 使数组互补的最少操作次数](https://leetcode.cn/problems/minimum-moves-to-make-array-complementary/)：把「每对**差值**等于 $X$」换成「每对**和**等于 $target$」，每次操作同样能把元素改成 $[1, k]$ 内任意值。那边单对代价同样是三档——$target \in [a+b+2,\ \min(a,b)+k]$ 内一改，恰为 $a+b$ 零改，其余两改——只是「一改区间」两端都活了，所以用**差分数组做区间加**来统计每个 $target$ 的总代价。

两题共享同一个范式，值得总结：

> 🎯 **枚举答案值域 + 计数摊销**：当①答案候选是一个不大的值域（本题 $[0, k]$），②每个候选的代价能拆成「逐对象贡献之和」，且③单个贡献分段常数（三档 0/1/2），就可以放弃对每个候选暴力重算，转而**按贡献分桶 / 差分**，一次线性扫描把所有候选的代价全部求出。前缀和与差分正是这类题的一体两面：分界点稀疏用桶 + 前缀和（本题），区间型贡献用差分数组（1674）。

反过来，若值域大到无法枚举（如 $10^9$），就必须换武器——排序 + 双指针、数学求极值或二分答案（单调验证）——这也是面试时值得主动提的边界判断。

## 6. 面试要点

1. **为什么 $X$ 只需枚举 $[0, k]$？**

   每次操作只能把元素改成 $[0, k]$ 内的整数，最终任意两数之差不超过 $k$；$X > k$ 时任何一对都无法满足，无需考虑。而 $X \in [0, k]$ 时每对至多两改必可满足（$a' = X,\ b' = 0$），所以答案一定存在。

2. **为什么单对代价封顶是 2？三档判定为什么只需 $d$ 和 $M$？**

   单改 $a$ 能到的差值集合是 $[0, \max(b, k-b)]$，单改 $b$ 是 $[0, \max(a, k-a)]$，合并为 $[0, M]$，$M = \max(a, b, k-a, k-b)$。于是 $X = d$ 零改；$X \le M$ 一改（$X \le b$ 取 $a' = b - X$，$X \le k-b$ 取 $a' = b + X$，改 $b$ 同理）；$X > M$ 时两条单改路都够不着，只能两改。$d \le M$ 保证三档互斥完备。

3. **`less` 为什么要「先用后加」？**

   $X$ 处的公式需要 $\#\{M < X\}$，即 $M \le X - 1$；$M = X$ 的对在 $X$ 处还属于「一改够用」。所以必须先用当前 `less` 算 $\text{cost}(X)$，再把 $cnt[X]$ 累加进去供 $X+1$ 使用——这就是前缀和的滞后一步写法。

4. **$M \ge \lceil k/2 \rceil$ 有什么用？**

   它来自 $\max(a, k-a) \ge k/2$。用途有二：一是口算 sanity check——$X \le \lceil k/2 \rceil$ 时两改项必为 0，公式退化为 $n/2 - diff[X]$；二是说明 `cnt` 桶只在值域右半非空，扫描左半程不产生任何累加。

5. **本题与 1674 的异同？**

   同为「配对独立 + 枚举目标值域 + 单对代价分档计数」。区别在于本题的一改区间是 $[0, M]$ 只有右端点活了，用普通桶 + 前缀和；1674 的一改区间 $[\min(a,b)+2,\ a+b+k]$ 两端都活，用差分数组做区间加。两者是同一范式在不同「贡献形状」下的两种实现。
