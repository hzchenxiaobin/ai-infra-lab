# LeetCode 两个对象之间的差异 题解

## 1. 题目概述

- **标题 / 题号**：两个对象之间的差异（#2700，medium）
- **链接**：https://leetcode.cn/problems/differences-between-two-objects/
- **难度**：中等
- **标签**：递归、深度差异、JSON、类型分派

> ⚠️ 本题为 LeetCode 付费题，题意描述根据官方示例用例与 hints 重建，可能与官方题面有出入。

**题意**：给定两个 JSON 值 `obj1` 与 `obj2`，返回一个**新对象**，表示两者之间的「差异」（differences）。差异只记录「共有键/下标中取值不同」的部分，规则如下：

- **只看交集**：仅比较两者**共有**的键（对象）或下标（数组）；只出现在一侧的键/下标直接忽略，不计入差异。
- **递归求差异**：对每个共有键/下标，递归比较取值——
  - 两值**严格相等**（`===`）或递归后无任何差异 → 该键/下标**省略**，不出现在结果中；
  - 两值都是**数组** → 按下标交集递归，结果仍是一个数组（无差异的下标省略为空槽）；
  - 两值都是**对象**（非数组）→ 按键交集递归，结果仍是一个对象；
  - **否则**（原始值不同、类型不一致、一为 `null` 一为容器）→ 这是一个**叶差异**，记为 `[obj1 的值, obj2 的值]`。
- **空则省略**：若某次递归得到空容器（空对象 `{}` / 无差异的空数组），则在父层省略该键。

**示例 1**：

```text
输入：obj1 = {}, obj2 = {"a": 1, "b": 2}
输出：{}
解释：无共有键，交集为空 → 没有任何差异。
```

**示例 2**：

```text
输入：obj1 = {"a": 1, "v": 3, "x": [], "z": {"a": null}}
      obj2 = {"a": 2, "v": 4, "x": [], "z": {"a": 2}}
输出：{"a": [1, 2], "v": [3, 4], "z": {"a": [null, 2]}}
解释：
  a: 1≠2 → 叶差异 [1, 2]
  v: 3≠4 → 叶差异 [3, 4]
  x: [] vs [] → 两空数组下标交集为空 → 无差异 → 省略
  z: 同为对象，唯一共有键 a 中 null≠2 → {"a": [null, 2]}
```

**示例 3**：

```text
输入：obj1 = {"a": 5, "v": 6, "z": [1, 2, 4, [2, 5, 7]]}
      obj2 = {"a": 5, "v": 7, "z": [1, 2, 3, [1]]}
输出：{"v": [6, 7], "z": [∅, ∅, [4, 3], [[2, 1]]]}
解释：（∅ 表示「无差异被省略的下标空槽」）
  a: 5===5 → 省略
  v: 6≠7 → 叶差异 [6, 7]
  z: 同为数组，按下标 0..3 递归——
     下标 0: 1===1 → 省略（空槽 ∅）
     下标 1: 2===2 → 省略（空槽 ∅）
     下标 2: 4≠3 → 叶差异 [4, 3]
     下标 3: [2,5,7] vs [1] 同为数组，下标交集仅 {0}——
              下标 0: 2≠1 → 叶差异 [2, 1]
              结果 = [[2, 1]]（长度 1，仅下标 0 有差异）
```

**示例 4**：

```text
输入：obj1 = {"a": {"b": 1}}, obj2 = {"a": [5]}
输出：{"a": [{"b": 1}, [5]]}
解释：a 的值一边是对象、一边是数组（数组性不一致）→ 直接叶差异 [{"b": 1}, [5]]。
```

**示例 5**：

```text
输入：obj1 = {"a": [1, 2, {}], "b": false}, obj2 = {"b": false, "a": [1, 2, {}]}
输出：{}
解释：a 的两数组逐下标全相同（含下标 2 的 {} vs {} 无共有键→无差异），整体无差异→省略；
      b: false===false → 省略。
```

**约束**：

- `obj1`、`obj2` 均为合法 JSON 值（不含 `undefined` / 函数 / Symbol / 循环引用）；
- 两值合并后的键 / 元素总数不超过 $10^5$（递归栈深度可控）。

> 💡 本题是 LeetCode「30 天 JavaScript」系列题目，**仅提供 JavaScript / TypeScript 提交入口**。它与 [2628. 完全相等的 JSON 对象](https://leetcode.cn/problems/json-deep-equal/) 是一对姊妹题：2628 沿 JSON 文法递归判「是否相等」返回布尔，本题把同一套递归骨架的 `false` 换成「收集差异 `[v₁, v₂]`」、把「要求键集/长度全等」放宽为「只看交集」。本文以 JS 为提交语言，并给出 Python 概念等价实现。

## 2. 解题思路

### 2.1 暴力思路：先判等再逐项枚举差异

最直白的「能跑」写法分两步：先用 2628 的 `areDeeplyEqual` 判两值是否相同，相同就跳过；不同就枚举所有键/下标逐一比较，遇到不同的就塞进结果。但这会把「判等」和「求差异」写成两套递归，重复遍历两遍结构；而且「不同」时还要再递归判断「是叶差异还是嵌套差异」，逻辑割裂。

> ⚠️ 更省事的 `JSON.stringify` 比字符串在此完全不可行：差异结果本身是一个**结构化对象**（`{key:[v1,v2]}`），不是布尔，序列化字符串无从表达「只保留差异键、省略相同键」。

### 2.2 核心观察：复用 2628 的递归骨架，把「判等」改写成「求差异」

![核心直觉：只比共有键/下标，相同处省略，不同的叶记为 [v₁, v₂]](../images/p2700_diff_concept.svg)

2628 的递归类型分派骨架在这里几乎原样可用，只需把「返回 `true/false`」改写成「返回差异结构」：

| 2628（判等） | 2700（求差异） | 关系 |
|--------------|----------------|------|
| `o1 === o2` → `true` | `obj1 === obj2` → `{}`（无差异） | 递归基不变，把 `true` 换成「空对象 = 无差异」 |
| 任一为 `null` / 类型不一致 → `false` | 同样条件 → `[obj1, obj2]`（叶差异） | 把 `false` 换成「记录两侧值」 |
| 数组：要求**等长** + 逐下标判等 | 数组：只看 **min 长度**（交集）+ 逐下标求差异 | 放宽为交集；相同下标省略 |
| 对象：要求**键集全同** + 逐键判等 | 对象：只看**共有键**（交集）+ 逐键求差异 | 放宽为交集；相同键省略 |

三个关键观察让它从 2628 自然延伸：

| 观察 | 含义 |
|------|------|
| **「无差异」用空容器 `{}` 表示** | 递归基 `===` 与「递归后键集为空」都映射到 `{}`；父层用 `Object.keys(d).length !== 0` 判「是否有差异」，空则省略该键/下标 |
| **交集而非全等** | 数组取 `min(len1,len2)` 个下标、对象取「双方都有的键」；只在一侧存在的键/下标直接忽略，不产生差异 |
| **叶差异恒为 `[v₁, v₂]`** | 一旦「不同型」（`null`/原始值/数组↔对象），就不再下钻，直接把两侧原值封进二元组返回——`Object.keys` 长度为 2，天然被判为「有差异」 |

> ⚠️ **「不同型」必须先于「同型容器」拦截**：`typeof null === 'object'`，若不先拦 `null`，它会被当成对象继续比键集而误入歧途；`[]` 与 `{}` 同为 `object` 但数组性不同（`Array.isArray`），混比会出错。这与 2628 的三道闸门完全一致——拦截顺序也是 `===` → `null` → `typeof` → `Array.isArray`。

> 💡 **为什么「省略空容器」天然成立**：叶差异 `[v₁,v₂]` 是长度 2 的数组，`Object.keys` 非空；而「无差异」是 `{}`（对象）或 `[]`（空数组，来自两空数组的下标交集为空），`Object.keys` 为空。两者用同一个 `Object.keys(d).length !== 0` 即可区分，无需额外标记位。

### 2.3 算法流程图

![算法流程：递归类型分派——同型容器下钻求差异，否则叶差异 [v₁, v₂]](../images/p2700_diff_algorithm_flow.svg)

决策是「短路」的：第 1 步命中递归基直接返回 `{}`；第 2 步一旦「不同型」立刻返回叶差异 `[obj1,obj2]`；只有「同为数组」或「同为对象」才进入第 3 步的循环，在交集上递归、收集非空差异，最后返回容器（可能为空 → 父层省略）。

### 2.4 示例演算

![示例演算：沿结构逐层下钻，相同处省略、不同叶收集为 [v₁, v₂]](../images/p2700_diff_example_walkthrough.svg)

以**示例 3** 为例（结构最丰富）：递归从根对象下钻到 `z` 数组，再下钻到 `z[3]` 的内层数组。每一层只在「共有键/下标」上推进，相同的（`a`、`z[0]`、`z[1]`）被省略为空槽 ∅，不同的叶（`v`、`z[2]`、`z[3][0]`）收集为 `[v₁,v₂]`，嵌套数组 `z[3]` 递归后仍是数组 `[[2,1]]`，结构同构地向上汇总成 `{ "v":[6,7], "z":[∅,∅,[4,3],[[2,1]]] }`。

## 3. 参考代码

### JavaScript / TypeScript（提交语言）

```javascript
/**
 * @param {Object|null|undefined} obj1
 * @param {Object|null|undefined} obj2
 * @return {Object}
 */
function objDiff(obj1, obj2) {
    // 1. 递归基：=== 覆盖 null===null、原始值严格相等、同引用 → 无差异 {}
    if (obj1 === obj2) return {};

    // 2. 不同型 → 叶差异 [obj1, obj2]
    //    （typeof null === 'object' 须先拦 null；Array.isArray 区分数组与对象）
    if (obj1 === null || obj2 === null
        || typeof obj1 !== 'object' || typeof obj2 !== 'object'
        || Array.isArray(obj1) !== Array.isArray(obj2)) {
        return [obj1, obj2];
    }

    // 3. 同型容器：在「交集」上递归、收集非空差异
    const result = Array.isArray(obj1) ? [] : {};
    const keys = Array.isArray(obj1)
        ? Array.from({ length: Math.min(obj1.length, obj2.length) }, (_, i) => i)
        : Object.keys(obj1).filter(k => Object.hasOwn(obj2, k));
    for (const key of keys) {
        const d = objDiff(obj1[key], obj2[key]);
        // 非空（有差异）才写入；{} / 空数组 的 Object.keys 长度为 0 → 省略
        if (Object.keys(d).length !== 0) result[key] = d;
    }
    return result;
}
```

> 💡 **数组下标的「省略」产生稀疏空槽**：对数组用 `result[key] = d`（而非 `push`）按原下标写入，无差异的下标不写入，形成稀疏数组（JS 中称为空槽/hole，序列化为 `null`）。这样结果保留了「差异在第几个下标」的位置信息；题解示例中的 ∅ 即这些空槽。若判题环境以紧凑列表为准，把 `result[key] = d` 换成 `result.push(d)` 即可（代价是丢失下标位置）。

TypeScript 版（带类型标注，分支展开以减少类型断言）：

```typescript
type Json = null | boolean | number | string | Json[] | { [k: string]: Json };

function objDiff(obj1: Json, obj2: Json): { [k: string]: Json } | Json[] {
    if (obj1 === obj2) return {};
    if (obj1 === null || obj2 === null
        || typeof obj1 !== 'object' || typeof obj2 !== 'object'
        || Array.isArray(obj1) !== Array.isArray(obj2)) {
        return [obj1, obj2];
    }
    if (Array.isArray(obj1) && Array.isArray(obj2)) {
        const result: Json[] = [];
        for (let i = 0; i < Math.min(obj1.length, obj2.length); i++) {
            const d = objDiff(obj1[i], obj2[i]);
            if (Object.keys(d as object).length !== 0) result[i] = d;
        }
        return result;
    }
    const r1 = obj1 as { [k: string]: Json };
    const r2 = obj2 as { [k: string]: Json };
    const result: { [k: string]: Json } = {};
    for (const k of Object.keys(r1)) {
        if (Object.hasOwn(r2, k)) {
            const d = objDiff(r1[k], r2[k]);
            if (Object.keys(d as object).length !== 0) result[k] = d;
        }
    }
    return result;
}
```

### Python（概念等价）

> 本题 LeetCode 仅开放 JS/TS，Python 版作概念对照。注意：① `bool` 是 `int` 子类（`True == 1`），须先判类型一致；② 大整数 `is` 不可靠（`257 is 257` 可能为 `False`），故原始值用 `==` 判等；③ Python 无 JS 的稀疏数组「空槽」，此处数组差异用「紧凑列表」（`append` 仅收集有差异项）表达，位置信息靠结构隐含。

```python
def objDiff(o1, o2):
    # 1. None：两者均 None → 无差异；否则叶差异
    if o1 is None or o2 is None:
        return {} if (o1 is None and o2 is None) else [o1, o2]
    # 2. bool 先于 int 判（True == 1，须严格分型）
    if isinstance(o1, bool) or isinstance(o2, bool):
        if isinstance(o1, bool) and isinstance(o2, bool):
            return {} if o1 == o2 else [o1, o2]
        return [o1, o2]
    # 3. 原始值（int/float/str）：== 判等，不等则叶差异
    if isinstance(o1, (int, float, str)) and isinstance(o2, (int, float, str)):
        return {} if o1 == o2 else [o1, o2]
    # 4. 同为数组：按下标交集递归、收集非空差异
    if isinstance(o1, list) and isinstance(o2, list):
        result = []
        for i in range(min(len(o1), len(o2))):
            d = objDiff(o1[i], o2[i])
            if d:                     # 非空（有差异）才收集
                result.append(d)
        return result
    # 5. 同为对象：按共有键递归、收集非空差异
    if isinstance(o1, dict) and isinstance(o2, dict):
        result = {}
        for k in o1:
            if k in o2:               # 只看共有键（交集）
                d = objDiff(o1[k], o2[k])
                if d:
                    result[k] = d
        return result
    # 6. 类型不一致（list↔dict，或原始值↔容器）→ 叶差异
    return [o1, o2]
```

> ⚠️ **Python 的 `if d:` 真值判定**：空 `{}`、空 `[]` 为假值→省略；叶差异 `[v₁,v₂]` 是非空列表→真值→保留。这与 JS 的 `Object.keys(d).length !== 0` 等价。本题叶差异恒为二元组且 `v₁===v₂` 会被递归基提前收口，不会出现单元素或「值恰好为假」的误判；但须先于 `int` 判 `bool`，否则 `True == 1` 会让 `objDiff(True, 1)` 误判无差异——这是两语言类型系统差异带来的对照点（与 2628 同）。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | $O(n)$ | $n$ 为两值合并后的键 / 元素总数；每个共有节点至多访问常数次，递归无重复下钻 |
| 空间复杂度 | $O(h)$ | $h$ 为嵌套深度（递归栈）；最坏退化到 $O(n)$（单条链状嵌套），通常 $h \ll n$ |

> 💡 本质是**一次结构同构的遍历**：递归沿两棵 JSON 树并行下钻，只在「共有」节点上推进，独有部分直接跳过（不像 2628 那样因键集/长度不全面短路 `false`）。差异结果的大小上界为共有叶差异数，遍历成本仍为 $O(n)$。

## 5. 扩展：diff vs deepEqual，以及「交集」语义的代价

- **2700 = 2628 的对偶**：2628 回答「相等吗？」（布尔），2700 回答「哪里不同？」（结构）。二者共用同一棵类型分派决策树，区别只在「同型容器分支」的聚合方式——2628 用 `&&` 聚合（全过才 `true`，遇不同短路），2700 用「收集非空差异」聚合（不短路，把不同处封进 `[v₁,v₂]`、相同处省略）。可以把 2700 看作 2628 的「**带定位的判等**」：不仅告诉你不同，还告诉你每一处不同的两侧值。
- **「交集」而非「全等」的取舍**：2628 要求键集/长度**完全相同**，任何缺失即判 `false`；2700 只看**交集**，只在一侧存在的键/下标被静默忽略。这意味着 `{a:1}` 与 `{a:1,b:2}` 的差异是 `{}`（`b` 被忽略）而非「有差异」——这是「只描述共同部分的不同」的语义选择。若要做成 `git diff` 式「左侧独有 / 右侧独有 / 双方不同」三态差异，需在叶差异之外再引入方向标记（如 `{"b":{">":2}}` 表示右侧独有），结构会从二元组升级为带方向的三态对象。
- **稀疏数组与位置语义**：JS 的 `result[i] = d`（仅对有差异的下标赋值）会留下空槽（hole），保留了「差异在第几个下标」。这是把数组当成「以整数为键的对象」的自然结果——对象省略键、数组省略下标，统一用「不写入」表达「无差异」。空槽序列化为 `null`，但 `null` 在差异格式中只可能出现在叶差异 `[null, x]`（被数组包裹）里，裸 `null` 在数组下标层即代表「省略槽」，二者可凭「是否被 `[v₁,v₂]` 包裹」区分。
- **循环引用**：本题保证无环。若放宽到可能环，朴素递归会栈溢出；标准做法是用 `Map` 记录已访问的 `(obj1, obj2)` 配对，重复配对即视为无差异（同构环必然同步相遇），这是 `lodash.isEqual` 的实现要点之一。

> 💡 工程实践中，`deep-diff`、`JSON-patch`（RFC 6902）、`immutability-helper` 都是对「结构化差异」的不同语义裁剪：RFC 6902 用 `op:add/remove/replace` 的路径序列表达差异，强调可还原（有 patch 即可重建）；本题的 `{key:[v₁,v₂]}` 则是只读的「两侧对照」。理解本题的递归分派，就理解了它们的核心骨架。

## 6. 面试要点

1. **本题与 2628 的关系是什么？复用了哪一部分？**

   > 二者是姊妹题，共用「沿 JSON 文法递归 + 类型分派」的骨架：`===` 作递归基、`null`/`typeof`/`Array.isArray` 三道闸门判同型。区别在聚合：2628 判等返回布尔（键集/长度须全同，遇不同短路 `false`），2700 求差异返回结构（只看交集，把不同封进 `[v₁,v₂]`、相同省略）。可把 2700 视作 2628 的「带定位判等」。

2. **「无差异」为什么用空对象 `{}` 表示？父层如何识别？**

   > 递归基 `obj1 === obj2` 与「递归后共有部分全相同」都映射到空容器 `{}` / `[]`。父层用 `Object.keys(d).length !== 0` 判「是否有差异」：叶差异 `[v₁,v₂]` 长度为 2 非空→保留；`{}` / 空数组长度为 0→省略。一个判定同时区分「叶差异」与「无差异」，无需额外标记位。

3. **为什么「不同型」要单独一步拦截，而不是直接进容器分支？**

   > 「不同型」包括：一边 `null`、一边原始值、或数组↔对象。这些都不应再下钻比键集/下标——`typeof null === 'object'` 会把 `null` 伪装成对象、`[]` 与 `{}` 同为 `object` 但不可混比。单独拦截后直接返回叶差异 `[v₁,v₂]`，既正确又短路，避免错误地继续递归。

4. **为什么只比较「交集」而非要求键集/长度全等？**

   > 差异的语义是「共同部分哪里不同」，不是「结构是否完全一致」。只在一侧存在的键/下标不产生「两侧取值不同」的事实，故静默忽略。这与 2628（判等时任何缺失都判 `false`）形成对照：判等关心「完整性」，求差异关心「共同处的分歧」。

5. **数组下标省略后会怎样？为什么用 `result[i] = d` 而非 `push`？**

   > 用 `result[i] = d` 只对有差异的下标赋值，无差异的下标不写入，形成稀疏数组空槽，保留了「差异在第几个下标」的位置信息。若用 `push` 则下标会被重排（紧凑列表），丢失原始位置。前者语义更完整（差异可定位），代价是空槽序列化为 `null`——但裸 `null` 在差异格式中只代表「省略槽」，与叶差异里的 `[null, x]`（被包裹）可凭结构区分。
