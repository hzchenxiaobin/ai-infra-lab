# LeetCode 把二叉搜索树转换为累加树 题解

## 1. 题目概述

- **标题 / 题号**：把二叉搜索树转换为累加树（#538，medium）
- **链接**：https://leetcode.cn/problems/convert-bst-to-greater-tree/
- **难度**：中等
- **标签**：树、BST、中序遍历

**题意**：给定一棵**二叉搜索树（BST）**的根节点 `root`，将其转换为**累加树（Greater Tree）**：每个节点的新值 = 原值 + 树中所有**大于**该原值的节点值之和。转换后返回新的根节点。

**示例 1**：

```text
输入：root = [4,1,6,0,2,5,7,null,null,null,3,null,null,null,8]
输出：[30,36,21,36,35,26,15,null,null,null,33,null,null,null,8]
```

**示例 2**：

```text
输入：root = [0,null,1]
输出：[1,null,1]
```

**示例 3**：

```text
输入：root = [1,0,2]
输出：[3,3,2]
```

**示例 4**：

```text
输入：root = [3,2,4,1]
输出：[7,9,4,10]
```

**约束**：

- 树中节点数在 `[0, 10^4]` 范围内
- `-10^4 <= Node.val <= 10^4`
- 树中所有值**互不相同**
- `root` 保证是一棵合法的 BST

> 💡 本题与 [1038. 把二叉搜索树转换为更大和树](https://leetcode.cn/problems/binary-search-tree-to-greater-sum-tree/) 完全同构，代码一字不改即可互用。

## 2. 解题思路

### 2.1 暴力思路：全量遍历两次

先一次遍历求出所有节点值的**总和** `total`，再一次遍历：对每个节点，新值 = `total - （所有小于该节点值的和）`。但「所有小于该节点值的和」并不好直接算——需要额外维护排名信息，实现繁琐且空间 `O(n)`。

更直接的暴力做法：对每个节点，再遍历一次整棵树累加所有大于它的值，时间 `O(n^2)`，显然不可取。

### 2.2 核心观察：反序中序遍历 + 累加

![反序中序累加](../images/bst_greater_concept.svg)

BST 的核心性质：**中序遍历（左→根→右）得到严格递增序列**。把它反过来——**右→根→左**——就得到**严格递减序列**。于是「所有大于当前节点的值」恰好就是「在反序中序中、排在当前节点**之前**访问的所有节点」。

维护一个全局累加变量 `sum`（初值 0），按**右→根→左**顺序遍历：

1. 先递归右子树（访问所有更大节点，`sum` 已累加好它们）。
2. 访问根：`sum += node.val`，再令 `node.val = sum`（此时 `sum` = 当前节点 + 所有大于它的值）。
3. 再递归左子树（继续累加更小的节点）。

> 💡 一句话记忆：**反序中序让「比当前大的」都先被访问**，因此一个滚动 `sum` 就够了，无需额外数组。

### 2.4 示例演算

![示例演算](../images/bst_greater_walkthrough.svg)

以 `root = [3,2,4,1]`（示例 4）为例，反序中序访问顺序为 `4 → 3 → 2 → 1`（降序）：

| 步骤 | 访问节点 | 累加和 `sum` | 新值 |
|------|----------|--------------|------|
| ①    | 4        | 0 + 4 = 4    | 4    |
| ②    | 3        | 4 + 3 = 7    | 7    |
| ③    | 2        | 7 + 2 = 9    | 9    |
| ④    | 1        | 9 + 1 = 10   | 10   |

转换后的累加树为 `[7,9,4,10]`，与官方输出一致。

## 3. 参考代码

### C++（递归反序中序）

```cpp
class Solution {
    int sum = 0;
  public:
    TreeNode* convertBST(TreeNode* root) {
        if (!root) return nullptr;
        convertBST(root->right);        // 右：先累加所有更大节点
        sum += root->val;               // 根：累加自己
        root->val = sum;                //     写回新值
        convertBST(root->left);         // 左：继续累加更小节点
        return root;
    }
};
```

### Python（递归反序中序）

```python
class Solution:
    def convertBST(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        self.sum = 0

        def dfs(node: Optional[TreeNode]) -> None:
            if not node:
                return
            dfs(node.right)              # 右：先累加所有更大节点
            self.sum += node.val         # 根：累加自己
            node.val = self.sum          #     写回新值
            dfs(node.left)               # 左：继续累加更小节点

        dfs(root)
        return root
```

### C++（迭代反序中序，显式栈）

```cpp
class Solution {
  public:
    TreeNode* convertBST(TreeNode* root) {
        stack<TreeNode*> st;
        TreeNode* cur = root;
        int sum = 0;
        while (cur || !st.empty()) {
            while (cur) {                // 一路向右压栈
                st.push(cur);
                cur = cur->right;
            }
            cur = st.top(); st.pop();    // 访问根
            sum += cur->val;
            cur->val = sum;
            cur = cur->left;             // 转向左子树
        }
        return root;
    }
};
```

> 💡 迭代版把「右-根-左」用栈模拟：压栈方向从「向左」改成「向右」，弹出即访问根，再转向左子树。与 [230. 第 K 小](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/) 的迭代中序是镜像关系。

## 4. 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间复杂度 | O(n) | 每个节点恰好访问一次（递归/迭代各一次入栈出栈） |
| 空间复杂度（递归） | O(H) | 递归栈深度等于树高；平衡时 O(log n)，链状退化为 O(n) |
| 空间复杂度（迭代） | O(H) | 显式栈深度同上 |
| 空间复杂度（Morris） | O(1) | 见第 5 节，利用线索指针免栈 |

> ⚠️ `sum` 只占 `O(1)` 额外空间；空间开销完全来自遍历本身的栈。

## 5. 扩展：Morris 遍历实现 O(1) 空间

若要求**严格 O(1) 额外空间**（不含递归栈），可用 **Morris 反序中序**：利用空闲的 `left` 指针建立临时线索，在 O(n) 时间内、O(1) 空间内完成。

```cpp
class Solution {
  public:
    TreeNode* convertBST(TreeNode* root) {
        TreeNode* cur = root;
        int sum = 0;
        while (cur) {
            if (cur->right == nullptr) {
                // 无右子树：直接访问当前节点，再转向左子树
                sum += cur->val;
                cur->val = sum;
                cur = cur->left;
            } else {
                // 找 cur 在反序中序下的「前驱」：右子树中最靠左的节点
                TreeNode* succ = cur->right;
                while (succ->left && succ->left != cur)
                    succ = succ->left;
                if (succ->left == nullptr) {
                    succ->left = cur;      // 建立线索，稍后能回到 cur
                    cur = cur->right;
                } else {
                    succ->left = nullptr;  // 线索已用，拆除
                    sum += cur->val;       // 访问 cur
                    cur->val = sum;
                    cur = cur->left;
                }
            }
        }
        return root;
    }
};
```

> 💡 Morris 的代价是**修改树结构**（临时挂线索再拆除），代码复杂度上升。面试中若没要求 O(1) 空间，递归版是更稳的默认选择；能把 Morris 讲清楚则是加分项。

## 6. 面试要点

1. **为什么反序中序能让一个 `sum` 解决问题？**
   - BST 中序升序 ⇒ 反序中序（右-根-左）降序 ⇒ 访问到某节点时，**之前访问过的都比它大**。于是滚动 `sum` 累加「已访问值」就是「所有大于当前值的和」，访问当前节点时 `sum += cur.val` 再写回即可，无需额外存储。

2. **递归和迭代版怎么选？**
   - 默认递归：代码最短、最不易写错。迭代版（显式栈）适合面试官追问「不用递归怎么做」或担心栈溢出（链状树高 n 时递归栈 O(n)）。Morris 则仅在明确要求 O(1) 空间时才上。

3. **新值为什么就等于累加后的 `sum`？**
   - 写回时机在 `sum += node.val` **之后**。此时 `sum` = （之前所有更大值之和）+ 当前值 = 题目要求的「原值 + 所有大于原值之和」，正好是新值。

4. **和 230（第 K 小）、98（验证 BST）有什么共通点？**
   - 都建立在「BST 中序有序」这一性质上。230 用中序找第 k 小（升序第 k 个），98 用中序单调性验证，538 用反序中序做后缀和。掌握中序这一个模板，能迁移到一整类 BST 题。

5. **进阶：如果频繁修改并频繁查询「大于 x 的和」，如何优化？**
   - 给每个节点维护 `size`（子树节点数）和 `subSum`（子树值之和），并保持平衡（AVL/红黑）。查询时按 BST 路径二分下降，把右子树整棵的 `subSum` 一次性累加，做到 `O(log n)`。本质是把 BST 升级为带子树和的平衡树。
